# Research Note 模板

研究完成後依環境輸出，**不是直接發文**：有 filesystem 時存成 `.research/<YYYY-MM-DD>-<slug>.md` 且不入版控；Web-hosted agent 優先建立 Markdown artifact，無 artifact 能力時在回覆中完整輸出，不聲稱寫入本機路徑。

## 完整格式

```markdown
# Research: <題目>

## 子問題
1. ...
2. ...

## 來源清單
- [標題](URL) — 來源角色：官方 / 一手 / 二手；取用層級：全文 / 摘要 / 轉引 / 未驗證；訪問日：YYYY-MM-DD
- ...

## 讀取完整度盤點
| 來源 | 讀到什麼程度 | 阻礙 |
|---|---|---|
| ... | ✅ 全文 / 🟡 部分 / 🔴 未讀 | 付費牆 / JS 載入 / 我自己沒去拿 |

## 事實交叉表
| 事實 | 來源 1 | 來源 2 | 驗證狀態 |
|---|---|---|---|
| ... | ... | ... | ✅ / ⚠️ unverified / ❌ conflict |

## 我的推論（與上表分開）
| 推論 | 依據 | 這個推論可能錯在哪 |
|---|---|---|
| ... | ... | ... |

## 草稿骨架
（以下段落可直接丟給 `post` skill 的 `tech-deep-dive` 模板）

### 核心概念
（這個東西在解什麼問題；不是「特色清單」）

### 關鍵設計決定
（為什麼這樣設計、捨棄了什麼）

### 跟替代方案的比較
（選它而不選 X 的理由）

### 適合 / 不適合的情境

### 限制 / 已知問題

### 取捨總結

## 待解問題
- ...
```

## 範例：子問題拆解

題目：研究 LangGraph 1.x 的變動

```
1. 1.x 的 release note 有哪些 breaking changes？
2. State / Channel / Annotation 模型怎麼變？
3. 跟 0.x 的 migration path 是什麼？
4. 社群實際遷移時踩到什麼坑？
5. 跟 LangChain 主套件的關係怎麼變？
```

## 範例：事實交叉表

```markdown
| 事實 | 來源 1 | 來源 2 | 驗證狀態 |
|---|---|---|---|
| LangGraph 1.0 release date | 官方 blog 2025-10 | GitHub release v1.0.0 | ✅ |
| 官方 release date 為 2025-10 | 官方 release note | （只此一源） | ✅ 單一權威一手（窄事實） |
| 移除 `StateGraph.add_edge` | 官方 changelog | HN 討論 | ❌ conflict — 官方說 deprecated，HN 說已移除 |
```

**衝突的事實要列出來，不要選邊**。讓使用者拍板。

## 範例：讀取完整度盤點

```markdown
| 來源 | 讀到什麼程度 | 阻礙 |
|---|---|---|
| Flanigan et al. 2024 | ✅ 全文（66,898 字元） | 無 |
| Voyer et al. 2022 | 🟡 摘要 + section snippets | 正文在 ScienceDirect 付費牆後 |
| Delgado et al. 2018 | 🟡 片段 | **我自己帶了 `query` 造成截斷** |
| Allen et al. 2020 | 🔴 僅二次引用 | 未嘗試查完整書目 |
```

「阻礙」欄要誠實區分**擋住的**與**我沒去拿的**。後者不該留在盤點表上過夜——直接去拿。

## 範例：推論與事實分開

```markdown
| 推論 | 依據 | 這個推論可能錯在哪 |
|---|---|---|
| 效果量隨「設計是否排除干擾」遞減 | 四份 meta 的效果量排序 | 四份同時在族群、設計、年代上都不同，不是只差一個變項 |
```

**不要把這種推論寫進事實交叉表。** 一旦混進去，下一輪就會被當成已查證的事實往上疊。
