# 英文口說需求 → 有依據的學習文章

把使用者當下想表達的意思留下來，讓下次遇到相似情境時能說出口。先回答眼前疑問，再完成文章；不要只回「可以寫成文章」。如果使用者明確只要短答，遵照該次範圍。

## 1. 對準意思與對話動作

抽出原始中文、對話對象、當下動作、目的、語氣與已知地區。六個常用情境是衝浪、攀岩、工作（軟體／AI）、旅遊、日常閒聊、面試（軟體／AI）；分類用既有 `learning`，不要新增 schema 分類。

資訊可從對話判斷就直接做。若「我的票在這裡」可能是找到票、指出位置、拿給人看，先分支寫出不同情境；只有無法合理分支、且會影響主題時才問一個必要問題。不要偷偷選一個意思再將其他正確句子判錯。

句型從使用者的卡點選：實際會用、可替換內容、需要辨別差異。一次圍繞同一個溝通目的，避免補成不相關的單字大全。面試範例不得編造使用者專案、職責或成績。

## 2. 先選來源再推薦說法

讀 [references/source-selection.md](references/source-selection.md)，按要驗證的主張選來源。字典證明字義／句型，不自動證明某職場、浪點或攀岩場景最常這樣說。找具體頁面與段落，閱讀正文；搜尋摘要、網站名氣或多個轉載都不等於核對。

研究優先 Groundlane `web_search` → `web_fetch`／`web_extract`。宣告不可用前搜尋完整 callable inventory；未掛載或一次 bounded request 整體失敗時，選其他合適 MCP，無合適 MCP 才用平台 web。Claude／Codex 使用同一條規則。Fallback 只查公開頁面，揭露工具與原因；不把它算成 Groundlane 驗證。禁止 stealth_fetch、WebFetch、web-fetch、fetch_page、playwright 抓取研究網頁。分派子 agent 時傳遞同一規則。

把核對記錄存到 `.work/english-speaking/<slug>/evidence.md`，使用下方模板的 evidence 表。每個核心差異都需有對應依據：來源直接示範、依來源句型改寫、或仍待核對。自行改寫可以教，但要交代為改寫，不能假裝是原文或母語者頻率證據。

分別記錄「表達本身」與「對話情境」的來源範圍：來源原句直接出現，不代表整個自寫票券情境也來自該頁。來源記錄需加 contextEvidenceType（direct／adapted），避免 direct 標籤遮掉情境改寫。

待查替代句只列在工作紀錄或文章的「仍待核對」欄，不給推薦口吻、用法定論或可背誦範例；先查齊再移入正式教學。來源不足不得以「草稿」名義把猜測寫成已確定差異。

「更常用」「最自然」「不能說」「英美不同」需要支持該比較的材料；只有一個例句就寫「這個情境可用的說法」。不要靠增加無關連結湊來源數。關鍵差異缺證據時繼續找合適材料；仍找不到就保留待查草稿與具體缺口，不將未查證句子加入練習卡。

## 3. 留成雙語學習文章

先查 `src/content/posts/learning/` 是否已有同一主題。新主題建立 `YYYY-MM-DD-<slug>.md` 與 `-en.md`；既有主題走 post-update，保留 slug／date，不重複生一篇。日期用 Asia/Taipei 當日。

沿用 post／post-update 的 metadata、雙語與寫作要求，搭配 [templates/learning-post.md](templates/learning-post.md)。預設草稿 `draft: true`，提供可 review 的完整文件；使用者已有發佈授權時依現有流程處理，不重問。站內語言連結依目前 src/pages 路由驗證，不直接照抄舊範例的 `/en/posts`。

tags 含 `english-speaking`，情境 tag 先查現有命名。內容包含：原始需求與具體情境、參考說法、也可怎麼說與意義差異、兩三個替換練習、短對話、中文情境回想、參考資料。詞彙數量和篇幅依卡點決定，不硬湊。

每個推薦說法回答「對誰、做什麼時用」；替代說法要區分「同情境也可用」與「換了意思才適用」。不以答案字串吻合評分，也不將自評宣稱為發音評分。

## 4. 練習資料與文章一起交付

在同篇文章提供可反覆用的中文回想題與答案，並依模板留下練習卡草稿。每卡有穩定 ID、scenario、context、zh、參考英文、可接受替代、使用差異、替換提示、文章路徑與來源映射。

先讀目前 `src/lib/english-speaking.ts` 與 `src/components/EnglishSpeaking/` 的實際契約。若整合已存在，可將查證完成的句子接進練習；若尚不支援文章／來源／替代說法連結，先把完整卡片存 `.work/english-speaking/<slug>/practice-cards.json`，明確報告「文章與卡片草稿完成、網站練習尚未接入」。不要默默丟棄來源欄位或宣稱寫入檔案等於上線。

修改題意或主答案時評估舊熟悉度是否仍適用；同語義改字不改 ID，新溝通目的用新 ID，避免沿用舊卡的熟練紀錄。

## 5. 分開驗證語言與工程

逐題審查中文／context／英文是否對齊，尤其是原始需求和使用者提出的替代說法。讀 [references/regression-cases.md](references/regression-cases.md) 作自查；涉及語用比較時可由獨立 agent 反查來源。

文章跑必要的 references、lang-parity、台灣用語與 post 流程檢查；整合網站或交付前跑 `pnpm verify`。改排程／保存契約才加針對性測試；改 UI 時實際走過揭示、播放、自評、重新整理與原文入口。

工程檢查通過只代表格式與程式檢查，不能宣稱英文自然度已驗證。最後列出文章路徑、來源核對範圍、練習是否接入、未解決缺口。按使用者授權決定 commit／push／deploy；套用 skill 不自動獲得發佈授權。
