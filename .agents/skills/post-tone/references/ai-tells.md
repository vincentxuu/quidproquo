# AI 味清單（中文／英文）

判斷「這句像不像 LLM 寫的」的實際檢查項。

**重要**：站上既有文章大量帶有這些特徵（見 `voice-profile.md` 第二層）。所以「站上也這樣寫」**不是**通過理由，反而是這份清單存在的原因。

## A. 填充語與暖身句

LLM 習慣在講重點前先暖身。使用者的規則是「直接，不客套」。

| 壞味道 | 改法 |
|---|---|
| 總之 / 綜上所述 / 整體而言 | 刪掉，直接講結論 |
| 值得注意的是 | 刪掉，或改成具體的「注意 X 會 Y」 |
| 換句話說 | 通常代表前一句沒寫好 → 改前一句，不要補譯 |
| 首先…其次…最後 | 改成有內容的小標或直述 |
| 不可否認 / 毋庸置疑 | 刪掉 |
| 在當今／隨著…的快速發展 | 刪掉整句，用具體事件或數字開場 |

## B. 對稱與排比癖

LLM 愛把句子排成整齊的對仗，讀起來像簡報而不像人講話。

- ❌ 「它讓開發更快速、讓維運更輕鬆、讓成本更低廉。」
- ✅ 「它把部署時間從 40 分鐘壓到 3 分鐘。維運和成本的差別沒那麼明顯。」

三項並列出現時先問：**第三項是真的，還是為了湊對稱？**

## C. 過度強調

粗體、破折號、「真正的」「關鍵在於」如果每段都出現，等於沒有強調。

- 一段最多一處粗體，且標**論點**不標名詞
- 破折號連續兩段都用 → 至少一處改成句號分開
- 「真正的 X 是…」一篇最多一次

## D. 虛假的平衡與過度 hedging

LLM 習慣兩面都說一點，結論就消失了。

- ❌ 「這個工具有優點也有缺點，適合部分情境，但也不是萬能的。」
- ✅ 「借 5 年以上這個方案是虧的。4 年以內才划算。」

使用者的規則明講「可以說『不推薦』」。**有結論就下結論。**

## E. 喊話結尾與展望

- ❌ 「快去試試看吧！」「期待它未來的發展。」「希望這篇對你有幫助。」
- ✅ 收在取捨：「這套組合的代價是 X，換到的是 Y。」

## F. 標點與裝飾

- 驚嘆號：站上 339 篇只有 9 個。基本上不要用。
- 標題 emoji：站上 0.1%。不要用。
- 內文 ✅ ❌ 只在表格當標記，不在句子裡當語氣。

## G. 空話形容詞

沒有數字的評價詞多半是空的。

| 空話 | 換成 |
|---|---|
| 非常強大 / 極為出色 | 具體能力或 benchmark 數字 |
| 大幅提升 | 從 X 到 Y |
| 眾多 / 許多 | 實際數量 |
| 相當不錯 | 刪掉，或說出跟什麼比 |

## H. 英文版對應

英文版是對譯，同樣要過這份清單。

| 中文壞味道 | 英文對應 |
|---|---|
| 總之 / 綜上所述 | "In conclusion," / "All in all," / "Ultimately," |
| 值得注意的是 | "It's worth noting that" / "Notably," |
| 此外 | "Moreover," / "Furthermore," / "Additionally," |
| 深入探討 | "Let's dive into" / "delve into" |
| 喊話結尾 | "Give it a try!" / "Happy coding!" |
| 過度 hedging | "It might be worth considering that perhaps…" |

英文同樣不用驚嘆號，同樣避免三項排比湊數。

## 怎麼用這份清單

掃描時逐項比對，命中就列進 `原句 → 建議` 對照表，理由欄寫**是哪一項**（例如「A. 填充語」）。

不要把清單當成硬性刪除規則——D 項（有結論就下結論）有時會跟事實不確定性衝突。**事實不確定時該 hedge 就 hedge**，那不是 AI 味，那是誠實。要刪的是「沒有不確定卻硬要兩面說」。
