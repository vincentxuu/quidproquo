# quidproquo 語氣輪廓

## ⚠️ 先讀這段：語料是汙染的

這份文件曾經把「站上 339 篇中文文章的統計」當成使用者的語氣基準。**那是錯的。**

實測（2026-07-27）：

| 檢查 | 結果 |
|---|---|
| 動到 `src/content/posts` 的 commit | 101 個，其中 **79 個含 Claude co-author（78%）** |
| 完全沒被 AI commit 碰過的中文文章 | **0 篇** |
| 2026-03 單月中文文章產量 | **194 篇**（每天 6 篇以上，機器產量） |
| git 歷史 | shallow（208 commits），無法完整追溯更早來源 |

結論：**站上文章幾乎全部由 LLM 產出或改寫過。從語料統計出來的「語氣」，量到的是模型的中文習慣，不是使用者的。**

所以本 skill 的判準**不是**「跟站上既有文章一致」。那個標準會讓 AI 味自我複製、越滾越厚。

三層分開看：

- **第一層 硬規則** — 使用者親筆訂的，可信，照做
- **第二層 站上現況** — AI 產出的統計，**僅供辨識，不是標準**
- **第三層 人聲樣本** — 唯一可信的語氣來源，數量少，要持續累積

---

## 第一層：硬規則（使用者訂的，可信）

來源：`../post/references/writing-guide.md`，由使用者撰寫。

- 直接，不客套
- 可以有情緒、可以說「不推薦」「踩到坑」
- 不需要介紹自己
- 具體 > 抽象，可驗證 > 模糊聲明
- 寫給「一週後的自己」，也寫給遇到同樣事情的人

結構慣例（這些是格式決定，不是語氣，照做即可）：

- `## 參考資料` 是硬要求（`pnpm check:references` 會擋）
- 收尾段慣用 `## 整體來說`
- 論文／工具名稱第一次出現就要是 inline 連結
- 數據與引述要附 inline 來源

## 第三層：人聲樣本（唯一可信）

只收**確定出自使用者本人**的文字：社群平台親手發的貼文、對話中親口說的、他親手改的、他明確認可採用的。

### 3.1 詞彙指紋（真人樣本實見）

| 特徵 | 實例 | 說明 |
|---|---|---|
| **「自己」代替「我」** | 「**自己**觀察到現在買課程很容易」「**自己**會嘗試但沒有習慣分享」 | 最明顯的指紋。降低斷言強度，保持觀察者位置 |
| **「蠻」+ 形容詞** | 「**蠻**有意思的」「**蠻**想知道這差異是什麼」 | 台式口語緩衝詞 |
| **「好／超／大」當程度詞** | 「**好**難玩」「**超**有收穫」「**大**推」「主管**好**耐斯」 | 不用「非常」「極為」這類書面語 |
| **「想 X」直述目的** | 「**想**認識做陪跑的老師」「**想**找平常會記錄自己在做什麼的人」 | 開頭不鋪陳，直接說要什麼 |

### 3.2 句法指紋

**長句串接，逗號多句號少，用因果連詞推進：**

> 「現階段來說陪跑這種方式是一個不錯的解方，但如果投入太多時間陪伴，成本就會高，整個服務的價格也勢必要提高，這樣相對的消費門檻就會提高。」

一句四個子句，靠「但／就會／也勢必／這樣」串起來。**不切成短句，也不用破折號。**

**遞進式對比，不是對仗排比：**

> 「買課程很容易，完成很不容易，達到買課程的目標，提升/養成某項能力更是遙遠。」

三段一路加碼（容易 → 不容易 → 更是遙遠），不是為了對稱湊三項。

**觀察 → 暫定解方 → 自己指出限制：**

先講看到什麼，再說目前的解法，然後主動點出這個解法的成本。這是他思考的形狀，不是修辭。

### 3.4 register 差異：社群 ≠ 文章

以下是**平台慣例**，不要跨平台照搬：

| 項目 | 社群（Threads/IG） | 部落格文章 |
|---|---|---|
| 驚嘆號 | 用，且不少（「完全沒想到還可以這樣！」） | 幾乎不用 |
| emoji | 用（😬🙏😆） | 不用 |
| 招呼／邀請語 | 用（「來跟我們聊天！」「歡迎轉貼」） | 不用 |

**可以跨平台帶進文章的是 3.1 和 3.2**（詞彙與句法指紋），不是 3.4 的 register 標記。

### 3.5 已確認採用進文章的原句

> 「國泰世華一直打電話來推信貸。想說研究一下到底有什麼特別的，就把他們在賣的東西拆開來算了一遍。」
> — 2026-07-27，`investing/2026-07-27-cathay-personal-loan-rate`。「想說研究一下到底有什麼特別的」為使用者原話，直接採用。

### 3.6 對話口語樣本

（用來判斷「他會怎麼講這件事」，不是直接貼進文章）

- 「標題好奇怪，調整一下」
- 「電銷那一段改個用詞」
- 「想說研究一下有什麼特別的」
- 「那代表 ai 味的有問題」
- 「寫了啥？」

可讀出的傾向：**句子短、不鋪陳、直接指出問題、不解釋理由**。

### 3.7 他明確否決過的寫法

| 否決的 | 原因 |
|---|---|
| 「1.88% 是行銷數字，真正的價格藏在加碼與 APR 裡」 | 兩個子句講同一件事，囉嗦 |
| 「信貸電銷」 | 行話味 |
| 「與其每次掛掉，不如…」 | 預告了一篇抱怨文，跟內文的中性分析語氣不合 |

### 3.8 累積方式

每次使用者改語氣或否決寫法，**當場補進這一節**，附日期與出處。這一層長大，前兩層的權重就下降。這是這個 skill 唯一會變準的機制。

## 重新量測（第二層用）

```bash
files=$(ls src/content/posts/*/*.md src/content/posts/*/*/*.md | grep -v -- "-en.md")
echo "篇數: $(echo "$files" | wc -l)"
for p in "你" "我" "我們" "——" "所以" "因此" "！" "？" "總之" "老實說"; do
  printf "%-8s %s\n" "$p" "$(grep -ho "$p" $files | wc -l)"
done
echo "粗體總數: $(grep -ho '\*\*[^*]\+\*\*' $files | wc -l)"

# 汙染度：posts commit 有多少含 Claude co-author
git log --format="%H %(trailers:key=Co-Authored-By)" -- src/content/posts | grep -ci claude
```

**汙染度沒有下降之前，第二層的數字不會變成標準。**
