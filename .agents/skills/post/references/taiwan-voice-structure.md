# 台灣文章來源結構參考

這份不是媒體仿寫清單。用途是把台灣文章來源的結構拆成可用的審稿判準，避免只學表面語氣。

研究來源見：

- `.research/2026-08-29-taiwan-article-sources-for-tone.md`
- `.research/2026-08-29-taiwan-writing-tone-sources.md`
- `.research/2026-08-29-quidproquo-voice-reference-set.md`

## 核心判準

台灣感不是詞頻，而是文章骨架：

1. 讀者先看到問題，不是先看到來源摘要。
2. 外國材料要被翻成台灣／繁中讀者的決策題。
3. 台灣題材要有台灣制度、產業、生活或資料來源支撐。
4. 標題最好帶具體矛盾、後果或選擇，不只標示主題類型。
5. 缺一手經驗時標「需作者補」，不要替作者捏造場景。
6. 少靠固定轉折撐論點；同一篇反覆出現「不是 A，而是 B」「可以 A，但不能 B」「值得看，是因為」會削弱真人語氣。

## 結構模板

### 報導者型：公共問題長文

適合：政策、教育、治理、資安、公共技術風險。

骨架：

1. 具體人物、事件、制度卡點或讀者正在遇到的矛盾。
2. 這個矛盾背後的公共問題。
3. 證據線：文件、法規、採訪、公開資料、數字。
4. 利害關係人：誰受影響、誰做決策、誰承擔成本。
5. 結尾回到制度或工作流會怎麼變。

不要學：篇幅、沉重感、調查報導語氣。本站多數文章只借問題意識與證據鋪陳。

### 上下游型：台灣產業／政策現場

適合：台灣產業鏈、採購、法規、供應鏈、地方場景。

骨架：

1. 地點、產業節點或政策變化。
2. 具體利害關係：誰買、誰賣、誰被卡住。
3. 供應鏈、法規、成本或資料可得性的機制。
4. 用台灣硬證據驗證：政府資料、採購公告、公司 filings、法規、財報、台灣媒體。
5. 收成「這代表台灣市場的哪個限制或機會」。

不要學：過強倡議語氣。技術文要保留可驗證邊界。

### 研之有物型：研究／論文轉譯

適合：論文導讀、課程導讀、AI research、learning。

骨架：

1. 讀者原本會誤解或卡住的問題。
2. 研究者實際在解的問題。
3. 方法與結果只保留支撐判斷所需的部分。
4. 接回生活、工作、學習或制度情境。
5. 明講限制：樣本、場景、是否能外推、是否需要自己重跑。

不要學：過度科普化。工程細節不能被稀釋成單純故事。

### iThome／INSIDE／數位時代型：科技事件與產品選型

適合：daily、工具介紹、產品／平台、新創、API、框架。

骨架：

1. 誰推出了什麼，解哪個問題。
2. 影響哪群使用者或買方。
3. 核心數字、功能、限制或價格。
4. 放進市場位置：和既有方案差在哪。
5. 對台灣／繁中 builder 的採用判斷：採用、觀望、放進 provider matrix、只當 fallback、或暫不碰。

不要學：快訊腔、活動文包裝、只重述公司說法。

### TechOrange／換日線型：從台灣看國際趨勢

適合：外國工具、國際公司、創作者經濟、職涯、全球 AI 趨勢。

骨架：

1. 國際事件本身。
2. 它為什麼不是單純外國新聞。
3. 台灣讀者的位置：市場小、語言不同、採購慢、人才結構不同、資料主權、法規或供應鏈位置。
4. 哪些做法可借，哪些不能照搬。
5. 結尾給台灣讀者的選擇題，而不是全球趨勢口號。

不要學：口號式趨勢語。

### BIOS／500輯型：人物、場景與短篇觀點

適合：career、creator economy、life、產品人物、非純技術長文開頭。

骨架：

1. 一個具體場景、選擇或動作。
2. 從細節帶出人物／產品／問題。
3. 作者判斷藏在轉折裡，不急著下 slogan。
4. 段落短，留出換氣點。
5. 結尾收成一個可帶走的觀察。

不要學：文藝修辭、質感詞堆疊。tech / daily 只借節奏，不借裝飾。

### 經理人型：商業／職場行動

適合：product、marketing、career、工具採用指南。

骨架：

1. 讀者正在遇到的工作問題。
2. 一個可操作框架。
3. 案例或數字拆成變數。
4. 下一步行動。
5. 風險或不適用情境。

不要學：金句化、懶人包化。

## 對 quidproquo 的套用

### 一般文章

- 外國工具／論文／公司文：預設用「iThome／INSIDE／數位時代型」加「TechOrange／換日線型」。
- 台灣產業文：預設用「上下游型」；需要公共制度時加「報導者型」。
- 論文／課程導讀：預設用「研之有物型」。
- 職涯／創作者／人物文：預設用「BIOS／500輯型」加「經理人型」。

### Daily

日報每則不要只套新聞倒金字塔。用三層：

1. 事件：發生什麼。
2. 判讀：它改變哪個市場、技術或工作流。
3. 台灣位置：對台灣／繁中 builder 是採用、觀望、放進 matrix、避開，或需要補哪個能力。

避免每則都寫成同一個轉折模板：

- 不要每段都用「這不是 A，而是 B」開頭。
- 不要把「值得注意的是」當預設承接詞。
- 能用具體主詞時，不用抽象句型。例如「台灣團隊會先卡在繁中召回」比「這不是品質問題，而是在地化問題」更自然。

### Keenable 這類文章的適用結構

Keenable 是「外國工具／新創／API」題材，應用：

- iThome／INSIDE／數位時代型：誰推出、解什麼、限制、價格、和既有方案差在哪。
- TechOrange／換日線型：這不是單純外國新聞；台灣／繁中 agent 團隊要判斷它是否進 provider matrix。
- 研之有物型：NEEDLE benchmark 要轉成「能否被自己重跑與審查」的研究判斷。

因此開頭不應只說 Keenable 是什麼；前三段要先把問題翻成台灣／繁中 agent 團隊的選型題。
