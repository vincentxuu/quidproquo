# research-selection skill

任何需要「從一堆候選中選出代表案例」的場景，在開始搜尋之前先跑這三步。

## 何時用

| 情境 | 用 | 不用 |
|---|---|---|
| 「整理一下 vector DB 的案例」 | ✅ | |
| 「比較幾個 Agent 框架」 | ✅ | |
| 「電子報創業有哪些成功案例」 | ✅ | |
| 「寫個系列文介紹 X」 | ✅ | |
| 「研究一下 LangGraph」（單一主題） | | ❌ 直接用 deep-research |
| 「LangGraph 1.x 出了沒？」（單一事實） | | ❌ 直接搜 |

## 步驟一：定義母群

**在搜尋之前做。** 不是搜完才回頭畫邊界。

1. **寫一句話定義邊界**：什麼算、什麼不算。給使用者確認。
   - 例：「電子報創業 = 個人或小團隊創辦的付費/免費電子報，排除公司內部行銷電子報（如 a16z newsletter）」
   - 例：「Agent 框架 = 提供 agent 編排能力的開源框架，排除純 LLM wrapper（如 litellm）」

2. **用系統性方法掃母群**，不是「我知道誰」：

| 掃描方法 | 適用場景 | 範例 |
|---|---|---|
| 平台排行榜 | 有明確平台的領域 | Substack leaderboard、GitHub trending、Product Hunt |
| 分類目錄 | 技術選型 | awesome-list、survey paper 的 related work |
| 推薦鏈 | 社群驅動的領域 | A 推薦 B、B 推薦 C |
| 業界報告 | 市場分析 | Gartner、a16z annual、State of JS/AI/DB |
| 搜尋聚合 | 通用 | "best X 2026"、"X alternatives"、"X vs Y" |

3. **列出掃到的完整清單**，掃完才開始選。

## 步驟二：覆蓋矩陣

從完整清單中選代表案例，用二維表強迫檢查盲區。

### 維度該不該列的判斷標準

> **沿著這個維度的不同值，會不會導致讀者得出不同的行動結論？**
> 會 → 列入。不會 → 不列。

- ✅ 規模分層：只看大的 → 讀者以為「不到百萬就是失敗」
- ✅ 變現路線：走廣告和走訂閱的邏輯完全不同
- ✅ 生命週期：只看活著的是倖存者偏誤
- ❌ 創辦人星座：不影響行動結論

### 常用維度（依主題調整，不要硬套全部）

| 維度 | 覆蓋要求 | 為什麼 |
|---|---|---|
| 規模分層 | 大/中/小各至少 1 個 | 避免「做大才算成功」偏誤 |
| 路線/類型 | 每條路線至少 1 個代表 | 讓讀者看到不同選擇 |
| 生命週期 | 至少 1 個失敗/收掉/轉型 | 避免倖存者偏誤 |
| 地理/語言 | 至少 1 個非主流語言/市場 | 避免英語圈偏誤 |
| 時間 | 早期/中期/近期各有代表 | 環境在變，舊規律不一定適用 |

維度控制在 5–7 個以內——太多會讓每個維度只能塞一個案例，失去深度。

### 填表格式

```
母群定義：___
掃描方法：___
掃到的完整清單（N 個）：___

| 維度 | 值 | 選入的案例 | 缺口 |
|---|---|---|---|
| 規模 | 大 | ... | |
| 規模 | 中 | ... | |
| 規模 | 小 | ... | |
| 路線 | A | ... | |
| 路線 | B | ... | |
| ... | ... | ... | |
```

**缺口欄空的格子 = 你需要補搜的方向。** 不是跳過的理由。

### 給使用者看

填完矩陣後，把表格和缺口列給使用者，確認選案方向再往下走。

## 步驟三：標註偏誤

選完案例後，在 research note **和** 最終文章裡明確寫出：

1. **偏哪裡**：這批案例在語言、平台、規模、時間、地區上的偏向
2. **缺什麼**：覆蓋矩陣裡還有哪些空格沒補上
3. **為什麼還是選了這些**：資料可得性、讀者 relevance、或刻意的範圍限制

偏誤標註放在導讀或開頭段，不要藏在文末小字——它影響整篇的解讀。

## 反合理化

| 想偷懶 | 為什麼不行 |
|---|---|
| 從「我知道的」直接挑 | 你知道的 = 訓練資料裡有名的 = 倖存者偏誤 + 英語圈偏誤 |
| 搜跟選同時做 | 搜到一個順眼的就放進去，最後偏第一頁搜尋結果 |
| 先搜再定義邊界 | 搜尋結果會反過來縮窄定義——你只看到 Substack 的就定義成「Substack 上的電子報」 |
| 不標偏誤 | 讀者看到 10 個案例會以為是「全貌」，不標等於誤導 |
| 「找不到資料所以沒有失敗案例」 | 這本身就是偏誤——寫出來，讓讀者知道 |
| 覆蓋矩陣有空格但「夠了」 | 空格是你的盲區，至少補搜一輪再決定要不要放棄 |

## 跟其他 skill 的關係

- **deep-research**：多案例研究時，deep-research 步驟零引用本 skill
- **post**：選完案例、研究完，交給 post skill 發文
- **post-update**：系列文新增案例時，用 post-update 更新導讀篇的案例表
