"""UserPromptSubmit hook that injects the slackbot-v2 Opus reply reminder
as additionalContext on every turn.

Slackbot v2 is a stateless pipe: plain assistant text never reaches Slack.
Opus-class models tend to answer with plain text anyway, so a per-turn
reminder nudges them to call a terminal mcp__slackbot__* tool instead.

Delivering the reminder via a UserPromptSubmit hook (rather than
concatenating a <system-reminder>-wrapped suffix into the user turn text)
lets the CLI's normalizeMessagesForAPI / shouldUseMidConvSystem promote it
to a real {role:"system"} turn on models that accept mid-conversation
system messages (opus-4-8, mythos, fable, …) and fall back to the
<system-reminder> wrap on those that don't. The CLI owns that model gate;
this hook does not re-implement it.

Installed for slackbot v2 sessions: env-manager registers it in
launcher-settings.json only when CCR_OPUS_REMINDER_HOOK_BODY is set, and
CCR sets that env var only when the session is Slack-originated and the
ccr_slackbot_v2_system_turn_reminder GrowthBook boolean is on. Registered
as a UserPromptSubmit hook so it fires on every user turn (seed included).

The Opus-class gate lives here (is_opus on the transcript's most recent
main-loop assistant model), same as stop-hook-reply-gate.py: the
configured model can fall back CLI-side per request, so the effective

#!/bin/bash

# Read the JSON input from stdin
input=$(cat)

# Check if stop hook is already active (recursion prevention)
stop_hook_active=$(echo "$input" | jq -r '.stop_hook_active')
if [[ "$stop_hook_active" = "true" ]]; then
  exit 0
fi

# Check if we're in a git repository - bail if not
if ! git rev-parse --git-dir >/dev/null 2>&1; then
  exit 0
fi

# Bail if there's no remote to push to. Every error path below asks the user
# to "push to the remote branch" — meaningless without a remote, and
# unsatisfiable if signing also requires a source. This case arises when CCR
# was launched against a local repo with no github remote (sources=[]) and
# the container's cwd has a leftover .git from a cached resume.
if [[ -z "$(git remote)" ]]; then
  exit 0
fi

# Check for uncommitted changes (both staged and unstaged)
if ! git diff --quiet || ! git diff --cached --quiet; then
  echo "There are uncommitted changes in the repository. Please commit and push these changes to the remote branch." >&2
  exit 2
fi

# Check for untracked files that might be important
untracked_files=$(git ls-files --others --exclude-standard)
if [[ -n "$untracked_files" ]]; then
  echo "There are untracked files in the repository. Please commit and push these changes to the remote branch." >&2
  exit 2
fi

current_branch=$(git branch --show-current)
if [[ -n "$current_branch" ]]; then
  if git rev-parse "origin/$current_branch" >/dev/null 2>&1; then
    upstream="origin/$current_branch"
  else
    upstream="origin/HEAD"

#!/bin/bash
# CCR SessionStart hook: re-assert the git committer identity so that
# commits SSH-signed by CCR verify on GitHub.
#
# CCR's signing key is registered to noreply@anthropic.com. If a commit's
# committer email is anything else, GitHub reports verification.reason =
# unknown_key and shows the commit as "Unverified" even though the signature
# itself is valid. The base CCR image's /home/claude/.gitconfig sets
# commit.gpgsign=true but historically did not pin user.email, and past
# settings-sync behavior (tengu_strap_foyer) could pull in a user's own
# SessionStart hook that overwrote the identity. Re-asserting on every
# session start closes both gaps, including for checkpointed containers that
# still carry stale global git config.
#
# This sets both author and committer; CCR does not currently preserve a
# distinct human author identity in 1p sessions, and the Stop hook's
# remediation instructions and the byoc envtype already use these exact
# values. Exit 0 even on failure so a broken git install can't wedge session
# startup — the Stop hook will still catch any resulting unverifiable commit.

git config --global user.email noreply@anthropic.com 2>/dev/null
git config --global user.name Claude 2>/dev/null

# When the session has a user account, install a git commit-msg hook that
# appends a Co-authored-by trailer carrying the owner's address — the write
# side of the commit_identity_strict_committer rule in
# commitsign.MatchesAccountStrict. core.hooksPath replaces the repo-local
# hooks dir for every hook name, so every other name is a passthrough that
# chain-calls $GIT_DIR/hooks/<name> to keep repo-local hooks working.
#
# When CCR_SESSION_ACCOUNT_EMAIL is unset (org-service-key sessions), the
# strict rule accepts a bot-only commit with no trailer, so core.hooksPath
# is left untouched and none of this applies.
if [[ -n "$CCR_SESSION_ACCOUNT_EMAIL" ]]; then
  hooks_dir="$HOME/.ccr-git-hooks"
  mkdir -p "$hooks_dir" 2>/dev/null

  # Passthrough stub for every standard client-side hook name except
  # commit-msg and prepare-commit-msg, which we own below. Each stub
  # execs the repo-local hook when present. Hooks live under the COMMON
  # git dir (the main repo's hooks/), not the per-worktree GIT_DIR, so
  # the lookup goes via rev-parse so linked worktrees resolve correctly.
  passthrough_hooks=(
    applypatch-msg pre-applypatch post-applypatch
    pre-commit pre-merge-commit post-commit
    pre-rebase post-checkout post-merge pre-push
    reference-transaction fsmonitor-watchman
    pre-auto-gc post-rewrite sendemail-validate post-index-change
  )
  for h in "${passthrough_hooks[@]}"; do
    cat >"$hooks_dir/$h" <<'PASSTHROUGH'
#!/bin/sh
common_dir=$(git rev-parse --git-common-dir 2>/dev/null) || common_dir=.git
local_hook="$common_dir/hooks/$(basename "$0")"
[ -x "$local_hook" ] && exec "$local_hook" "$@"
exit 0
PASSTHROUGH
    chmod 0755 "$hooks_dir/$h" 2>/dev/null
  done
