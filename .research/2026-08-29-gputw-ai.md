## 草稿骨架

### 核心概念
GPUtw.ai 是台灣本地的 on-demand GPU cloud。它把 GPU 租用包成 container instance，而不是傳統長租裸機：使用者先儲值，選 GPU 與環境範本或自訂 Docker image，instance 進入 RUNNING 後透過 Web UI、SSH 或 API 使用，完成後 stop/terminate 停止運算費。

真正的產品焦點不是「GPU 型號最多」；而是把台灣研究室常見需求打包在一起：台灣機房、中文支援、統一發票、團隊帳務、可從小額開始、Jupyter/ComfyUI/Open WebUI 這類範本，以及可用 API 自動化。

### 關鍵設計決定
- 採預付點數，部署前需要足夠一小時承諾用量，避免月底帳單暴衝。
- 以 container/image/template 為部署單位，支援 public/private registry，並要求明確 tag 或 digest，這比「只給 VM」更貼近 AI 開發工作流。
- `/vault` 做跨 session 持久化，`/workspace` 做 instance-local 快速暫存，分工清楚。
- HTTP ports 有 private/public/unlisted+password；raw TCP/UDP 明確警告不得暴露未驗證 web UI。
- API scopes 設得細，`instances:exec` 另外隔離並稽核，這是安全設計上的好訊號。
- Team account 以 owner prepaid balance 支付成員 usage，並提供月額度與 instance cap，適合課程、實驗室、助教管理。

### 跟替代方案的比較
- 相對 RunPod：RunPod 產能、產品線、serverless/clusters、全球 regions 更成熟；GPUtw.ai 的優勢是台灣在地、帳務與低延遲，以及小型研究/教學場景的本地化。
- 相對 Vast.ai：Vast.ai 更像全球供需 marketplace，可能有更便宜的個人閒置卡；GPUtw.ai 更像受控平台，地點、帳務、存取模式更集中，但公開產能小。
- 相對台灣月租/裸機：GPUtw.ai 的自助 on-demand 和秒級/小時計費更適合間歇工作；長期 24/7 或固定硬體需求仍要跟月租/專案合約比較。
- 相對自架 GPU：GPUtw.ai 省硬體採購、維護、電力與環境建置，但資料備份、成本控制、供應可用性仍需自行管理。

### 適合情境
- 台灣研究室、課程、學生團隊需要短期 GPU，且要統一發票/台灣帳務。
- ComfyUI、Jupyter、PyTorch、Open WebUI、Unsloth 微調等互動式工作。
- 小額試跑、demo、作業、短期實驗、可停可開的訓練/推論。
- 需要把資料留在台灣、或不想承受跨洋互動延遲的 notebook / web UI 工作。
- 需要 API 自動部署，但規模還不到要多節點 cluster 或企業保證產能。

### 不適合情境
- 需要保證大量 H100/H200/B200 產能或 multi-node cluster 的正式訓練。
- 需要明確 SLA credit、企業合約、安全認證、SOC2/ISO 文件的企業採購。
- 需要 production inference serverless、autoscaling endpoint、multi-region HA。
- 對資料不可遺失有強要求但沒有自己的備份策略；Terms 明確說使用者要自行備份，Vault best-effort。
- 需要可驗證長期供應與第三方口碑；目前公開外部評測很少。

### 限制 / 已知問題
- 2026-08-29 公開 catalog 顯示高階 GPU 多數不可用：H100/H200/B200/V100 x8/RTX 4090/RTX A5000 多為 NO_HARDWARE 或售罄。
- Pricing 頁公開 Reader 抓不到完整表格；最可靠是 `/api/gpus/active`，但 API 欄位 `hourlyPrice`/`liveRentablePrice` 沒在 JSON 中明示幣別。Threads 摘要中的台幣數字與 API 數值換算一致；採購前仍必須以部署畫面的最終價格為準。
- 首頁 99.9% uptime SLA 沒在 Terms 中看到對應條款或補償機制。
- 合作/信任機構 logo 只能確認官網展示，不能當成正式採購或背書證據。
- 外部第三方評測、社群踩坑文、性能 benchmark、實際部署成功率資料少。
- Terms 是 "as is"，責任上限為前三個月付款額，這對 production workload 需要另談合約。
- 未找到公司登記/統編公開交叉證據；官方 About 有地址、電話、CTO 與公司自述，但正式採購需請對方提供公司資料。
- 官方公開 templates 使用 `:latest` tag；自訂映像文件要求使用者用固定 tag/digest。介紹時要區分「官方維護範本」和「使用者自訂映像」。

### 取捨總結
GPUtw.ai 看起來是早期但產品化程度不低的台灣 GPU cloud。它的公開 docs 和 API 設計有實作細節，不像只有行銷頁；但公開產能、第三方驗證與 enterprise 條款還不夠。最合理的使用方式是先用小額 credit 測一輪：部署 RTX 3090、測 Vault 上傳、測 Jupyter/SSH、跑一個真實工作負載、確認發票與停止計費，再決定是否放進研究室或團隊流程。

## 採購前檢查清單
- 登入部署頁確認最終幣別、CPU/RAM/disk/port/Vault 計費與稅務。
- 用 NT$100-300 小額跑一次：開機時間、SSH/Jupyter、停止計費、Vault 保存。
- 測一個真實 workload 的 throughput，不要只看 GPU 型號。
- 問清楚學術折扣、統編/發票、ECPay 付款方式、退款/餘額處理。
- 若要多人使用，測 team limits 是否真的能防止成員超額部署。
- 若要放敏感資料，確認資料中心位置、備份責任、刪除流程、權限與 audit log。
- 若要長任務或 production，要求書面 SLA、維護公告、故障補償與支援時段。
- 若需要 H100/H200/B200，先洽詢庫存，不要只看 catalog 中的 listed model。
