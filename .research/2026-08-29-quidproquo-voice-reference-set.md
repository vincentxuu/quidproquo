這組樣本的共同點不是「用了很多台灣兩字」，而是：

- 開頭很快交代「為什麼是我/本站來寫這題」。
- 國外工具、論文、公司或市場會被拉回台灣/繁中/本地制度的位置。
- 有明確方法論，願意承認限制、更正與不確定。
- 標題偏具體矛盾，不是抽象主題。
- 段落有口語判斷，但不靠語助詞裝人味。

## 主樣本

### 1. 台股研究 Agent 實戰系列（篇 1）：為什麼台股需要自己的研究 Agent

File: `src/content/posts/tech/2026-08-23-stock-agent-1-why-taiwan.md`
Key lines: 22, 24, 37, 49, 59, 69
External reference family: 報導者 / iThome / INSIDE

代表的寫法：**本站自己的問題從哪裡來**。

為什麼選：

- 第一段直接講「為什麼是台股、為什麼是我、規矩從哪來」。
- 不是把美股 agent 框架翻成台股，而是指出台股的制度、資料與開源生態缺口。
- 文章把作者手上的 side project 放進敘事，不是裝成中立百科。
- 結尾把「利基」與「可驗證」收成系列命題。

可抽成規則：

- 任何外國工具/框架文，開頭三段必須回答「它在台灣/繁中/本站場景裡缺哪一塊」。
- 可以寫第一人稱，但第一人稱要帶出方法、經驗或取捨，不是情緒裝飾。

### 2. 換更貴的 embedding 救不了繁中 RAG

File: `src/content/posts/ai/2026-06-04-zh-tw-embedding-rag-failures.md`
Key lines: 17, 21, 27, 35, 41, 58, 67
External reference family: 研之有物 / iThome

代表的寫法：**把技術問題翻成繁中讀者的實際痛點**。

為什麼選：

- 開頭不是介紹 embedding，而是先打掉常見錯誤反應：「換更大的模型」。
- 三層原因清楚：模型本質、簡中/英文語料偏移、評測缺繁中。
- 每一層都接回繁中、台灣法遵/保險/公文等實務語境。
- 結尾有明確落地順序，不停在觀念整理。

可抽成規則：

- 技術導讀要先說讀者正在犯的錯，而不是先定義名詞。
- 「繁中」不是語言標籤，要具體到資料、詞彙、制度、評測與使用場景。

### 3. 量產爬升的證據不在工廠，在「無法決標公告」裡

File: `src/content/posts/tech/2026-08-09-drone-production-ramp-procurement.md`
Key lines: 28, 43, 72, 93, 115, 134, 156, 206, 233
External reference family: 上下游 / 報導者 / iThome

代表的寫法：**用公開資料重建台灣產業現場**。

為什麼選：

- 題目本來像需要非公開產線訪談，文章反過來證明公開採購資料就足夠。
- 段落用一連串可查的公告、日期、金額、投標家數建立論點。
- 願意在正文承認原判斷被對照組推翻，這是本站很強的「誠實感」。
- 語氣有判斷，但不把懷疑寫成陰謀論。

可抽成規則：

- 台灣產業文優先找政府資料、公告、法規、採購、財報等本地硬證據。
- 如果分析途中推翻自己，保留推翻過程；這比寫成完美結論更像真人研究。

### 4. 「飛手年收 200 萬」之後：農噴走完了一輪循環

File: `src/content/posts/product/2026-08-07-agri-drone-unit-economics.md`
Key lines: 18, 22, 41, 57, 69, 85, 98, 108
External reference family: 上下游 / 數位時代 / 經理人

代表的寫法：**把台灣案例拆成產品/商業模型**。

為什麼選：

- 用一句既有判斷開場，再把它拆開驗證。
- 將農噴從熱鬧新聞還原成 unit economics：計價單位、作業時間、設備成本、替代方案價格。
- 對「真的有需求」與「不一定賺錢」同時成立的矛盾處理得好。
- 結尾的三個判斷可直接轉成讀者行動。

可抽成規則：

- 商業/產品文要把台灣案例拆成變數，而不是只講故事。
- 好的台灣感不是「本土案例很多」，而是讓讀者看到本地市場的算式。

### 5. Stratechery：在台北證明「一個人寫分析文可以養活自己」

File: `src/content/posts/career/2026-08-26-stratechery-paid-newsletter-pioneer.md`
Key lines: 18, 22, 38, 54, 70, 95, 103
External reference family: 換日線 / 獨立評論 / 數位時代

代表的寫法：**外國題材，但從台灣位置切入**。

為什麼選：

- 題材是美國科技分析師，但開場抓的是「在台北一間公寓」這個位置。
- 文章不是把 Stratechery 當成功學案例，而是拆角色、商業模式、內容策略。
- 「從台北寫矽谷」被寫成分析優勢，這是很好的台灣讀者位置示範。
- 適合作為 career / creator economy / media 類文章的語氣樣本。

可抽成規則：

- 外國案例如果跟台灣有位置關係，就應該把這個位置放進開場，而不是藏在背景段。
- 不要只問「他怎麼成功」，要問「這個案例對台灣讀者的選擇有什麼啟發」。

## 共通語氣規則

### 開頭

好的開頭不是「本文將介紹 X」。站內正樣本通常做三件事：

1. 指出一個常見誤解或現實矛盾。
2. 說明這件事在台灣/繁中/本站場景裡為什麼不同。
3. 告訴讀者這篇會怎麼查、怎麼驗證、怎麼收斂。

### 標題

正樣本標題多半是具體矛盾：

- 「換更貴的 embedding 救不了繁中 RAG」
- 「量產爬升的證據不在工廠，在無法決標公告裡」
- 「飛手年收 200 萬之後」

避免：

- 「完整指南」
- 「深入解析」
- 「趨勢觀察」
- 「一次看懂」

這些不是禁用，但如果標題只剩抽象類型詞，台灣語氣會被削弱。

### 段落

正樣本的段落不是百科式定義，而是「判斷 → 證據 → 反向限定」：

- 先說判斷。
- 接一組本地資料或具體例子。
- 再說這個判斷不能外推到哪裡。

### 台灣讀者位置

台灣感有三種強度：

1. **強台灣題目**：台股、台灣無人機、台灣法規、繁中 RAG。
2. **台灣位置切入**：Stratechery 從台北寫矽谷、國際課程對台灣學習者的意義。
3. **台灣讀者轉譯**：外國工具/論文雖無台灣題材，但明確說台灣工程師/產品人如何使用。

缺任一種時，文章就容易變成「英文資料翻繁中」。

## 下一步建議

### 寫回 skill 的最小變更

先只改 `post-polish` 或 `post-review`，新增 `taiwan-reader-position` 區塊：

- 前三段是否有台灣/繁中/本站場景？
- 標題是否有具體矛盾，而不是抽象類型詞？
- 國外案例是否被放回台灣讀者的工作、學習、產業或生活位置？
- 若缺口需要作者經驗，標「需作者補」，不要替作者捏造。

### Daily 的特別規則

- TL;DR 最多 2-3 個主訊號。
- 每則新聞用「事件 → 為什麼重要 → 對台灣/繁中 builder 的影響」。
- 避免 `證據 A:`、`影響:` 這類內部 memo 標籤。
- 至少保留一段「我這週學到什麼」或「今天的認知更新」，讓 daily 不只是摘要器。

### 建議先審的弱樣本

從 `daily` 與大量課程導讀抽 5 篇測試，因為它們最容易變成：

- 來源順序驅動，而不是讀者問題驅動。
- 英文課綱翻成繁中。
- TL;DR 塞太多事件。
- 標題抽象、段落像 memo。
