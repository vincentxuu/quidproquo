# WebMCP — 瀏覽器原生的 AI Agent 工具協定

> Research note · 2026-09-11
> Status: draft / ready for post

---

## 核心問題

WebMCP 是 Google 與 Microsoft 在 W3C Web Machine Learning Community Group 共同提出的**瀏覽器原生 Web 標準**，讓網站透過 `navigator.modelContext`（Chrome 150 起改為 `document.modelContext`）直接向 AI agent 暴露結構化、可呼叫的 tool。

**關鍵區別**：WebMCP ≠ remote MCP server。它完全跑在 client-side JavaScript，網頁本身就是 MCP server——不需要後端、不走 HTTP/SSE/stdio transport。

---

## Q1: WebMCP 解決什麼問題？

### 現有 AI agent 與網頁互動的痛點

| 方法 | 問題 |
|------|------|
| **截圖/pixel-based** | 每張圖消耗數千 token；視覺辨識不穩定；改版就壞 |
| **DOM 解析** | HTML 結構混亂（廣告、tracking script）；元素語義不明確 |
| **專用 API + 後端 MCP server** | 需要額外後端服務；認證複雜；維護成本高 |

### WebMCP 的定位

網站**主動宣告**自己的可互動能力——「我有這些 tool，參數長這樣，功能是這個」。Agent 不用猜，直接呼叫。

歷史脈絡中的定位：

| 標準 | 目的 | 年代 |
|------|------|------|
| `robots.txt` | 告訴爬蟲什麼可以索引 | 1994 |
| `sitemap.xml` | 告訴爬蟲內容在哪 | 2005 |
| Schema.org JSON-LD | 告訴機器實體語義 | 2011 |
| `llms.txt` | 告訴 AI 模型網站是什麼 | 2025 |
| **WebMCP** | **告訴 AI agent 如何互動** | **2026** |

## Q3: 兩種 API

### Declarative API（HTML 表單標註）

不需要 JavaScript。在現有 HTML `<form>` 加三個屬性：

```html
<form toolname="search_products"
      tooldescription="Search the product catalog by keyword and category">
  <label>
    Query
    <input name="query" type="text" required
           toolparamdescription="Search keyword or phrase">
  </label>
  <label>
    Category
    <select name="category"
            toolparamdescription="Product category filter">
      <option value="electronics">Electronics</option>
      <option value="clothing">Clothing</option>
    </select>
  </label>
  <button type="submit">Search</button>
</form>
```

瀏覽器自動把這個 form 解釋為一個 tool：
- `toolname` → tool 名稱
- `tooldescription` → tool 描述
- `toolparamdescription` → 每個 input 的參數描述（沒有的話 fallback 到 `<label>` 或 `aria-description`）

**Agent 呼叫 tool 時**：瀏覽器把 form 帶入 focus、填入欄位、使用者可見。移除 `toolname` 或 `tooldescription` 屬性即 unregister。

### Imperative API（JavaScript 註冊）

```javascript
const modelContext = document.modelContext ?? navigator.modelContext;

if (modelContext && 'registerTool' in modelContext) {
  const controller = new AbortController();

  await modelContext.registerTool(
    {
      name: 'filter_products',
      description: 'Filter the product list by category and max price.',
      inputSchema: {
        type: 'object',
        properties: {
          category: { type: 'string', description: 'Product category' },
          maxPrice: { type: 'number', minimum: 0, description: 'Upper price bound' },
        },
        required: ['category'],
      },
      annotations: {
        readOnlyHint: true,
        untrustedContentHint: false,
      },
      async execute({ category, maxPrice }) {
        applyFilter(category, maxPrice);
        return `Filtered by ${category}` + (maxPrice ? ` under ${maxPrice}` : '');
      },
    },
    { signal: controller.signal }
  );

  // 要移除 tool 時
  // controller.abort();
}
```

**核心元素**：
- `name` / `description`：agent 用來判斷何時呼叫
- `inputSchema`：JSON Schema 定義輸入契約
- `execute`：async callback，在頁面的 main thread 執行，回傳結果給 agent
- `annotations`：安全 hint（見 Q5）
- `signal`：AbortSignal，abort 即移除 tool

### 何時用哪個？

| 情境 | 推薦 |
|------|------|
| 伺服器渲染 form、靜態內容 | Declarative — 零 JS |
| SPA、動態路由、需依狀態增減 tool | Imperative — `registerTool` + AbortSignal |
| 混合 | 兩者並用：read-only 用 declarative，state-changing 用 imperative |

## Q4: Tool Discovery 與跨 origin

### Discovery

- **Agent 側**：`document.modelContext.getTools()` 取得當前頁面上所有已註冊 tool（alphabetically ordered）
- **DevTools**：Chrome 149+ 有 WebMCP tab，可檢視、測試 tool
- **Chrome Extension**：[Model Context Tool Inspector](https://chromewebstore.google.com/detail/model-context-tool-inspec/gbpdfapgefenggkahomfgkhfehlcenpd)，可用自然語言跟 agent 互動測試 tool

### 限制：必須造訪頁面才能發現 tool

> "Clients and browsers must visit a site directly to know if it has callable tools."

沒有全域 registry、沒有 DNS-level discovery。Agent 得先導航到頁面才知道有哪些 tool。

### 跨 origin

預設 same-origin only。跨 origin 需要兩邊配合：

**1. Parent page 授權 iframe**：
```html
<iframe src="https://partner.org/widget" allow="tools"></iframe>
```

**2. Tool 作者明確 expose**：
```javascript
await document.modelContext.registerTool(
  { name: 'my_shared_tool', /* ... */ },
  { exposedTo: ['https://example.com'] }
);
```

**3. 消費者明確要求**：
```javascript
const tools = await document.modelContext.getTools({
  fromOrigins: ['https://partner.org'],
});
```

三層缺一不可——Permissions Policy + `exposedTo` + `fromOrigins`。

## Q5: 安全模型

### 基本原則

1. **瀏覽器作為 proxy**：所有 tool 呼叫經由瀏覽器仲裁，不是 agent 直接存取
2. **Same-origin policy**：tool 只在註冊它的 origin 可見（除非顯式 expose）
3. **Origin isolation**：WebMCP 只在 origin-isolated document 中可用；啟用 `document.domain` 的頁面禁用
4. **使用者看得見**：Declarative tool 呼叫時 form 會被帶入 focus；不支援 headless 執行
5. **Permissions Policy**：`tools` policy 預設 `self`

### Annotation hints

| Annotation | 用途 | 建議 |
|------------|------|------|
| `readOnlyHint: true` | 標記 tool 不改變狀態 | 讓 agent 判斷何時需要使用者確認 |
| `consequentialHint: true` | 標記高風險 / 不可逆操作 | 觸發瀏覽器請求使用者確認 |
| `untrustedContentHint: true` | 標記輸出含 UGC 或外部資料 | 警告 agent 此資料可能含 prompt injection |

**關鍵警告**：annotation 是 **hints，不是 access control**。Chrome 官方文件明確說：

> "It's impossible to guarantee safety inside of a large language model (LLM)."

### 已知攻擊面

1. **Prompt injection via tool output**：tool 回傳的 UGC 可能包含「忽略前面指令」之類的注入。`untrustedContentHint` 是緩解但非根治
2. **第三方 script 劫持 tool**：這是 `provideContext` 被移除的原因——惡意 script 可以 replace-all tool 定義，proxy 所有呼叫來竊取資料。改為 `registerTool`（同名拋錯）後緩解
3. **Cross-origin 資料洩漏**：即使 read-only tool 也可能暴露使用者資訊，只應 expose 給信任的 origin
4. **Character budget**：Chrome 建議 tool description ≤ 500 字元、tool output ≤ 1,500 字元，避免觸發 agent guardrail

### Chrome 建議的防禦層次

- **Deterministic**：token 限制、origin 限制、使用者確認、untrusted content 標記
- **Probabilistic**：prompt injection classifier、critic model 二次審查 tool call
- **Application-level**：在 `execute` 內部做 authorization、input validation、rate limiting

## Q6: 與後端 MCP 的關係

### 不是同一個東西

| | WebMCP | Backend MCP |
|---|---|---|
| **跑在哪** | 瀏覽器 tab（client-side JS） | 後端 server（Python/Node/etc.） |
| **Transport** | 無（in-process JS call） | stdio / Streamable HTTP / SSE |
| **需要後端嗎** | 不需要 | 需要 |
| **認證** | 瀏覽器 session（cookie/token 已存在） | OAuth 2.1 / Bearer / API key |
| **支援的 primitives** | **只有 Tools** | Tools + Resources + Prompts |
| **Discovery** | 頁面載入後 `getTools()` | `/.well-known/oauth-protected-resource` + `server/discover` |
| **多租戶** | 否（per-tab, per-user） | 是 |
| **離線** | 否（需要載入頁面） | stdio 可離線 |

### 互補而非競爭

> 「Web pages that use WebMCP can be thought of as MCP servers that implement tools in client-side script instead of on a backend server.」
> — Google Chrome 官方 guide

**典型場景**：
- 企業內部系統已有後端 MCP server（資料庫查詢、API 呼叫）→ 繼續用 backend MCP
- 前端功能（搜尋、篩選、表單填寫、導航）→ 用 WebMCP 直接暴露，不需額外後端
- 混合：後端 MCP 做重活，WebMCP 處理 UI interaction

## Q7: 實務實作考量

### 如何開始

1. Chrome 149+：加入 [WebMCP Origin Trial](https://developer.chrome.com/origintrials/#/register_trial/4163014905540602241) 取得 token
2. 本機開發：`chrome://flags/#enable-webmcp-testing` 開 flag
3. Feature detect：
```javascript
const modelContext = document.modelContext ?? navigator.modelContext;
if (modelContext && 'registerTool' in modelContext) {
  // 可以用
}
```

### Progressive Enhancement 策略

WebMCP 是**漸進增強**——沒有支援的瀏覽器不會壞，只是 agent 看不到 tool。

```javascript
// 有 WebMCP → 註冊 tool
// 沒有 → 表單照常給人類用
if (modelContext) {
  registerSearchTool(modelContext);
} else {
  // 人類使用者正常用 form
}
```

### 跨瀏覽器 polyfill

`webmcp-sdk` 和 `@mcp-b/global` 提供 polyfill，但行為與 native 有微妙差異（事件時序、permission prompt）。建議永遠在 native Chrome 驗證。

### DevTools 整合

Chrome 149+ 有 WebMCP tab：
- 檢視所有已註冊 tool 和 input schema
- 手動呼叫 tool 測試
- 查看 Tool Activity log

### 已知坑

| 問題 | 說明 |
|------|------|
| entry point 遷移 | Chrome 150 起 `navigator.modelContext` deprecated → `document.modelContext` |
| `provideContext` 已移除 | 用 `registerTool` 逐一註冊 |
| 同名 tool 衝突 | `registerTool` 同名會 throw，用 namespace prefix 避免 |
| Headless 不可用 | 必須有可見的 browser tab / webview |
| 只支援 Tools | 不支援 MCP 的 Resources 和 Prompts primitives |

## 適合 / 不適合的情境

### WebMCP 適合

- 電商：搜尋、篩選、加購物車、結帳
- SaaS 後台：表單填寫、狀態查詢、批次操作
- 內容網站：搜尋文章、篩選分類
- 客服：引導填單、問題分類
- 任何「前端已有邏輯，只是 agent 不知道怎麼用」的場景

### 不適合

- 需要存取後端資料庫、檔案系統的操作 → 用 backend MCP
- 需要跨頁面持久狀態 → tool 生命週期綁定 document
- Headless / 批次處理 → 需要可見 tab
- 需要 Resources / Prompts primitives → WebMCP 只支援 Tools
