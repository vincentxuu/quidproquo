## 3. 具體錯誤清單

標「錯誤」的是我有把握的，標「疑似」的需要實跑或查證。

### Phase 00

1. **00-06 env_setup.sh:2、115-131（錯誤，bug）**：腳本開頭 `set -euo pipefail`，`verify_package` 失敗時 `return 1`，而呼叫端是直接寫 `verify_package "numpy" "numpy"`。在 `set -e` 下，第一個驗證失敗整支腳本就會中止，`FAILURES` 計數和最後的 summary 永遠到不了。
2. **00-06 docs/en.md:26（錯誤＋自相矛盾）**：「CUDA 11.8 builds don't work with CUDA 12.x drivers (and vice versa)」。NVIDIA driver 向下相容，12.x driver 可以跑 11.8 的 build。同一篇 l.242 又寫「PyTorch CUDA version must be <= driver CUDA version」，跟這句互相矛盾。
3. **00-06 docs/en.md:124-134（過時）**：per-phase 目錄寫成 `04-neural-networks`、`05-cnns`、`08-transformers`、`11-llm-apis`，跟實際的 `04-computer-vision`、`11-llm-engineering` 等不符。
4. **00-08 docs/en.md:84、88（錯誤）**：講義說「`code/.vscode/extensions.json`…打開專案 VS Code 就會提示安裝」，實際路徑是 `code/vscode/`（沒有點），VS Code 不會自動讀，而且 VS Code 只認工作區根目錄的 `.vscode`。
5. **00-08 docs/en.md:104 與 quiz（錯誤）**：「Type checking on basic … Saves debugging time on tensor shape mismatches」。Pyright／Pylance 的 basic 模式不檢查 tensor shape。quiz 第 5 題的正解照抄了這個說法。
6. **00-07 docs/en.md:317-321（錯誤）**：叫學生在容器裡 `from qdrant_client import QdrantClient`，但 Dockerfile:34-43 沒裝 `qdrant-client`，會 ImportError。
7. **00-07 code/docker-compose.yml:14（疑似 bug）**：`../../../:/workspace` 是從 `code/` 往上三層，結果是 `phases/`，不是 repo 根；講義 l.225 的 docker run 掛的卻是 `$(pwd)`（repo 根），兩者不一致。
8. **00-12 code/debug_tools.py:128-146（概念錯誤）**：用 tracemalloc 量 `torch.randn` 的記憶體。PyTorch 的 tensor 配置走 C++ allocator，tracemalloc 追不到，demo 只會列出無關緊要的 Python 物件。講義 Part 6 跟習題 3 也延續這個誤解。
9. **00-12 docs/en.md:112-137（概念錯誤）**：Timer 量 forward/backward 時沒有 `torch.cuda.synchronize()`；在 GPU 上量到的只是 kernel launch 的時間，緊接著據此得出的「data loading 佔 60%」結論不可靠。（00-03 有正確加 synchronize，兩課前後不一。）
10. **00-12 outputs/prompt-debug-ai-code.md:67（錯誤）**：「OOM during backward pass: Gradient accumulation without clearing. Call optimizer.zero_grad()」。`.grad` 原地累加不會增加記憶體；backward OOM 常見原因是保留了計算圖（例如累加 loss 沒用 `.item()`）或 activation 太大。
11. **00-12 docs/en.md:216、218（言過其實）**：說 `torch.cuda.empty_cache()` 能解 OOM（它只把快取還給其他行程，本行程可用記憶體不會變多）；說 mixed precision 能讓記憶體「減半」（master weights 和 optimizer state 仍是 fp32）。另外 `torch.cuda.amp` 已改成 `torch.amp`（待查證）。
12. **00-12 outputs/prompt-debug-ai-code.md:60（不準確）**：「BatchNorm with batch_size=1 will NaN」。PyTorch 的 BatchNorm1d 在 train mode、batch=1 時是直接丟 ValueError，不會出 NaN。
13. **00-05 outputs/prompt-notebook-helper.md:31（錯誤建議）**：用來修「套件裝到別的 Python」的建議是「run `!pip install` inside the notebook」，但 `!pip` 正是造成這個問題的常見原因，正確做法是 `%pip install`。
14. **00-05 code/notebook_tips.py:8**：import pandas，但 00-01 只裝了 numpy、matplotlib、jupyter，beginner 照順序跑會 ImportError。
15. **00-03 code/gpu_check.py:42-46（量測方法錯誤）**：第一次 GPU matmul 包含 cuBLAS 初始化／kernel 載入，沒有 warm-up 會嚴重低估加速比。講義 l.114-125 也一樣。另外 l.49-52 用 VRAM/2 bytes 推「最大模型大小」，只算了權重，沒算 activation 或 KV cache。
16. **00-04 code/first_api_call.py（目標與實作不符）**：學習目標寫「Identify and handle common API errors including authentication and rate limits」，但 Python 的 urllib 版遇到 HTTPError 會直接拋出未捕捉的例外，完全沒處理；講義 Step 1 推薦用 `.env`，Python 版也沒有載入 .env（只有 TS 版有）。
17. **00-01 code/main.rs:33、code/verify.ts:50-60 vs code/verify.py:77（不一致）**：三份檢查器的 Python 門檻分別是 3.10、3.10、3.11；main.rs 還把 Node 和 Rust 列為 required，跟 beginner route 只要求 python＋git 衝突。
18. **00-10 code/shell_aliases.sh:138（bug）**：`ps aux --sort=-%mem 2>/dev/null | head -11 || ps aux -m | head -11`。pipeline 的結束碼取最後一個指令 `head`，macOS 上第一段失敗也不會觸發 fallback，結果什麼都不印。
19. **00-09 docs/en.md:101-116（自相矛盾）**：先說 typical 80/10/10，示範程式卻是 test 0.2、再從 train 切 0.125 當 val，實際比例是 70/10/20。

## 5. Phase 層級總評

### 整體品質
- **Phase 00**：偏重「指令清單＋外部工具」，不是「從零打造」，Build It 大多是安裝步驟，或包一層呼叫既有工具（HF datasets、Docker、VS Code 設定）。內容正確度中等。可跑性問題集中在這一 phase：env_setup.sh 的 set -e bug、`.vscode` 路徑、docker 少裝 qdrant-client、pandas 沒在前面安裝、預設 model id 需查證。00-01 的 `verify.py` 是整個 phase 最紮實的程式。平均約 2.5／5。
- **Phase 01**：明顯比 Phase 00 好。大多數課真的用純 Python（`math`／`random`）手刻：autodiff、Gaussian elimination／LU／Cholesky／CG、t 分布與 χ² 的 p 值（不完全 beta/gamma 函數）、Marsaglia-Tsang Gamma 抽樣、MCMC、Gumbel、Cooley-Tukey FFT、power-iteration SVD。「Build It」的承諾大致有兌現。例外是 10（PCA 用 np.cov＋eigh，t-SNE/UMAP 直接用套件）、12（broadcasting／einsum 用 NumPy）、21（eigh），屬於「部分」。概念錯誤平均每堂 1-3 個，多半出在延伸的 ML 說法（Adam≈Hessian、sharp/flat minima、CLT 漏條件、FFT 必須 2 的冪次），核心數學推導大致正確；我驗算過的數值範例（Bayes、Rosenbrock Hessian、Lagrange、stationary distribution、SVD／LoRA 參數量、einsum FLOPs、χ²）除了 01-17 的最小平方範例以外都對。平均約 3.4／5。

### 最強 3 堂
1. **01-15 statistics-for-ml**：t／χ² 的 p 值從不完全 beta/gamma 函數自己算，配上 Welch df、bootstrap、Cohen's d、多重比較、power 模擬，內容扎實，深度明顯超過入門課。可惜有 Bonferroni、Wilcoxon、paired bootstrap 三個錯誤（見清單 40-42）。
2. **01-17 linear-systems**：GE／LU（含 P 的列交換）、Cholesky、CG、ridge 都是正確的實作，還跟 numpy／sklearn 交叉比對，並附 solver 選擇決策樹；只有一個算術錯誤（1.7→1.6）。
3. **01-05 chain-rule-and-autodiff**（與 01-16、01-11 並列）：最小但完整的反向模式 autodiff，有 gradient check，並跟 PyTorch 對照，教學效果好；扣分點是沒標註 micrograd 來源。
