## 3. 具體錯誤清單

### 3.1 我有把握的錯誤（技術或數學）

1. **P2 L11 多數決準確率算錯**：`phases/02-ml-fundamentals/11-ensemble-methods/docs/en.md:33`，原文「For 21 classifiers each with 60% accuracy, majority vote accuracy is about 74%. With 101 classifiers, it rises to 84%.」用二項分布精確計算是 21 個 → 82.6%、101 個 → 97.9%。兩個數字都錯。
2. **P2 L06 維度詛咒數字是捏造的**：`06-knn-and-distances/docs/en.md:150-152`，原文「d=100: max_dist / min_dist ~ 1.01；d=1000: ~ 1.001」。[0,1]^d 均勻分布、200 點對單一查詢點，實際比值約 1.28（d=100）與 1.09（d=1000），差了一個數量級。同一課的程式 `knn.py:395-426` 會實際算出這個比值，執行時會和講義矛盾。
3. **P3 L08 次方算錯**：`03-deep-learning-core/08-weight-initialization/docs/en.md:53`，「0.512^10 = 0.00013」，正確值是 0.00124。
4. **P3 L05 核心前提錯誤**：`05-loss-functions/docs/en.md:19,23` 與 quiz（ml「What happens if you use MSE loss for binary classification?」正解 "...predicting 0.5 for everything, achieving MSE=0.25 without learning"）。MSE（Brier score）是 proper scoring rule，最小化解是 P(y=1|x)，不會停在 0.5。0.5 只是「最佳常數」預測，對 CE 也一樣（0.693）。同一課 `code/main.py:258-263` 用 MSE 訓練一樣學得起來，等於自己推翻這個前提。學習目標第 2 條就建立在這個錯誤上。
5. **P3 L05 塌縮的說法錯誤**：`docs/en.md:25`，「your embeddings collapse to a single point ... Technically zero loss」。InfoNCE／NT-Xent 在全部塌縮時 loss = log(N)，不是 0。這種說法只適用於沒有負樣本的目標。
6. **P3 L05 「指數」用詞錯**：`docs/en.md:47` 與 quiz「punishes confident wrong predictions exponentially via -log(p)」。−log 是對數，不是指數。
7. **P3 L06 bias correction 的時間尺度錯**：`06-optimizers/docs/en.md:91`，「Bias correction matters for the first ~10 steps and is irrelevant after ~50」。β2=0.999 時，第 50 步 1−β2^t≈0.049，v̂ 仍被放大約 20 倍，要上千步才可忽略。原文只用 β1 推論。
8. **P3 L06 weight decay demo 失效**：`code/main.py:278-293`。lr=0.001、wd=0.1、100 步，衰減因子 (1−1e-4)^100≈0.99，兩者範數只差約 1%，卻印出「AdamW shrinks weights X.Xx more」。另外 Adam 組完全沒有正則，根本沒有比較到學習目標說的 Adam+L2。
9. **P3 L10 BatchNorm 實作錯誤**：講義版 `10-mini-framework/docs/en.md:360-362` 的 `forward(x)` 呼叫 `forward_batch([x])`，batch size 為 1 時 var=0，x_norm 恆為 0，輸出恆為 β。程式版 `code/main.py:180-187` 改成用單一樣本更新 running_mean、再用 running_var 正規化，這已經不是 BN；`backward` (193-200) 也沒有考慮 mean/var 對輸入的依賴，梯度不正確。BN 沒有出現在任何實驗中，所以這些錯誤不會被發現。
10. **P3 L10 DataLoader 只是裝飾**：`code/main.py:411-420`。迴圈雖然按 batch 取資料，但每個樣本都各自 zero_grad、step，batch_size 對最佳化完全沒有作用。講義 :53 宣稱的「mini-batch 雜訊」與 quiz 的「zero_grad 分離是為了梯度累積」在這裡都沒有被體現。
11. **P2 L03 凸性與唯一解**：`03-logistic-regression/docs/en.md:89`，「This loss function is convex ... guaranteeing a single global minimum」。資料線性可分時沒有有限的最小值，權重會發散。本課的資料（兩團中心相距約 4.2σ）接近可分。
12. **P2 L03 與 sklearn 「相同」**：`docs/en.md:498`，「Your from-scratch implementation produces the same decision boundary and metrics」。sklearn LogisticRegression 預設 C=1.0（有 L2），特徵又先做了標準化，資料還是用 numpy RNG 另外生成的，不可能相同。
13. **P2 L03 quiz**：「Why is logistic regression called 'regression'? → The name comes from the logistic function it uses, not from regression analysis」。logistic regression 正是 GLM，是對 log-odds 做迴歸，這個「正解」是錯的。
14. **P2 L04 資料洩漏**：`04-decision-trees/code/trees.py:590-594`（樹）與 :606-609（森林）。先做 bootstrap（有重複樣本），再對 bootstrap 結果切 train/test，同一樣本可能同時出現在兩邊，測試準確率會被高估。
15. **P2 L05 對記憶體效率的錯誤說法**：`05-support-vector-machines/docs/en.md:80,138` 與 `code/svm.py:503-507`（「Logistic regression: ALL points used ... at prediction time」）。線性 SVM 和線性 LR 預測時都只需要 w、b。support vector 的稀疏性只對 kernel SVM 有意義，而本課沒有實作 kernel SVM。

## 5. Phase 層級總評

**整體品質**：中等。兩個 phase 的確大多是從零實作（P2 18 堂中 15 堂為「真」、3 堂「部分」；P3 13 堂中 10 堂可算「真」，L07「部分」，L11/L12 為框架課），程式風格一致、能讀，示範資料都是合成資料，大致可以離線跑（P3 L11/L12 除外）。但講義在三方面普遍不可靠：
(1) 和程式脫節：學習目標與「程式會做 X」的宣稱經常落空；
(2) 精確數字的可信度低：有些是捏造或算錯的；
(3) 涉及真實模型的事實常常錯：Llama/GPT/PaLM 的超參數、各公司用哪個框架。
深度大致落在「中等」，屬於入門到中級教材，數學推導多半停在公式陳列，少有嚴謹推導（P2 L10、P3 L03 例外）。

**最強 3 堂**：P3 L03 Backpropagation、P3 L13 Debugging Neural Networks、P2 L10 Bias-Variance（並列：P2 L04 Decision Trees）。

**最弱 3 堂**：
- P3 L05 Loss Functions：核心前提「MSE 會預測 0.5」是錯的，塌縮 loss 的說法也錯，quiz 也跟著錯。
- P2 L15 Time Series：只有 AR；宣稱的比較與特徵都不存在；「樹處理趨勢」「差分無害」兩個錯誤觀念。
- P3 L10 Mini Framework：作為 capstone，BatchNorm 是壞的、DataLoader 是裝飾，講義和程式各錯各的。

（P2 L12 的講義程式無法執行、pruning 範例無效，也接近最弱。）

**模板化程度**：高。31 堂都套同一套骨架與段落語氣（「That is the entire algorithm.」「No magic.」「This is not X. It is Y.」等句型反覆出現）。P3 L04-L09 的實驗幾乎是同一份 circle 資料加 2-8-1 網路的 6 份複本。常見 AI 量產痕跡包括：結論寫死在 print、兩分支相同的死碼、宣稱存在但不存在的程式功能、無來源的精確百分比、講義與程式在同一段落各自分歧。

**適合誰**：適合已有 Python 基礎、想用「看得懂的手刻程式」建立直覺的自學者或面試準備者。程式碼可以拿來跑、拿來改。不適合把講義當成事實來源，尤其是論文數據、業界模型超參數、框架現況。建議搭配 ISLR/ESL、d2l.ai 或原論文校正。教學者若要採用，至少需要先修正第 3.1 節列出的 54 處錯誤，並刪除或改寫各課中與程式不符的宣稱。
