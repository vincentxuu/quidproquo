## 3. 具體錯誤清單

以下是我有把握的錯誤（我手算或對照文件內部能確認的）。標「疑似」的需要外部查證才能確定。

### Phase 05

1. **05/01 `docs/en.md:80`**："The `ies -> i` rule is why `ponies -> poni`, not `pony`. Real Porter has step 1b that would fix it." → 錯。完整 Porter stemmer 對 ponies 的輸出仍是 `poni`，step 1b 處理 -ed/-ing，不會把 i 還原成 y。
2. **05/03 `docs/en.md:16`**："Two layer neural network, trillion-token training runs" → 錯。Google News word2vec 約用 100B tokens，不是 trillion 等級。
3. **05/03 `docs/en.md:107`**：`W[context_idx] = W[context_idx]` 是沒有作用的殘留行，code 版本已經沒有這行。
4. **05/04 `docs/en.md:100`**：`char_ngrams("where")` 的示範輸出漏了 6-gram `'<where'`、`'where>'`。n_max=6 時這兩個一定會出現。
5. **05/04 `docs/en.md:12`**："Word2Vec left two open questions." 後面卻列了 First、Second、Third 三點。
6. **05/04**：講義 `docs:38-82` 完整列了 `glove_train`，但 `code/main.py` 完全沒有 GloVe。
7. **05/05 `code/main.py:6,8`**：tokenizer 會把 didn't 當成一個 token，所以 NEGATION_WORDS 裡的 `"n't"` 永遠不會匹配。
8. **05/07 `docs/en.md:157`**："[HMM] cannot capture that `saw` is a noun in 'I bought a saw' but a verb in 'I saw the movie.'" → 錯。bigram HMM 的 DET→NOUN、PRON→VERB 轉移機率正好能區分這兩句。
9. **05/07 `docs/en.md:157` vs `:159`**：前面說 "BiLSTM-CRF or transformer hits ~98%+"，後面又說 "Models past 98% are probably overfitting"，兩句互相矛盾。
10. **05/09 `code/main.py:5-43`**：`simulate_copy_accuracy` 不是 seq2seq，只是「衰減 0.85 的向量加總，再比 tanh 分數」；`epochs`、`n_train`、`context` 三個參數都沒用到。講義 `docs:131-136` 的 98/91/62/23% 表格不是這份 code 產生的。
11. **05/09 `docs/en.md:147-152`**：用 `facebook/bart-base` 做 "Translate this to French" 示範。bart-base 是英文去噪預訓練模型，沒有翻譯能力，跑出來大概是原句。
12. **05/10 `docs/en.md:12`** vs **05/09 `docs:131-135`**：一邊說 "89% accuracy at length 5 ... near-chance at length 80"，另一邊表格寫 length 5 是 98%，而且最長只到 40。跨課數字不一致。
13. **05/12 `docs/en.md:131` vs `:196`**：正文說 extractive 是 "much lower hallucination risk"，Key Terms 卻寫 "Never hallucinates."，前後矛盾。
14. **05/13 `docs/en.md:56`**：`{'start': 57, 'end': 70, 'answer': 'June 29, 2007'}` 錯。在該 passage 中，"June 29, 2007" 從字元 40 開始、53 結束。
15. **05/13 `docs/en.md:26` vs `:59`**：前面說 extractive QA "never handles questions the passage cannot answer (by construction)"，後面又介紹 SQuAD 2.0 的 `handle_impossible_answer`，自相矛盾。
16. **05/13 `docs/en.md:120`**："Citation accuracy ... Trivial to check automatically with string match" → 錯。字串比對只能確認引用的段落存在，不能確認它支持答案。
17. **05/15 `docs/en.md:177`**：Key Terms 把 c_v 寫成 "Average pointwise mutual information"，與同課 `docs:109` 的正確描述（NPMI 加間接 cosine）不一致。
18. **05/16 `docs/en.md:181`**："For beam-search-like output, pick the argmax at each step (greedy) and add ... temperature"，把 greedy、beam search、sampling 三件事混在一起。
19. **05/19 `docs/en.md:22` vs `:26`, `:174`**：Gemma 一處列在 BPE，兩處列在 Unigram，前後矛盾。
20. **05/19 `docs/en.md:94`**：`# lower for CJK (e.g. 0.9995 for English, 0.995 for Japanese)` 方向寫反。SentencePiece 官方建議中文、日文等大字元集用 0.9995，英文等小字元集用 1.0。

## 5. Phase 層級總評

### Phase 05 — NLP Foundations to Advanced（29 堂）
- **整體品質**：中等偏下。前 16 堂是古典 NLP：TF-IDF、word2vec、BPE、HMM/Viterbi、TextRank、BM25、RRF、KN LM 這幾個大多真的手刻，數學也大致正確。17 堂之後（chatbots、structured output、NLI、embedding、chunking、coref、EL、RE、eval、long-context、DST）的 Build It 多半是呼叫 HF pipeline 或 sentence-transformers；附的 code 則是詞彙重疊、hash trick、regex mock 這類 toy，講義與 code 經常錯位。
- **最強 3 堂**：05/16 n-gram LM（從 Shannon 猜字遊戲接到 cross-entropy、perplexity，KN 手刻正確）；05/10 attention（shape 表清楚、數值範例正確）；05/14 IR（BM25 加 RRF 正確，fake 元件也誠實標示）。05/07 與 05/15 也不錯。
- **最弱 3 堂**：05/09 seq2seq（mock 冒充實作，數字無來源）；05/08 CNN/RNN（直接用框架，code 幾乎是空的）；05/26 relation extraction（REBEL 用錯類別、Wikidata 屬性方向錯、驗證步驟是空轉）。
- **模板化程度**：高。每課固定是 Problem / Concept / Build It / Use It / "When X still wins in 2026" / Ship It（skill prompt）/ Exercises / Key Terms / Further Reading。17 堂之後大量出現無來源的「2026 年研究／業界數據」（80%、70-90%、11-12% 這類），也有疑似杜撰的論文或系統名（AEVS、LlamaPred、REL-GEN、qWALS 2026、NVIDIA 2026 chunk benchmark）。
- **可跑性**：Build It 片段大多要下載 HF 模型（NLLB、BART、RoBERTa-SQuAD、XLM-R、DeBERTa、MiniLM、spaCy 模型）；05/20、05/27 需要 Anthropic/OpenAI API key。code/main.py 本身幾乎都是 stdlib，可以直接跑。
- **適合誰**：想快速建立 NLP 名詞地圖和 2026 選型直覺的工程師。不適合想從頭真正實作模型的學習者，也不建議把裡面的數字當成事實引用。

### Phase 07 — Transformers Deep Dive（16 堂）
- **整體品質**：中等。core 系列（02、03、04、05、11、12、15、16）用純 stdlib Matrix 類手刻 attention、MHA/GQA、RoPE/ALiBi、MoE 路由、online softmax、speculative sampling，是全 phase 最接近「from scratch」的部分。但量化說明錯誤偏多：KV cache 差 32 倍、參數量、scaling law 公式、Llama 3 的 RoPE 類型；講義宣稱的模型或步驟常常不在 code 裡（06、07、14）。只有 1/16 堂有 quiz。
- **最強 3 堂**：07/16 speculative decoding（演算法正確，用 χ² 實證分佈等價）；07/07 GPT（從 prefix average 推導 mask，觀點獨到）；07/04 positional encoding（RoPE 相對距離有數值驗證）。07/03 MHA/GQA 也很扎實。
- **最弱 3 堂**：07/06 BERT（只有 masking 規則，講義步驟大半不存在）；07/10 Whisper（沒有 mel、沒有模型，層數自相矛盾）；07/01 why transformers（計時示範有誤導，Chinchilla 和 parallel scan 兩處概念錯）。07/14 capstone 的 code 其實好，但講義描述嚴重失真。
- **模板化程度**：中等。版型一致，最後都是 "2026 picture" 表格加 skill，但內容比 Phase 05、08 具體。07/02 的格式與其他課不同（有 Learning Objectives、沒有 assets），像是早期版本留下來的。
- **可跑性**：除了 07/14 需要 torch（缺了會退成只算參數量），其他都是 stdlib 可跑。Use It 段多需要 HF gated 模型（Llama 3.x）和 GPU/vLLM。
- **適合誰**：已會 PyTorch、想把 attention 機制、推論優化名詞（GQA、MLA、KV cache、FlashAttention、spec decoding）串起來的中階工程師。數字與 config 細節一定要回原始論文或 config 驗證。

### Phase 08 — Generative AI（15 堂）
- **整體品質**：兩極。02 VAE、03 GAN、06 DDPM、13 flow matching、14 FID 是真正的 stdlib 手寫反向傳播，教學價值高。但 05 StyleGAN、10 video、11 audio、19 VAR 屬於「宣稱 transformer 或 attention，實際是直方圖、MLP、未訓練網路」的假實作；01、12 有數值或算法錯誤。年份、模型歸屬錯誤密集，例如 Kontext、Turbo/LCM/schnell 的蒸餾方法、SD2 文字編碼器、AudioCraft 2。DDPM 系列 code 共用的 T=40 schedule bug 會影響 4 堂課。
- **最強 3 堂**：08/02 VAE（手寫 VAE 反向傳播完全正確）；08/13 flow matching（CFM 加多步數 Euler 比較清楚）；08/14 FID（手刻矩陣平方根）。08/06 DDPM 的推導也好，但有 schedule bug。
- **最弱 3 堂**：08/11 audio（bigram 冒充 transformer）；08/10 video（宣稱 attention、對照組是稻草人）；08/19 VAR（直方圖冒充 transformer，還與自己的規定矛盾）。08/05 StyleGAN、08/01 taxonomy 也是 2 分。
- **模板化程度**：最高。14 堂都附有明顯批次貼上的 "Production note"（套用 LLM serving 術語、引用不存在的 notebook）；5 堂 diffusion 系 code 幾乎逐字相同；skill 檔有 HTML entity 殘留；缺 quiz；編號跳號（15–18）。
- **可跑性**：code 全是 stdlib 或 numpy，可以跑。Use It 需要 diffusers 加 GPU（SDXL、Flux 12B）。
- **適合誰**：想看「生成模型最小可運作數學」的學習者，挑 02、03、06、13、14 這幾堂很值得。產品選型表、年份、模型細節錯誤率高，不能當參考資料。
