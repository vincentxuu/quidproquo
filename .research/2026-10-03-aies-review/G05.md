## 3. 具體錯誤清單

下列項目以「把握較高」為主，標「疑似」者需要再確認。路徑前綴：P9＝`phases/09-reinforcement-learning/`，P10＝`phases/10-llms-from-scratch/`。

### 3.1 程式碼 bug／假實作（最嚴重）

1. **P10/06-instruction-tuning-sft/code/main.py:145-160**（docs/en.md:364-379 同）
   原文：`dlogits = ... ; dlogits = dlogits * mask_expanded / num_resp` 之後
   `block.ffn.W1 -= lr * np.random.randn(*block.ffn.W1.shape) * 0.01`
   問題：遮罩後的梯度算完就丟掉，權重只加上隨機雜訊。docs:391 卻寫「The gradient is masked: instruction tokens produce zero gradient. Only response tokens push the weights.」這是假的訓練。「base model」也只是隨機初始化的 MiniGPT（docs:497）。

2. **P10/07-rlhf/code/main.py:259-267**（docs:437-440）
   原文：`update_scale = lr * total_reward; block.ffn.W1 += update_scale * np.random.randn(...) * 0.01`
   問題：沒有 ratio、clip、advantage，也沒有梯度，卻稱為 PPO；docs:451 宣稱「update the policy… automatically preventing reward hacking」。

3. **P10/07-rlhf/code/main.py:136-143**（docs:327-332）
   原文：`rm.reward_head -= lr * grad * rm.ln_f.forward(rm.embedding.forward(preferred_ids))[:, -1, :]`
   問題：forward 會經過 transformer blocks，但梯度用的特徵跳過了 blocks；BT loss 對 head 的梯度應為 (σ−1)(h_pref − h_rej)，這裡少了 −h_rej 項。

4. **P10/08-dpo/code/main.py:190-202**（docs:378-381）
   原文：`update_direction = 1.0 if metrics["logit"] < 0 else -0.1` 再加 `lr*update_direction*np.random.randn(...)`
   問題：隨機更新，不是 DPO 梯度；docs:398 卻寫「compute the gradient, update the policy」。

5. **P10/04-pre-training-mini-gpt/code/main.py:203-265**
   問題：只更新 FFN、LN2、ln_f 與輸出端的 token_embed；attention 的 W_q/W_k/W_v/W_out、LN1、pos_embed 從未更新，梯度也沒有經過 attention 分支。docs:27 宣稱「Every gradient is computed by your code」，而 docs 自己的 Step 6 訓練迴圈（docs:419-431）只有 forward＋loss，docs:435 卻說「the loss drops」。

6. **P10/04-pre-training-mini-gpt/docs/en.md:253**
   原文：`scores = Q @ K.transpose(0, -1, -2 if Q.ndim == 4 else 1)`
   問題：Q 是 4 維時，對 4-D 陣列只給 3 個軸，會直接報錯。

7. **P9/08-ppo/code/main.py:90-98**
   原文：`next_v = 0.0 if buffer[t]["done"] else (buffer[t + 1]["v_old"] ...)`；`gae_val = delta + gamma * lam * gae_val`
   問題：buffer 把 8 個環境的 episode 串在一起，`gae_val` 在 done 時沒有歸零，advantage 會跨 episode 洩漏；被 horizon 截斷（非 done）的最後一步會用「下一個環境第一個 state」的 V 來 bootstrap。

8. **P9/07-actor-critic-a2c-a3c/code/main.py:125-127**
   原文：`entropy_grad = -math.log(p_i) - 1.0`，更新項 `ent_coef * entropy_grad * probs[i]`
   問題：這是 ∂H/∂p_i·p_i，漏了 softmax Jacobian。正確的 ∂H/∂z_i = −p_i(log p_i + H)，兩者差 p_i(H−1)，不是常數，因此梯度方向是錯的。

9. **P10/11-quantization/docs/en.md:532-577**（code 同）`simulated_gptq`
   問題：一欄一欄量化**輸出**欄，再把量化誤差加到後面 3 個**輸出**欄（乘上 0.1·diag(H)）。不同輸出神經元的誤差彼此獨立，這樣做只會破壞其他欄。真正的 GPTQ 是用 H⁻¹ 補償**同一輸出欄**中尚未量化的輸入維度權重。

10. **P10/11-quantization/docs/en.md:592-626** `simulated_awq`
    問題：(a) `scale_factors[idx] = min(4.0, mean|W| / rowmax)` 對顯著列通常 <1，是縮小，AWQ 則是放大；(b) 後續 `quantize_per_channel(axis=0)` 是逐列（輸入維度）縮放，列縮放會被該列自己的 scale 吸收，結果與 per-channel 完全相同，等於 no-op；(c) 用權重 MSE 評估，而非以 activation 加權的輸出誤差。

11. **P10/11-quantization/docs/en.md:510-516**
    問題：「Attention logits (5% noise)」實驗是加高斯雜訊，不是量化，卻與量化結果並列排序，用來「證明」敏感度階層，比較基準不一致。

12. **P10/11-quantization/docs/en.md:283-288** `simulate_fp8_e4m3`
    問題：尾數四捨五入到 1.0 時被夾成 0.875，沒有進位到指數（例如 1.99→1.875，誤差約 6%）；也沒有處理 subnormal。

13. **P10/12-inference-optimization/docs/en.md:561-571**（code/main.py:280-290）
    原文：`acceptance_prob = min(1.0, target_p[token] / ...)` 算完後改用 `if r < draft_model.acceptance_rate:`（code 版連前一行都刪了）
    問題：接受率是輸入參數，輸出的「speedup」等於循環論證；拒絕後從 target_p 抽樣，而非 residual max(0,p−q)，所以不是精確演算法，與 docs:186「mathematically exact」矛盾。

14. **P10/09-constitutional-ai-self-improvement/code/main.py:113,117**
    原文：`ratios = np.exp(policy_logprobs - ref_logprobs)`；`kl = (ref_logprobs - policy_logprobs).mean()`
    問題：ratio 應為 π_θ/π_θ_old，這裡用了 π_ref；以 π 抽樣時 E[log ref − log π] = −KL，號誌相反（demo 會印出 kl=−0.05）。docs:170 宣稱「GRPO trainer runs on a tiny LM from Lesson 04」，實際是字串樣板的 mock sampler，也沒有任何更新；docs:298 說「weak sampler improve」，但 sampler 固定不變。

15. **P10/18-multi-token-prediction/docs/en.md:31,50**、**code/main.py:150-157**
    原文：`logits_{i+k} = Out(h_i^(k-1))  for k = 1..D`
    問題：差一錯位。DeepSeek-V3 的 MTP module k 是用 h^(k) 預測 t_{i+k+1}；照此寫法，depth-1 loss 就是主模型自己的 next-token loss。同一 repo 的 P10/20:183 寫法又是正確的，兩課互相矛盾。

16. **P10/18-multi-token-prediction/code/main.py:96-107,254-268**
    問題：`attention_single` 算出 score 後丟棄（weight=1.0）；Step 3「降低雜訊後 L_1、L_2 下降」沒有意義，因為 backbone hidden＝E[t_i]＋雜訊，而目標 t_{i+1} 是彼此獨立的隨機 token，而且過程中沒有任何訓練。

17. **P10/16-differential-attention-v2/code/main.py:195-202**

## 5. Phase 層級總評

### Phase 09 Reinforcement Learning

**整體品質：中下到中等，誠實度高於 Phase 10。** 12 堂裡有 01–08 共 8 堂沿用同一個 4×4 GridWorld，全部只用標準函式庫手刻：DP、MC、TD、DQN（手寫 MLP 反傳）、REINFORCE、A2C、PPO。這部分確實符合「從零手刻」，也沒有冒充框架。問題集中在三處：
1. 文字中的概念錯誤偏多，尤其是收斂條件（GLIE、MC control）、PPO clip 的解釋、把 DPO 硬塞進 policy-gradient 家族。
2. 交叉引用指向不存在的 SAC、CQL、model-based RL 課，看起來是先寫了大綱、後來刪了課，卻沒有回頭修正。
3. 兩個實作 bug：A2C 的 entropy 梯度、PPO 的 GAE 跨 episode。
後半段（10–12）的深度明顯變淺，code 也變成玩具或寫死的結論。

- **最強 3 堂**：02 Dynamic Programming（PI/VI 正確、乾淨，有 sup-norm 交叉驗證）、05 DQN（純 Python 手寫反傳，target net 與 replay 都是真的）、04 Q-learning/SARSA（短小正確，可以直接對照 SARSA 與 Q-learning）。
- **最弱 3 堂**：11 Sim-to-Real（示範不出 DR 的價值、結論寫死、文獻重複）、10 MARL（doc 與 code 規格不一致，self-play 沒做）、07 A2C（entropy 梯度錯，沒有平行化，「A3C」只有名字）。
- **模板化程度：高。** 每課都是固定 9 段：Problem／Concept／Build It／Pitfalls／「Use It」（必有「The 2026 … landscape」表格）／Ship It（skill md，與 outputs 檔逐字相同，12/12 驗證）／三段式 Exercises（Easy/Medium/Hard）／Key Terms（「What people say | What it actually means」）／Further Reading。「In 2026」幾乎出現在每一課。outputs 只是把 doc 內的 code block 複製出來，沒有額外內容。
- **適合誰**：想在一天內看過 tabular→deep RL 全貌的工程師，搭配 Sutton & Barto 一起讀，並自行勘誤 GLIE、PPO-clip 與 OpenAI Five 相關段落。不適合作為唯一的 RL 教材。

**整體品質：差，且有「假實作冒充訓練」的系統性問題。** 標題是「from Scratch」，但核心的訓練鏈條沒有一課真的完成梯度訓練：
