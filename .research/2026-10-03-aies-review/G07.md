## 3. 具體錯誤清單

### 3.1 單堂內的錯誤或 bug

1. **01 `docs/en.md:44`**：「`parallel_tool_calls: true` (default on OpenAI and Gemini, opt-in on Anthropic)」。Anthropic 平行工具呼叫預設是開的，用 `disable_parallel_tool_use` 才能關。本 phase 的 02:79、03:52 自己也寫「default」，所以 01 錯了。
2. **01 `docs/en.md:83`**：「constrained decoding (OpenAI's strict mode, Anthropic's `tool_use`, Gemini's `responseSchema`). The output is guaranteed to validate.」把一般的 Anthropic tool_use 算成受約束解碼，跟 02:60/97 寫的「schema is advisory」矛盾。
3. **01 `docs/en.md:89`**：「Claude Code defaults to 20; OpenAI Assistants to 10; Cursor's agent mode to 25.」沒有來源，Claude Code 有沒有這種預設很可疑（疑似捏造）。
4. **01 `code/main.py:44-47`**：`tool_get_time` 不管 timezone 參數，永遠回 UTC 時間，卻把它標成使用者指定的時區。
5. **02 `docs/en.md:55/60/97`**：Anthropic 一欄依序寫成「schema-is-schema (always enforced)」、「the model tends to comply」、「schema is advisory」，同一堂課自相矛盾。
6. **02 `docs/en.md:115`**：「`UniversalToolNode` (LangGraph)」，LangGraph 沒有這個 API（實際是 `ToolNode`）。同一行說「Phase 13 · 17 ships a gateway that exposes an OpenAI-shaped API」，但 17 是 MCP gateway，OpenAI 相容路由在 21。
7. **02 `code/main.py:48`**：`"units": {"type": ["string","null"], "enum": ["celsius","fahrenheit"]}`。enum 裡沒有 null，可空寫法就失效了。`_gemini_schema`（76-89）遇到 list 型別也不轉大寫、不產生 `nullable`，輸出的 Gemini schema 不合法。
8. **03 `docs/en.md:105`**：「The difference is constant, not proportional, so the savings grow with tool count.」差值是 sum−max，不是常數，這句自相矛盾。
9. **03 `code/main.py:87`**：註解寫「Real streams look like this」，用的卻是每個 call 各自 start/stop 的事件。OpenAI Chat Completions 實際只有 index delta 加上單一 `finish_reason`，跟文件 :77/:83 的描述也不一致。
10. **04 `docs/en.md:30`**：「`stop_reason: "refusal"` is not a thing」，錯。Anthropic API 有 `stop_reason: "refusal"`。另外同課 :3 把 Anthropic 算成 schema 強制，:92 又列為「outside strict mode」。
11. **04 `docs/en.md:41`**：「Every provider accepts JSON Schema 2020-12」，跟 02 說 Gemini 用的是 OpenAPI 3.0 子集互相矛盾。
12. **05 `docs/en.md:38` 對照 `code/main.py:47`**：文件把 `get_weather_for_city(city)` 當正面範例，linter 的 regex `_(in|for|at|by)_\w+$` 卻會對它報 warn。
13. **05 `docs/en.md:87`**：「OpenAI strict mode requires every field in `required`; add an `is_default: true` convention in your code and let the model omit it.」strict 模式下模型不能省略 required 欄位，正確做法是用 `["T","null"]`，這個建議是錯的。
14. **05 `code/main.py:4`**：docstring 宣稱有 verb-noun 與「enum on closed sets」檢查，程式沒有實作。108-110 行的重複名稱也會被報 N 次。

## 5. Phase 層級總評

**整體品質：中上，但分成明顯的兩代。**
- **新一代**（06–18、22–31，共 23 堂）全部改寫成以 MCP 2026-07-28 為準的無狀態模型。每堂都用 stdlib 實作協定的關鍵不變式（per-request `_meta`、header 與 body 對等、MRTR、HMAC requestState、nonce 防重放、durable task、OAuth CIMD/PKCE/iss、registry admission、conformance transcript），還有 11–51 個測試。這是全課程少見真正「從零寫機制」的段落，安全邊界（fail-closed、先資格後排名、不執行的政策審查）也教得很到位。
- **舊一代**（01–05、19–21）停在 2025 年左右的模板，有大量沒有來源的數字（5–15%、60–70%、62→89%、3B>70B）、可疑或捏造的 API 與預設值，沒有測試，也沒有 quiz。19–21 還留著編號錯位（印出的課號與 outputs 的 frontmatter 都差 1）。19、20、21 的程式只是形狀模擬。

**最強三堂**：09（stdlib 寫完整 Streamable HTTP 邊界）、29（取消競態、SQLite 原子冪等帳本加真實的執行緒競爭測試、有界 SSE）、12（路徑 containment、可共享的 nonce store、decline/cancel 語意）。26 也接近滿分。

**最弱三堂**：19 A2A（規格過時，AP2 概念錯置，沒有 wire）、20 OTel（OTLP 定義錯，stable/experimental 自相矛盾，屬性與指標可能捏造）、21 Routing（toy fallback 程式，事實可疑，跟 MCP sampling 的立場衝突）。

**模板化與 AI 量產跡象（明顯）：**
- 同一套樣板程式（`request_meta`、`validate_request_meta`、`complete()`、`dispatch`、notification 不回應）在 15 個以上的 `main.py` 裡幾乎逐字複製。
- 段落級重複：「An envelope without a JSON-RPC `id` is a notification…」出現在 11:66、12:150、13:86、14:204、15:81、16:228、17:77；「Validate in one exact order…」出現在 14:195、15:79、16:226、17:75；「The server implements `server/discover`… Because it advertises tools, it also implements mandatory `tools/list`」出現在 11:68、12:154、13:82、14:146、16:230。看起來像為了通過自動審查清單而逐段補上的。
- 「Inspect four things」底下列五項（14）、「five」列六項（23）；過時的習題（16 Ex3、24 Ex3/6、25 Ex2）是先改程式、沒回頭改文件的痕跡。
- 測試極度防禦性（bool 型別的 id、Content-Length 走私、IDNA、attestation），27 的 1095 行程式加上 1279 行測試明顯過度工程，教學訊號被稀釋。

**可跑性（靜態判斷）**：全部只用 stdlib Python，不需要任何 API key。例外：07 的 TS 測試需要 Node ≥ 22.6（不符合時會 skip）；01、07、19 的 TS 版需要 `npx tsx`；22 與 27 的 real-host lab 需要 `npx skills`、網路，以及 Claude Code 或 Codex 這類宿主；26 的 sandbox 演練需要 docker 並拉取 `python:3.13-alpine`；09 會在 localhost 開臨時 port。沒有看到寫死的絕對路徑。

**適合誰**：已經會基本 function calling、想深入 MCP 生產級協定與安全工程（gateway、OAuth、供應鏈、conformance）的中高階工程師，最大的價值在 06–18 與 28–31。Agent Skills（22–27）適合要在團隊內建立技能發佈流程的人。01–05、19–21 不建議當權威教材，事實都要另外查證。另外，整個 MCP 路線都押在「2026-07-28 無狀態修訂版」上，所以待查證清單 A 的結果決定這半個 phase 是前瞻還是虛構。
