## 5. Phase 層級總評

### Phase 14（Agent Engineering）
- **整體品質**：中等偏弱，而且明顯可以分成三波作者或生成批次：
  1. **L01–L30**：固定模板（Problem/Concept/Build/Use/Ship/Exercises/Key Terms），每堂約 120–140 行，「2026 pitfalls」和「Where this pattern goes wrong」三段式幾乎逐字重複。程式全部是 100–250 行的 stdlib 玩具，LLM 一律換成**腳本或關鍵字規則**，很多「示範結果」是預先寫好的（03、05、08、22、25、41），而且常出現講義宣稱的機制在程式裡沒有發生的情況。
  2. **L31–L42**（workbench mini-track）：文風轉為論戰式，引用大量 2026 年的部落格、HN 討論和 preprint 數據。程式品質明顯提升（34–38 是整個 phase 最扎實的部分），但 L31 和 L41 的 A/B 比較是寫死的，L42 的 capstone 會 fail-open。
  3. **L43–L54**：新格式，有 unittest、6 題 quiz、引用經典 RE／管理文獻（Nuseibeh、Boehm、Basili GQM），乾淨、小而一致，但偏向產品管理，幾乎沒有 AI 技術內容。
- **Build It 是否「從零」**：L01–L30 嚴格說是「從零寫一個形狀」，不是從零實作演算法。真正有演算法的是 04（MCTS）、06（schema validator）、11（HTN）、13（state graph）。所有「框架課」（14–18、23–24）其實是在講框架的概念與形狀，沒有接觸真框架。**全 phase 沒有任何一堂呼叫真正的 LLM**，所以不需要 API key，可跑性高；但 15 需要 numpy，而 31、32、33、35–42 執行時會往 repo 裡寫入 `workdir/`、`outputs/`、json 檔。
- **最強 3 堂**：37 runtime-feedback-loops（真 subprocess、遮罩、輪替、lineage）、38 verification-gates（確定性 gate 加 HMAC override、fail-closed 的 secret 處理）、34 repo-memory-and-state（schema validator 加原子寫入）。35 init-scripts 並列。
- **最弱 3 堂**：41 workbench-for-real-repos（量測結果全部寫死）、25 multi-agent-debate（辯論沒有作用，數字自相矛盾）、22 voice（barge-in 是假的）。08、09、17 也很弱。
- **模板化程度**：高。L01–L30 的段落骨架、skill 檔的格式（Produce／Hard rejects／Refusal rules）、quiz 的「Which is NOT…」加上一個荒謬選項（Gradient ring、Quantized、PreEmbedding、compile_prompt…）一再重複。交叉引用錯誤很多（至少 9 處），並殘留「before the renumber」，顯示經歷過重新編號而沒有校對。好幾處推廣作者自己的專案（agentmemory、SkillKit、pro-workflow）。
- **適合誰**：已經會寫 agent、想快速掌握 2026 年名詞地圖與工程紀律（workbench、gate、handoff）的工程師。**不適合**想學演算法或真實框架 API 的人，也**不適合**把課文數據直接當成事實引用。

### Phase 15（Autonomous Systems）
- **整體品質**：偏弱。性質上是「2025–2026 前沿安全新聞導讀加上 Python 小模擬器」，每堂都是 Learn 型。程式多半是比例或機率模擬（沒有學習、沒有真 agent），而且**多堂模擬器的參數讓講義的核心主張在程式中不成立**（13、14、07、03、04、05、08）。事實密度極高，但錯誤與年代混亂也多：Beel 評 v1 被誤植為 v2、SB-53 已簽署、Llama Guard S14、RE-Bench 71、alignment faking 78% 被曲解並跨三堂重複、FSF v3 引用不可能的時序。
- **最強 3 堂**：10 permission-modes（composite exfil 的示範好）、21 METR（logistic fit 是真的，但有 10/90 反轉的問題）、12 durable-execution（replay 概念清楚，雖然 key 設計有誤）。16 checkpoints（自承缺口、atomic write）次之。
- **最弱 3 堂**：13 cost-governors（velocity limit 不可能觸發，還有算術錯誤）、05 AI Scientist v2（來源誤植加上死參數）、14 kill-switch（習題結果全錯）。19、20、22（政策文件的版本與時序錯誤）也弱。
- **模板化程度**：極高。每堂開頭都是一大段 blockquote 塞滿數字，接著「honest note／caveat」、「HEADLINE」print 區塊、skill 檔「Produce: 1. … 2. …」的格式都一樣；大量重複引用同一個 Anthropic "Measuring agent autonomy" 連結當通用出處；而且完全沒有 quiz。
- **適合誰**：想了解 2026 年 AI 安全治理全景（RSP/PF/FSF、HITL、cost governor、kill switch）的工程主管或 PM，當作**主題清單**使用。所有數字與日期都必須自行查證；不適合當技術或事實參考。
