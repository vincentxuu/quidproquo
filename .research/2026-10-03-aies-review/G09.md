Build It 真實度說明：「真」= 用 stdlib 實作出講義宣稱的演算法；「部分」= 有真實計算但關鍵部分寫死、腳本化或與講義不符；「假」= mock、寫死輸出、或結論在程式裡被預先設定；「無」= Learn 型課程，沒有 Build（有程式也只是印靜態表）。註：Phase 17 與 18 的 58 份 docs 都**沒有** "Build It" 段落，程式都放在 "Use It" 底下。

## 5. Phase 層級總評

### Phase 16 — Multi-Agent and Swarms（平均 2.8／5）

- **整體品質**：中下。主題選得完整，從 FIPA、A2A、黑板、BFT、談判、PSO/ACO、MARL、機制設計到 MAST，覆蓋面寬，概念介紹大致正確。問題在程式：多數課是腳本化的模擬器，結論常常在設定裡就決定了（16-07 把辯論做成 DeGroot 平均、16-15 的異質性只是讓錯誤票分散、16-18 用 prime 預先分配、16-20 完全沒有學習）。講義和程式常常不一致：講義說會出現某個現象，程式不會產生。
- **最強 3 堂**：16-22（sqlite checkpoint／resume、三態佇列、asyncio 與 thread 對照，是真的工程）、16-03（ed25519 簽章與完整協定堆疊，雖然有金鑰重用和只簽 id 的問題）、16-21（Shapley 精確與抽樣版本、二價拍賣都實作正確）。16-13 的黑板與 provenance 也不錯。
- **最弱 3 堂**：16-20（宣稱 MADDPG/QMIX/MAPPO，實際上沒有學習，三者共用一個集中式分配）、16-01（fakeLLMCall 加亂數）、16-18（ToM 前提被程式自己破壞）。
- **模板化程度**：高。25 堂中有 22 堂的 docs 用同一套章節骨架；outputs/ 有 23 堂是同一個「Produce／Hard rejects／Refusal rules／Output」模板；只有 01 和 03 有 quiz.json，其餘 23 堂都沒有。交叉引用的課號常常錯（至少 5 處），16-03 與 16-12 對 A2A 的 wire format 各說各話，看得出是分批生成、沒有統一校對。
- **適合誰**：想快速掃過多代理領域地圖、術語與論文名稱的工程師。不適合想學「能跑的多代理系統」的人，也不適合把講義裡的數字當作事實引用的人。

### Phase 17 — Infrastructure and Production（平均 2.55／5）

- **整體品質**：低到中。28 堂都**沒有** Build It 段落，與 repo「先手刻、再用框架、再出 artifact」的宣稱不符。程式幾乎都是玩具計算器或模擬器，裡面滿是寫死的「2026 approximations」與 vendor 數字。數量級錯誤很多：KV cache 大小（17-04、17-09）、spec decoding 期望值公式（17-05）、跨區延遲推論（17-11）、burn rate 定義（17-24）。程式算出的數字經常反駁講義與 quiz 的結論（17-02 的 30% vs 68%、17-13 的成本、17-15 的「10%」、17-17 的 crossover、17-18 的 LMCache）。多處印出的 KEY FINDING 是寫死的字串，不是計算結果。
- **最強 3 堂**：17-19（main.ts 是真的 gateway：constant-time key 比對、分級 token bucket、指數退避、fallback chain）、17-14（講義最謹慎，有附日期的價格快照，雖然程式有 bug）、17-21（真正的雙比例 z 檢定與樣本量公式）。17-08 的概念講解也清楚。
- **最弱 3 堂**：17-05（核心公式錯，加上對 rejection 機制的誤解）、17-18（它自己的模型裡 offload 比重算還慢）、17-23（分組 bug 導致 demo 失敗，自動核准又違反自己的政策）。17-22、17-24、17-27 也一樣弱。
- **模板化程度**：很高。28 份 outputs 全是同一個模板；quiz 每堂 6 題，都逐字取自講義，至少 5 堂的 quiz 把錯誤寫成標準答案（17-01 Q3、17-02、17-09 Q2、17-11 Q4 等）。大量具體但無來源的公司事件與統計數字（17-11 的 JPMorgan/Mayo、17-23 的「MIT 89%」、17-25 的 Vercel 事件），典型的 AI 量產特徵。部分課另附 main.ts，品質反而比 main.py 好。
- **適合誰**：想要 2025–2026 推論基礎設施名詞與廠商地圖的讀者，可以當成「該去查什麼」的索引。不適合拿來學容量規劃或做成本估算，數字要逐一查證。

### Phase 18 — Ethics, Safety and Alignment（平均 2.4／5）

- **整體品質**：中下，前段比後段好。01–23 堂的主題有模型可做（RLHF、DPO 系列、Goodhart、sleeper agents、control、W2S、DP、watermark），程式也真的有 SGD／logistic 等計算，但核心現象經常被模型設定預先決定或根本無法出現：18-02 的線性 gold 不會先升後降；18-04 的模型反證自己的結論；18-05、18-06、18-07、18-13 都是套套邏輯或循環論證。24–30 堂退化成新聞與法規摘要，程式只印靜態表（「Languages: none」卻附 code）。事實錯誤偏多而且集中在引用：CaMeL 歸屬、SynthID 機制、EU AI Act 罰款上限、CamoLeak 發現者、arXiv 2411.00986 標題、虛構的「NIST AI SPD」、虛構的 safety case「三支柱」。
- **最強 3 堂**：18-21（公平性指標定義正確、實作誠實）、18-03（五種 DAA loss 並排實作，梯度大致一致）、18-11（PGR 由實測量計算，誠實，只有機制解釋錯）。18-01、18-23 次之。
- **最弱 3 堂**：18-04（模型反證自身結論，加上疑似虛構的 DOI）、18-26（標 Build 卻只有寫死的字串，演進順序講反）、18-25（程式只做字串比對、框架自相矛盾、CVE 事實多處錯）。18-02、18-05、18-13 也很弱。
- **模板化程度**：很高。30 堂都用同一套骨架（Learning Objectives／Problem／Concept／Where this fits／figure／Use It／Ship It／Exercises／Key Terms／Further Reading），每堂都有固定的「Where this fits in Phase 18」段落；figure 區塊是佔位 id（18-28 甚至用了不相關的「sae-features」）；outputs 全是同一模板；quiz 每堂 6 題、逐字取自講義，至少 8 堂的 quiz 把錯誤寫成標準答案。虛構或錯置的引用在多課之間重複出現（「NIST AI SPD」出現在 15、25；「monitoring/illegibility/incapability」出現在 08、09、18、30），先修關係還有循環（24↔27）。
- **適合誰**：想要 AI 安全領域「論文與機構地圖」的初學者，可以把它當成閱讀清單。不適合當作權威的事實來源，法規與 CVE 細節尤其如此；也不適合期待「從零實作」對齊演算法的學習者，只有少數幾堂（03、11、21、22、23）的程式有教學價值。

### 跨三個 phase 的共同觀察

- 「Build It」宣稱與實際不符：Phase 17、18 共 58 堂都沒有 Build It 段落；Phase 16 有段落，但多為腳本化模擬。整體估計，83 堂中 Build 為「真」的 11 堂，「部分」40 堂，「假」26 堂，「無」6 堂（依第 2 節表格統計）。
- 講義和程式脫節是最普遍的問題類型：講義承諾的實驗、量測或現象，程式沒有做，甚至得出相反結果。這種情況超過 30 堂。
- 寫死的 takeaway／KEY FINDING 字串取代計算結果，學生跑程式看到的「結論」不是從資料來的。
