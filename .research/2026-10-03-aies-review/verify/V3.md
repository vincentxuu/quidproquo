# V3 覆核：G05（Phase 09、10）＋ G06（Phase 11、12）

## 挑選規則（覆核前寫定）
每 phase 依「若為真，對學習者傷害最大」排序取 4 條：
1. 核心演算法機制錯（學習者會學到錯的公式／梯度／概念）優先；
2. 其次假實作冒充真實作（講義宣稱的功能程式並未做到）；
3. 再次安全建議錯誤、大幅數值錯誤（會導致錯誤的工程決策）；
4. 每 phase 至少一條外部事實類、至少一條程式類，避免只挑容易驗的。
排除已覆核：P10 SFT/RLHF/DPO 加雜訊更新（G05 #1/#2/#4）、11-13 SHA-256（G06 B23）、11-11 $3.75（G06 E13）。

## 逐條覆核

### Phase 09

**1. G05 §3.1 #7 — PPO GAE 跨 episode 洩漏**
- 位置：`phases/09-reinforcement-learning/08-ppo/code/main.py:67-100`
- 覆核：`collect_rollout`（67-87）把 8 個環境各自最多 50 步依序 append 進同一個 buffer。`gae()`（90-100）：`next_v = 0.0 if buffer[t]["done"] else (buffer[t + 1]["v_old"] ...)`；`gae_val = delta + gamma * lam * gae_val`。done 時只把 next_v 歸零，`gae_val` 沒有乘 (1−done)，所以 t+1（下一個環境的第一步）的 advantage 會累加進來。若某環境跑滿 horizon=50 而沒有 done，`buffer[t+1]` 是下一個環境的初始 state，bootstrap 用錯 V。docs 沒有任何說明說這是刻意簡化。
- 判定：✅ 成立。兩個 bug 都能靜態確認（正確寫法應為 `gae_val = delta + γλ(1−done)·gae_val`，並另外記錄 truncation）。

**2. G05 §3.1 #8 — A2C entropy 梯度漏 softmax Jacobian**
- 位置：`phases/09-reinforcement-learning/07-actor-critic-a2c-a3c/code/main.py:123-127`
- 覆核：程式寫的是 `entropy_grad = -log p_i - 1`，乘上 `probs[i]`，也就是 p_i(−log p_i − 1)。推導：∂H/∂z_i = Σ_j(−log p_j−1)·p_j(δ_ij−p_i) = −p_i(log p_i + H)，兩者差 p_i(H−1)，公式確實錯。但我用 python 隨機抽 10,000 組 4 動作 softmax（logit ~ N(0,3)）比較：程式方向與真梯度的內積 **100% 為正**，例如 p=[.7,.1,.1,.1] 時，程式給 [−.45,.13,.13,.13]，真梯度是 [−.409,.136,.136,.136]。也就是說，程式的更新仍然會讓熵上升，只是方向不精確；而且 ent_coef=0.01，對整體影響很小。
- 判定：⚠️ 部分成立。公式錯誤成立，但「梯度方向是錯的」說得太重：它仍然是熵的上升方向，實際影響輕微。

**3. G05 §3.2 P9/08 — PPO clip 說明講反**
- 位置：`phases/09-reinforcement-learning/08-ppo/docs/en.md:37,39`（另有 41）
- 覆核：37 行原文「If the advantage `A_t < 0` and the ratio tries to grow past `1 - ε` … don't push a bad action below `-ε`」：前半寫 grow past，後半又寫 below，判斷是用詞失誤，讀者大致還能看懂原意。39 行原文「The `min` handles the other direction: if the ratio has moved in the *beneficial* direction, you still get the gradient」：L^CLIP 在 A>0、r>1+ε 時（也就是往有利方向移動）才會變平；min 保留未裁切項的情況，是 ratio 往**讓 objective 變差**的方向移動時（悲觀下界）。所以 39 行確實講反了。41 行「flat floor on the bad side」也不精確：A>0 時 r<1−ε 那一側並沒有被裁切。
- 判定：✅ 成立。核心直覺（min 的作用）寫反了；37 行只是用詞失誤，嚴重度看 39 行就夠。

**4. G05 §3.2 P9/12 docs:63 — GRPO「No reward model」**
- 位置：`phases/09-reinforcement-learning/12-rl-for-games/docs/en.md:53-63`
- 覆核：原文「No reward model, no critic, no MCTS. Group-relative baseline replaces all three.」。一手來源 DeepSeekMath（https://arxiv.org/html/2402.03300v3）§4.1.2 寫：「A reward model is then used to score the outputs, yielding G rewards」，Algorithm 1 的輸入也包含「reward models r_φ」，iterative GRPO 還會重新訓練 RM。脈絡上這一段是用 R1-Zero 的 rule-based verifier 來介紹，R1-Zero 確實沒有 RM；但「group baseline 取代 reward model」在概念上是錯的，baseline 只取代 critic。同課 docs:73 的 R1 stage 4 自己也寫了「preference-based rewards」，前後矛盾。
- 判定：✅ 成立。可以補一句：只對 R1-Zero 的 verifier 設定成立，但寫成 GRPO 的一般性質是錯的。

### Phase 10

**5. G05 §3.1 #3 — RLHF reward model 梯度少 −h_rej，而且特徵跳過 blocks**
- 位置：`phases/10-llms-from-scratch/07-rlhf/code/main.py:127-144`（docs:327-332 相同）
- 覆核：forward（65-77）是 embedding→blocks→ln_f→取最後一個 token→head。更新式為 `rm.reward_head -= lr * grad * rm.ln_f.forward(rm.embedding.forward(preferred_ids))[:, -1, :]`，特徵只做 embedding→ln_f，沒有經過 blocks；而且只用 preferred 的特徵。BT loss −log σ(r_p−r_r) 對 head 的梯度是 (σ−1)(h_p−h_r)，程式少了 −h_r 項。docs 中找不到 simplified／head-only 之類的標註。
- 判定：✅ 成立。

**6. G05 §3.1 #5 — mini-GPT 只訓練 FFN／LN2／ln_f／token_embed，attention 從未更新**
- 位置：`phases/10-llms-from-scratch/04-pre-training-mini-gpt/code/main.py:203-265`；docs:27、419-435
- 覆核：反向迴圈（240-261）只呼叫 `ffn_backward` 和 ln2 的 `layernorm_backward`，更新的只有 ffn.W1/b1/W2/b2、ln2、ln_f 和 token_embed。attn 的權重、ln1、pos_embed 都沒有更新；`dx = dx + dln2_in` 也沒有往 attention 分支反傳。docs:27 寫「Every gradient is computed by your code」。docs Step 6 的訓練迴圈（docs:410-431）只有 `model.forward` 加 loss，沒有 backward 也沒有更新，docs:433 卻說「As training progresses, the loss drops」。全課沒有任何「只訓練 FFN」的說明。
- 判定：✅ 成立。

**7. G05 §3.1 #13 — speculative decoding 的接受率是循環論證，拒絕後也不是從 residual 抽樣**
- 位置：`phases/10-llms-from-scratch/12-inference-optimization/code/main.py:260-308`；docs:512、561-571、186
- 覆核：程式以 `if r < draft_model.acceptance_rate` 決定接受（282），拒絕後用 `np.random.choice(..., p=target_p)` 抽樣（287），沒有用 max(0,p−q)。docs 版在 561 先算 `acceptance_prob = min(1, p/q)`，算完卻沒用（死碼）。反證脈絡：docs:512 明說「We simulate draft-target speculative decoding with configurable acceptance rates」，所以這段本來就標成 cost 模擬：給定 α 和成本參數，算出 speedup 是合理的成本模型，不算刻意冒充真實作。不過 docs:186 強調「mathematically exact」，示範的拒絕步驟卻是錯的，`acceptance_prob` 死碼也會讓讀者以為接受判定有用到它。
- 判定：⚠️ 部分成立。拒絕步驟錯、死碼誤導，這兩點成立；但這段已標成「configurable acceptance rate」的模擬，「循環論證」的批評應該降級。

**8. G05 §3.1 #9 — simulated_gptq 把量化誤差補到其他輸出欄**
- 位置：`phases/10-llms-from-scratch/11-quantization/docs/en.md:527-585`（code 相同）
- 覆核：`n_in, n_out = weight_matrix.shape`，迴圈 `for col in range(n_out)` 逐一量化輸出欄，再把 `quant_error * importance_weights * 0.1` 加到 `W[:, next_col]`（後 3 個輸出欄）。y=xW 時，不同輸出欄彼此獨立，把 A 欄的誤差加到 B 欄只會讓 B 欄偏離原值。GPTQ（Frantar et al.）是在同一列（同一輸出 row）內，依 H⁻¹ 把誤差補到尚未量化的輸入維度。docs:529 的說明「simplified version that captures the core idea … quantize the least important weights more aggressively」，與程式也對不上：程式根本沒有依重要性調整量化精度。雖然標了 simplified，但核心機制本身就錯了。
- 判定：✅ 成立。

**11. G06 E9 — 11-08 `quantize_to_nf4` 實為均勻 INT4**

**12. G06 E16 — 11-15「cache 要讀兩次才回本」，quiz Q5 正解錯**
- 位置：`phases/11-llm-engineering/15-prompt-caching/docs/en.md:49`；`quiz.json` Q5（correct=3 →「2」）
- 覆核：原文「a cached block has to be read at least twice to net-save money. 1 write + 1 read averages 0.675x cost per request (saves 32%)」。一手來源 https://platform.claude.com/docs/en/build-with-claude/prompt-caching 寫「5-minute cache write tokens are 1.25 times… Cache read tokens are 0.1 times」。計算：1 write＋1 read = 1.25+0.1 = 1.35 < 2.0（兩次都不快取），平均 0.675x（python 驗算），所以讀 1 次就已回本，同一句的算式自己就推翻了前半句。quiz Q5 問「How many reuses are needed to break even」，選項有「1」，正解卻標「2」。
- 判定：✅ 成立。

**15. G06 E27 — 12-04「Idefics2 dropped the resampler」說法相反**
- 位置：`phases/12-multimodal-ai/04-flamingo-gated-cross-attention/docs/en.md:92`
- 覆核：原文「Idefics / Idefics2 / Idefics3: Hugging Face's gated cross-attention lineage, progressively simpler (Idefics2 dropped the resampler in favor of direct patch tokens with adaptive pooling)」。一手來源 HF 官方部落格 https://huggingface.co/blog/idefics2（作者為論文作者）：「We departed from the Idefics1's architecture (gated cross-attentions)… The images are fed to the vision encoder followed by a learned Perceiver pooling and an MLP modality projection」，表格也列出每張圖 64 tokens。可見 Idefics2 保留了 Perceiver resampler，丟掉的是 gated cross-attention。所以把 Idefics2 歸入「gated cross-attention lineage」也不對。
- 判定：✅ 成立。

**16. G06 E46 — 12-18「ring attention 讓訓練計算量隨 context 線性成長」**
- 位置：`phases/12-multimodal-ai/18-long-video-million-token/docs/en.md:39`
- 覆核：原文「Training compute scales linearly with context, not quadratically — the quadratic hit on attention is amortized across the ring's devices.」。一手來源 Ring Attention 論文 https://arxiv.org/html/2310.01889 給出 blockwise attention 需要 4dc² FLOPs，整條序列的 attention 計算量仍是 O(s²)；ring 只是把計算分散到 N 台裝置，並把通訊和計算重疊，總 FLOPs 不變（摘要寫的是「without… additional communication and computation overheads」，並非減少計算）。反證脈絡：論文 §5 另有「training FLOPs per dataset… does not scale quadratically because the number of tokens remains fixed」的說法，也就是在 token 總數固定時，FLOPs 比例低於二次方。但這是任何 transformer 都有的計帳方式，並非 ring 造成的；講義把原因歸於「amortized across devices」是錯的。
- 判定：✅ 成立。審閱者說的「分散的是記憶體（與每台的計算），總計算仍為二次」正確；只是「線性」這個說法在 per-dataset 計帳下有一點依據，可以補充這個 nuance。
