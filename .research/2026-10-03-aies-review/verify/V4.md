### 3. G07 §3.2「缺少 clientCapabilities 的錯誤碼」— 06/07/09 回 -32602，31 回 -32021
- 位置：`13/06-mcp-fundamentals/code/main.py:137-138`（-32602）；`13/31-mcp-conformance-versioning-and-operations/code/main.py:203-204`（`-32021`）
- 覆核：
  - 程式確認：06 `if not isinstance(meta.get(CAPABILITIES_KEY), dict): return rpc_error(..., -32602, ...)`；31 `raise ProtocolViolation(f"modern request is missing {CLIENT_CAPABILITIES_KEY}", -32021)`。衝突屬實。
  - 官方規格 https://modelcontextprotocol.io/specification/2026-07-28/basic/index （§_meta, Per-request protocol fields）：`io.modelcontextprotocol/clientCapabilities` 為 Required；「A request missing any required field is malformed; the server **MUST** reject it with JSON-RPC error code `-32602` (Invalid params)」。`-32021 MissingRequiredClientCapability` 是另一情境：「If processing a request requires a capability the client did not include in `clientCapabilities` … MUST return `-32021` whose `data.requiredCapabilities` lists the missing capabilities」。changelog 也確認 -32021 由 -32003 重編號而來。

- 判定：✅ 成立
- 理由：前後矛盾屬實，且以規格判定 31 那側違反 MUST；審閱者只列衝突、未指出誰對，但指控本身成立。

### 4. G07 §3.2「Mcp-Name/Mcp-Param 值編碼」— 28 要求空白與空字串 base64，09/16/31 允許 0x20 明文
- 位置：`13/28-mcp-tool-contracts-and-content/docs/en.md:193-196`、`code/main.py:533-543`；`13/09-mcp-transports/code/main.py:115-121`；`13/16-*/code/main.py:105-118`；`13/31-*/code/main.py:155-161`
- 覆核：
  - 程式確認：28 `_is_plain_visible_ascii` 只收非空且 0x21–0x7E；09/16/31 收 0x20–0x7E 且 `value == value.strip()`。衝突屬實。
  - 官方規格 https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http （Value Encoding）：「header field values must consist of visible ASCII characters (0x21-0x7E), space (0x20), and horizontal tab (0x09). When a value cannot be safely represented … (e.g., it contains non-ASCII characters, control characters, or has leading/trailing whitespace), clients **MUST** use Base64」，同規則適用 Mcp-Name。規格沒有要求空字串或內部空白編碼，也沒有禁止多編碼；伺服器「MUST decode an encoded `Mcp-Name` or `Mcp-Param-{Name}` value before comparing」。
  - 結論：09/16/31 與規格逐字一致；28 比規格嚴格（會多編碼內部含空白的值），但因伺服器必須先解碼再比對，28 產生的 header 仍可互通，不會造成 HeaderMismatch。28 講義說「may travel as plain text only when…」把自家較保守的政策寫得像規格要求，這點會誤導。
- 判定：⚠️ 部分成立
- 理由：跨課不一致屬實，但兩種寫法在規格下都可互通（28 是保守超集），學習者傷害小，嚴重度應降為「措辭把政策說成規格」。
