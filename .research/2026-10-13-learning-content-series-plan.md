狀態：草案，待使用者確認弧線、範圍與斷崖處理。日期：2026-10-13。

依據：六份子問題研究筆記（`.research/2026-10-13-learning-content-q1…q6-*.md`）的草稿骨架，加上已寫的五篇。六份筆記屬於 deep-research 2.5 節說的「掃描」階段，本表只用它們決定寫哪些篇、每篇問什麼。表裡沒有任何結論可以直接成文；每篇動筆前要另挑 8 到 12 篇來源精讀並留抽取紀錄。

## 系列名：教學文章怎麼寫（Writing Articles That Teach）

目標讀者：自己寫教學文章、課程導讀或技術解說的人，沒有教育研究背景。讀完每一篇，他能對自己文章的某一個決定說出「研究測過什麼、沒測過什麼、我這樣做的依據有多強」。

總篇數：30（order 0–29）。

弧線：頁面上放什麼 → 要讀者做什麼 → 讀者帶著什麼來 → 隔一段時間之後 → 跟誰學、誰讀不到 → 怎麼知道有效、怎麼做出來。

排序理由：作者最先面對的是看得到的東西（一段文字、一張圖、一段程式）。讀者要做的事（題目、專案）也在頁面上，但效果取決於讀者做不做。讀者的差異看不到，放在第三段，回頭說明前兩段的做法為什麼不是對每個人都成立。時間、社群與評估離單篇文章越來越遠，放後面。最後一篇是本站自己的案例，用到前面所有篇。

## 併與拆的決定

- order 9：已寫的「題目與回饋」和 q3 篇二是同一題，併成一篇。q3 讀到而原文沒有的內容（自評判準、程式題回饋）在修正時補進去。
- order 15：後設理解在 q1、q4、q6 三份筆記各出現一次。讀者端的放 order 15；作者端的（好評、流量等訊號）放 order 25，引用 order 15，不重講。
- order 19：q1 的「誰覺得這不是寫給我的」併成 order 19 的一節。它唯一的教材層次研究只有摘要，撐不起一篇。
- 生成活動（自我解釋、畫圖、摘要）不單獨成篇，分別放在 order 1、2、9。
- 「各種呈現方式何時互相取代」不單獨成篇，放系列導讀。
- order 24 篇幅過長時，把手機與頁面重量拆成另一篇。

## 斷崖處理

| 位置 | 問題 | 處理 |
|---|---|---|
| order 1 | 第一篇就出現效果量、統合分析、調節變項 | 系列導讀用一節講怎麼讀這些數字；order 1 第一次用到時再各解釋一句 |
| order 1→12 | order 1 提到「對熟手反而有害」，完整說明要等到 order 12 | order 1 只講教材這一側，加前向連結；order 12 回頭引用 |
| order 7→8 | 從「頁面零件」轉到「讀者的行為」 | order 7 的結論是互動有沒有用看讀者拿它做什麼，結尾交給 order 8 |
| order 9→10 | order 9 假設讀者會作答 | order 9 的限制一節先寫明這個假設，連到 order 10 |
| order 11→12 | 第二段的做法都有「看讀者程度」的但書 | 第三段開頭一段收齊前面出現過的但書，再進 order 12 |
| order 15→25 | 同一個現象從讀者端與作者端各講一次 | order 25 開頭兩句帶過 order 15 的結論並連結 |
| order 19→20 | MOOC 的數字不能當成部落格讀者的寫照 | order 19 明講類比的界線；order 21 用同一批資料時沿用同一句 |
| order 29 | 需要前面多篇的概念 | 放最後；前置寫明 order 3、9、15、26 |
