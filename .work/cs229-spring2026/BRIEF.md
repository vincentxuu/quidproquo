# CS229 Spring 2026 逐堂導讀：寫稿共用說明

repo 根目錄：`/Users/vincent/Work/study/quidproquo`（以下路徑皆相對於此）。

## 這件事在做什麼

quidproquo.cc 的「Stanford CS229 導讀」系列原本是照 2026 主講義逐章寫的 21 篇（`src/content/posts/ai/2026-08-22-stanford-cs229-2026-notes-chapter-*.md`）。站長看了不滿意，三個具體抱怨：

1. 系列文都叫「第 N 章」，不是跟著課堂走。
2. 影片被塞在文末，開頭還寫「原講次錄影未確認」，讀起來像沒附影片。
3. 文章讀起來像查證報告，每篇只有三到五千字元，對八十分鐘的數學課太薄。

現在改成照 Stanford Online 公開的 Spring 2026 錄影（17 支，講者 Tengyu Ma 與 Chris Ré）一堂一篇。舊的逐章文之後會刪掉。你負責其中一堂的中文稿（zh-TW）。英文版之後另外翻，你不用寫。

讀者是照這份錄影自學的人：會 Python、學過微積分與線性代數與基礎機率，但沒人可以問。這篇文章要讓他看完之後真的懂這堂課的推導，而不是只知道這堂課「講了哪些主題」。

## 你手上的材料

- **逐字稿**（主要底本）：`.work/cs229-spring2026/txt/<NN>-<videoId>.txt`。這是 YouTube 上的英文字幕軌轉成的純文字，每段前面有 `[HH:MM:SS]` 時間戳。請整份讀完，不要只讀開頭。字幕看不到板書，所以講者說「this one here」之類的指涉要靠前後文與講義還原；還原不出來的就不要寫。
- **講義文字**：`.work/cs229-spring2026/main_notes.txt`（`pdftotext -layout` 轉出的 2026 年 8 月版主講義，278 頁，目錄在檔案開頭）。用來補板書上的公式與記號，並寫「對應閱讀」。PDF 在同目錄的 `main_notes.pdf`，公式轉壞時可以用 Read 工具指定頁碼看原頁。
- **舊的逐章文**：任務訊息裡會列出跟你這堂相關的舊文。裡面的講義頁碼、公式整理可以拿來用，但它們是照講義寫的，不是照這堂課寫的；課堂講法與講義不同時以課堂為準，並在文中指出差異。

## 文章要長什麼樣

**檔案**：寫到任務訊息指定的路徑，檔名不要改。

**frontmatter**：

```yaml
title: "<主題：可選的一個核心問題>｜Stanford CS229 第 N 堂"
date: 2026-10-12
category: ai
type: guide
tags: [cs229, ai-course, stanford, machine-learning, <再加二到三個本堂主題的英文小寫 tag>]
lang: zh-TW
series:
  name: "Stanford CS229 導讀"
  order: <任務訊息給的 order>
tldr: "<兩三句，講這堂課的推導走到哪個結論>"
description: "<一句，給搜尋結果用>"
draft: false
```

堂次用任務訊息給的「第 N 堂」，那是影片標題上的官方編號，不等於 order。

**開頭順序**（影片要在讀者一進來就看得到的位置）：

1. `> 🌏 [English version](/posts/ai/<你的 slug>-en)`
2. 影片狀態行，一定以 `**影片狀態：已附影片。**` 開頭，同一段接著一兩句說明底本：這篇依 Stanford Online 公開的 Spring 2026 第 N 堂錄影的英文字幕寫成，公式記號對照 2026 主講義第幾章；沒看到板書畫面。
3. 一小段導言：這堂在整門課的位置、先備、讀完能做什麼。連到課程總覽 `/posts/ai/2026-08-21-stanford-cs229-machine-learning`，以及上一堂（任務訊息會給 slug）。
4. 影片嵌入：

````
```youtube
url: https://www.youtube.com/watch?v=<videoId>
title: <YouTube 上的完整標題>
captions: en
```
````

然後才是教學正文的第一個 H2。

**正文**：照這堂課實際的進行順序走，用 H2 分段，每個 H2 的開頭或結尾標出對應的影片時間區段（例如「（錄影 12:20–31:05）」），讓讀者可以跳回去看。內容要求：

- 推導要走完，不要寫「經過推導可得」。每一步為什麼可以這樣做要講出來，這正是自學者卡住的地方。數學用 KaTeX：行內 `$...$`，獨立式 `$$` 各佔一行。
- 至少一個完整的數值例子：有輸入、有計算過程、有結果、有「這個結果代表什麼」。課堂上有例子就用課堂的；沒有就自己擬一個，並明講「以下是本文自擬的例子，不是課堂內容」，數字要自己再算一遍確認。
- 講者說了有意思的話（對某個方法的評價、實務建議、對學生提問的回答）可以引用，引英文原句並附時間戳。只引逐字稿裡真的有的句子。
- 這堂課一個以上主題時在同一篇分節，不要省略後半堂。
- 篇末前放「自我檢查」：三到五題，每題附答案或判準，題目要測得出讀者會不會算、會不會解釋，不是背定義。
- 再放「對應閱讀」：主講義第幾章第幾節、頁碼，以及課堂跟講義講法不同或課堂沒講到的部分。
- 篇幅以把這堂課講清楚為準，預期落在 8,000 到 15,000 字元。不要為了精簡砍掉推導步驟；也不要灌水重複。

**結尾區塊**（順序固定，都在教學正文之後）：

```
## 課程影片來源

原始影片：[<YouTube 完整標題>](https://www.youtube.com/watch?v=<videoId>)

- [Stanford CS229 Machine Learning｜Spring 2026 播放清單（Stanford Online，17 支）](https://www.youtube.com/playlist?list=PLaqpC4kq8Gpw)
- [CS229 課程官網](https://cs229.stanford.edu/)
- [CS229 主講義 main_notes.pdf](https://cs229.stanford.edu/main_notes.pdf)

查核日期：2026-10-12。

內容核對：已依字幕核對（2026-10-12）：<一兩句說明核對範圍與限制，例如未看板書畫面>。

## 參考資料

- <本文實際用到的來源，每條附一句用在哪>
```

新文章不需要「更新紀錄」區塊。

## 事實紀律

- 寫成「課堂上說」的內容必須在逐字稿裡找得到。字幕聽寫可能有錯字（例如把 CS229 聽成 CS299、人名拼錯），明顯的錯字照正確的寫，不確定的不要猜。
- 講者是誰請從逐字稿內容判斷（自我介紹、提到「Chris 上週講的」之類）。任務訊息給的講者只是初判，判斷不出來就寫「春季由 Tengyu Ma 與 Chris Ré 分堂授課」而不指名。
- 逐字稿與講義以外的事實（論文年份、模型名稱、某方法是誰提出的）如果要寫，必須是你確定的，並在回報裡列出來讓人複查；沒把握就不寫。不要為了這篇上網做額外研究。
- 你自己的解讀、補充的直覺、自擬的例子，要跟課堂說法分清楚。

## 不要做的事

- 不要 `git add`、commit、push，也不要刪或改任何既有文章與設定檔。只新增兩個檔案：文章本身，以及範圍卡 `.work/cs229-spring2026/cards/lecture-<NN>.md`（課程版本、原課堂次與 order、讀者先備、主問題、讀完的能力、完整例子、自我檢查題與答案、來源底本；一頁以內）。
- 不要跑 `pnpm verify` 或 `pnpm build`（十幾個人同時跑會互相干擾，而且英文版還沒寫，內部連結檢查一定紅）。可以跑 `node .agents/skills/post/scripts/check-course-titles.mjs <你的文章路徑>` 確認標題格式。
