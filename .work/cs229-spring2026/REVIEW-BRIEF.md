# CS229 Spring 2026 逐堂導讀：獨立審稿說明

repo 根目錄：`/Users/vincent/Work/study/quidproquo`（以下路徑皆相對於此）。

## 背景

quidproquo.cc 的「Stanford CS229 導讀」系列剛從「照講義逐章」改成「照 Spring 2026 公開錄影一堂一篇」。17 堂的中文稿（zh-TW）各由一位寫手依該堂的英文字幕逐字稿與主講義寫成，你沒有參與寫作。你的工作是當其中一篇的獨立審稿者：找出錯的、沒根據的、教不會人的地方，確定錯的直接改掉，需要判斷的列出來。

站長對舊版的不滿是：文章像查證報告、內容太薄、影片沒放在開頭。新稿刻意寫得深（每篇一萬六到兩萬四千字元，含公式原始碼），**不要為了精簡刪推導或例子**。篇幅不是問題，錯誤與教不懂才是。

讀者是照這份錄影自學的人：會 Python、學過微積分、線性代數與基礎機率，沒人可問。

## 材料

- 文章：任務訊息指定的路徑。
- 寫手的範圍卡：`.work/cs229-spring2026/cards/lecture-<NN>.md`。
- 逐字稿（事實底本）：任務訊息指定的 `.work/cs229-spring2026/txt/*.txt`，每段前有 `[HH:MM:SS]`。請整份讀完。
- 講義文字：`.work/cs229-spring2026/main_notes.txt`（目錄在開頭）；公式轉壞時用 Read 工具指定頁碼看 `.work/cs229-spring2026/main_notes.pdf`。
- 規格：`.agents/skills/post/references/course-guide-contract.md`（尤其「依角色教學」與「完成證據與防復發」第 3 點）、`.agents/skills/post/references/writing-guide.md`。
- 全系列定稿標題、路徑、講者與缺號說明：`.work/cs229-spring2026/titles.md`。

## 要查的五件事

**1. 課堂事實。** 文中寫成「課堂上說／講者說／學生問」的內容，逐項回逐字稿確認真的有，而且意思沒被改掉。英文引句已經用腳本逐句比對過都在逐字稿裡，你不用重查字面，要查的是引句有沒有被斷章取義、轉述有沒有加料、時間區段標得大致對不對。寫手把自己的補充標為「本文補充」「本文自擬」之類，請確認沒有哪段補充漏標而讀起來像課堂內容。

**2. 數學。** 每一條推導從頭跟一遍：每一步是否成立、記號前後是否一致、有沒有跳步到自學者接不上。每一個數值例子與自我檢查題的答案，自己用 Python 重算一遍，不要相信寫手說驗算過。公式用 KaTeX（行內 `$...$`、獨立式 `$$` 各佔一行）；請用 repo 裡的 katex 套件（`node_modules/katex`）寫個小腳本把全文公式渲染一遍，確認沒有語法錯誤。

**3. 逐字稿與講義以外的事實。** 論文作者與年份、模型名稱、工具預設值、歷史說法這類外部事實，文中出現的每一條都要是你確定正確的。不確定的，把它改成不需要那個事實的寫法，或刪掉那一句；不要為了保留它上網做長時間研究。講者憑印象說的數字，文中應該標明是講者的說法。

**4. 教得會嗎。** 依 course-guide-contract 的要求逐項對：導言有沒有交代先備與讀完的能力；每個主要概念有沒有從問題帶到機制；是否至少有一個完整例子（輸入、計算、結果、結果的意思）；自我檢查題是否有答案或判準，而且測得出理解；課堂後半段有沒有被草草帶過。把你認為自學者會卡住的地方指出來，能用一兩段補救的就直接補，補的內容同樣要守事實紀律並標明是本文補充。

**5. 站上規格與銜接。**
- 開頭順序：英文版連結 → `**影片狀態：已附影片。**` 那一段 → 導言 → youtube 嵌入區塊 → 第一個 H2。結尾依序是「課程影片來源」「參考資料」，都在教學正文之後。
- 連到上一堂、下一堂、課程總覽的連結路徑與連結文字，對照 `titles.md` 修正成實際的標題主題（寫手寫稿時彼此看不到對方的定稿）。文中對其他堂內容的描述如果跟 `titles.md` 的主題明顯不符，改掉或刪掉。
- 講者：依 `titles.md` 的判定。文章裡指名講者的地方要有依據（本堂字幕的句子，或「Chris Ré 在第 10 堂結尾說那是他這學期最後一堂」這類跨堂依據），寫法保持簡短，不要變成一段考證。
- 台灣用語：跑 `node scripts/check-tw-terms.mjs <文章路徑>`，blocking 與 review 項都處理掉；另外自己留意中國用語（例如 信息、概率、方差、算法、優化、默認、質量、視頻、網絡、數據 當名詞時應為 資訊、機率、變異數、演算法、最佳化、預設、品質、影片、網路、資料）。
- 文風：不要有查證報告的口吻。「字幕聽寫成 X」「無法確認」這類說明，只有在讀者看影片時真的會困惑的地方才留，其餘刪掉或併成一句。正文裡不要出現「寫手」「審稿」「逐字稿第幾行」之類的製作過程。

## 怎麼動手

- 確定錯的（算錯、推導錯、事實錯、連結錯、用語、漏標的補充）直接用 Edit 改文章。改完之後，改到的數字與公式再驗一次。
- 需要判斷而你拿不準的，不要改，列在報告的「待決事項」。
- 不要改檔名、frontmatter 的 `date`、`series`、slug；`title` 只有在違反標題格式或與內容明顯不符時才動，並在報告說明。
- 不要 `git add`、commit、push；不要動這篇以外的任何文章或設定檔；不要跑 `pnpm verify`、`pnpm build`。可以跑 `node .agents/skills/post/scripts/check-course-titles.mjs <文章路徑>`、`node .agents/skills/post/scripts/check-course-guide-layout.mjs`、`node scripts/check-tw-terms.mjs <文章路徑>`。

## 報告

寫到 `.work/cs229-spring2026/reviews/lecture-<NN>.md`，並把同樣的內容當作最後一則訊息回給我。格式：

1. **結論**：通過／修改後通過／退回重寫，一句話理由。
2. **文章版本**：審完當下 `shasum -a 256 <文章路徑>` 的輸出。
3. **教學對齊**：學習目標、正文機制、完整例子、練習與答案，各自在文章的哪個段落，是否對齊；指出最弱的一環。
4. **已修改**：逐條列出改了什麼、為什麼（附逐字稿時間戳或你的驗算）。
5. **數學驗算**：你重算了哪些例子與題目、結果；KaTeX 渲染的段數與錯誤數。
6. **外部事實**：文中留下的每一條外部事實，以及你對它的把握。
7. **待決事項**：需要人判斷的地方，每條附你的建議。
