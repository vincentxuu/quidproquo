## 這堂的性質

課程總覽 + Andrew Ng 對 AI 產業與職涯的看法。技術含量低，觀點含量高。
**適合當系列開篇**，因為 Ng 在這一講把「為什麼還要學 deep learning，而不是只學 prompt」講得很直接。

## 主線一：flipped classroom 的設計理由

- 學生本來就會自己去看線上影片，「與其我們年復一年講同一堂課，不如把影片做到最好放線上，把教室時間留給更深的討論」。
- 排課排兩小時，實際只用約 1 小時 20 分。

## 主線二：scaling 的敘事

- 橫軸資料量、縱軸效能：傳統 ML（logistic regression、decision tree）給再多資料都會 plateau —
  「就像舊世代演算法不知道拿這麼多資料要幹嘛」。小型 NN 會往上，中型更高，大型持續往上。
- 「deep learning 主宰 AI 十到十五年的原因，是我們有一套訓練超大神經網路的**配方**（recipe）。」
- 可預測性：先有百度的論文顯示 scale 上去效能增益是可預測的，之後 OpenAI 用 scaling laws 那篇把這個想法普及化。
  **這個可預測性才是資料中心投資的真正推手。**
- 趣聞（Ng 口述，未查證）：他第一台拿來訓神經網路的 GPU 機器，是一位 Stanford 大學部學生在宿舍組的，
  那人叫 Ian Goodfellow。→ 引用時要標「講者說法」。

## 主線三：抽象層地圖（整堂最可畫成圖的一段）

```
CS fundamentals → machine learning → deep learning → generative AI（transformer）
```

- 「就算你用 Claude Code / Gemini CLI / Codex / Cursor / Windsurf，懂 CS 基礎的人東西就是做得比較好，
  而不是『我來 vibe code 一下』。」
- **本課的定位**：把你帶到 deep learning 的近專家水準，往下沾一點 ML（目標函數、最佳化技巧），
  往上碰一點 GenAI（transformer 架構）。
- 「我天天用 LLM，但**光靠 prompt 是不夠的**（just prompting LLMs, it doesn't cut it）——很多東西我沒辦法只靠 prompt 做出來，
  所以常常得往下鑽一層，去動 deep learning 的東西。」

### 什麼時候會被迫往下鑽（可直接做成判斷表）

| 資料型態 | 實務做法 |
|---|---|
| 文字 | prompt 就能走很遠，大量應用是純 prompt 建的 |
| 音訊 | 常直接動 deep learning |
| 影像 / 影片 | 常直接動 deep learning |
| 結構化資料（大表格） | 常直接動 deep learning |

兩個把人推下去的力量：
1. **調了一個月 prompt 效能就是上不去。**
2. **帳單。** 原型期 LLM 便宜（每百萬 token 幾塊美金），一旦真的有 product-market fit、使用者衝上來，
   AI 帳單會「skyrocket」。Ng：我們付給 LLM 供應商的錢遠超過我想付的數字。
   **把成本曲線壓回去的關鍵技能，就是知道怎麼 fine-tune 比較小的模型。**

## 主線四：課程五個模組（Coursera 端）

1. 神經網路與深度學習基礎——用**純 Python 手刻**，因為 TensorFlow/PyTorch 會把細節藏起來
2. 調參（hyperparameter tuning）
3. 機器學習專案策略（structuring ML projects）
4. 卷積網路（CNN，電腦視覺）
5. 序列模型（時間序列、文字），含 transformer

### 調參那段的金句

「我認識的每一個後來變得很強的博士生，都在某個時間點凌晨兩點在調超參數。」
「有些晚上，我調參的技術好不好，差別就是**三點回家睡** vs **七點回家睡**。」（他自己補：別學我）

### 專案策略那段（Lecture 3 / 6 的伏筆）

- 例子：人臉辨識開門系統。相機、去背、切臉、註冊、比對、要不要再拍一張防照片攻擊——決策點很多。
- 「經驗不足的團隊常常**幾乎是隨機挑事情做**：讀到一篇論文說要更多資料，就花六個月去收資料。
  但很多時候收更多資料對你的應用根本沒幫助。」
- 反例：某家族企業 CTO 買了一大堆 GPU，然後指著他還在念大學部的姪子說「我姪子懂 AI，我把這筆預算交給他」。
- 「有紀律的開發流程，是速度上**十倍**差距的來源。我看過團隊花六到十個月走一條有經驗的工程師六個月前
  就能告訴他們走不通的路。」

## 主線五：AI 輔助寫程式（現場舉手：幾乎全班都在用）

- 「我個人希望這輩子再也不要回去手刻程式。」（在咖啡店看到有人手刻，禮貌地問了才知道是別校的作業）
- **兩個 bucket**：quick and dirty 原型 vs production-grade 軟體。AI 輔助對**原型**的幫助最大。
- 反例（同一天早上發生）：合作者用某個 agent coder，**database migration 出錯，把資料庫紀錄全清掉了**
  ——所幸是只有五個使用者的測試應用。所以他對 production 的用法比較小心。
- **sandbox 論點**：原型只跑在自己筆電、不碰敏感資料，那安全需求就可以低一點
  ——「除非你打算惡意入侵你自己的筆電」。在沙盒裡就能不管擴展性/安全/可靠性，決策快很多。
- 「try 20 things and see what sticks」：很多團隊為 PoC 進不了 production 而焦慮，
  「如果一個 PoC 夠便宜，做 20 個又何妨？那就是找到那一兩個真正有用的東西的代價。」
- **「move fast and be responsible」**（明確對照 move fast and break things）：
  「有些團隊從那句話學到的是不要快，我覺得那是錯的。我認識最負責任的團隊，往往也是跑最快的團隊，
  因為快才能真的把東西做出來、才會知道資料裡有什麼、使用者要什麼，那才是找出哪裡會出錯的最好方法。」

### 為什麼 ML 專案一定要「先做出來才知道」

「你 100% 控制你的程式碼，但你**不控制資料**。」
他做了那麼多次語音辨識，到現在還是會被資料嚇到：某種口音比預期多、有人講特別快、車上背景噪音很大、
最近一個案子則是被**背景說話的人數**嚇到（使用者對我們講話、轉頭跟別人講話、再轉回來，系統就混亂了）。

## 主線六：職涯（本講最有傳播力的一段）

- **「不要學寫程式」是史上最糟的職涯建議之一。** 理由：coding 變簡單時，該有**更多**人寫程式，不是更少。
  - 打孔卡 → 鍵盤終端機：更多人學寫程式
  - 組合語言 → 高階語言：更多人學寫程式
  - 他去翻了 COBOL 剛發明時的文章，當年真的有人說「有 COBOL 了，程式這麼好寫，還需要程式設計師嗎？」
- **CS 新鮮人失業率上升**的解讀：不是 AI 取代了，而是很多學校課綱**從 2002 年以來幾乎沒變**，
  教出來的是非 AI 時代的技能組。「我今天不會雇用一個不會用 AI 輔助寫程式的軟體工程師，
  就像我不會雇用一個用打孔卡而不用鍵盤的人。」
- **真實案例**：他前後面試兩個人——一個還沒畢業但很懂 GenAI 工具鏈，一個十年全端經驗但技能組跟 2002 年一樣、
  完全沒碰 AI 輔助。他選了那個還沒畢業的。
- **四級生產力排序**（他自己強調無不敬之意）：
  1. 沒經驗、不懂 AI
  2. 十年經驗、不懂 AI
  3. 應屆畢業、懂 AI
  4. 十年經驗、又懂 AI ← 最強
  「兩個因素之間，真的懂 AI 很重要，但經驗也很重要。」
- **midjourney / 藝術史的故事**：合作者 Tommy Nelson 懂藝術史，能用流派、靈感、色盤的語言去 prompt，
  生出漂亮的圖；Ng 只會打「請給我漂亮的機器人圖」，永遠拿不到那種控制力，最後整套素材都用對方的。
  → 「**未來最重要的技能之一，是懂電腦與 AI 怎麼運作，才能用 AI 的語言精確告訴電腦你要什麼。**」
- **他面試 GenAI 職位會看的工具袋**（逐項列出，可直接對照站上既有系列）：
  RAG / 向量資料庫 / evals 與 error analysis / guardrails / 知識圖譜介接 / multimodal / fine-tuning / agentic workflows
- 「很多雇主自己還沒搞懂怎麼面試。一家公司如果沒有人懂 GenAI，他們要怎麼知道該怎麼考？」

## 主線七：問答裡的有用細節

- **要多少資料才夠？** 很難知道。做過或文獻有的題目有 gut sense（例：**從零訓人臉辨識，五萬張不重複的臉算不錯**）。
  全新題目（greenfield，例如沒人收過的新醫材血液資料）就先收一點、先訓一個模型，
  用它的成敗來校準需要多少——「有時候一百筆就夠，有時候一千億筆還在要更多」。
- **CS129 / CS229 / CS230 定位**：129 最容易的入門坡道；229 數學理論重、步調快、涵蓋面廣（監督/非監督/決策樹/boosting/k-means）；
  230 最應用、只做 deep learning、幾乎不做證明。229 與 230 重疊刻意做得很低，可同時修。
- 「把 Stanford 的 AI 課當寶可夢，你要全部收集。」
