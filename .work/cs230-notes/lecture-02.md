## 暖身：把「模型」講清楚

- **模型 = 架構 + 參數**。「你想 ChatGPT 在雲端上其實就是兩個檔案：一個描述架構，一個描述參數。
  你不斷呼叫這兩個檔案，就得到推論結果。當然實際複雜得多，但核心就是這兩件事。」
- 可變的東西：輸入型態、輸出型態（分類/迴歸/生成）、架構、**loss function**、activation、optimizer、超參數。
- **loss function 是一門藝術**：「厲害的 deep learning 研究者在設計 loss function 上非常有創意。」
  YOLO（You Only Look Once，不是 You Only Live Once）的 loss function 第一次看很難懂，但那是有理由的。

### capacity（容量）這個詞

- 網路越深，capacity 越大。
- 淺網路 + 一百萬張貓照 → 學不動（不夠彈性）。
- **十億參數的 transformer + 一百萬張貓照 → 它不會學到「貓是什麼」，它會把那一百萬張背起來**，
  因為 capacity 遠大於資料集。
- → **資料量與資料多樣性決定你該用多大 capacity 的模型。**

### 一層一層在看什麼（可畫圖）

臉部資料訓練的三層網路，逐神經元去看：
- 第一層看的是像素 → 對角邊、垂直邊、水平邊
- 中間層看的是第一層的輸出 → 眼睛、鼻子、耳朵（有邊就能拼出圓）
- 深層 → 更大的臉部結構，越接近任務本身

→ 這就是 encoding。**Lecture 10 會整堂講怎麼可視化與解讀這件事。**

### encoding vs embedding（本講最該記住的定義）

> encoding 是任何向量表示；**當這個向量之間的「距離」有意義時，它才叫 embedding。**

- feature engineering（過去：手刻眼睛偵測器、嘴巴偵測器再組起來）
  vs **feature learning / end-to-end learning**（現在：讓資料自己說話）。
- 「你不需要告訴網路眼睛對辨識臉很重要，它自己會學到。」

### 最常見的錯誤

「專案裡我們看到的**第一名錯誤**，是人們加了資料卻忘了調整標籤。」
（貓 → 貓/狗/長頸鹿，輸出層要變三顆神經元，標籤要變 one-hot；同時出現多種動物要 multi-hot。）

## 案例一：日夜分類（暖身，但重點在「任務定義」）

刻意設定「假裝 foundation model 不存在」，要學生從零想。

**學生一路挖出來的困難案例**：室內照片（但畫面裡有時鐘）、時鐘只能分 12 小時（要靠穿著推溫度）、
晴天陰天、**挪威/瑞典北部（時鐘也救不了你）**、黎明與黃昏（連「日/夜」的定義都要先訂）。

> 「問題看起來很簡單，實際上可以非常複雜。而且說真的，這件事想做到很好，**今天的 foundation model 在某些情況也做不到**。」

### 用人當 proxy 決定解析度（最實用的一招）

- 把圖片印成不同解析度發給朋友看，問他們判斷得出白天黑夜嗎。低於某個解析度就判斷不出來了。
- **結論落在 64×64×3。**
- 特別強調那個 **3**：這題顏色有資訊（藍天），去掉顏色人類都變難判斷。
  但後面 RL 那講會看到，OpenAI 和 DeepMind 在某個著名演算法裡發現**拿掉顏色模型效能不受影響、訓練卻簡單很多**。
- > 「在你的 AI 專案裡，總會有需要驗證假設的時候，而你手上最好的 proxy 就是人。」

### 解析度的取捨

| 太低 | 太高 |
|---|---|
| 資訊不足（時鐘可能根本沒入鏡） | 算力貴、訓練慢、**迭代週期變長** |

- 硬體限制影響很大，但**信封背面的計算是算「迭代能多快」，不是算最終效能**。
  「如果你的模型要訓練一年，你就沒辦法迭代了。」
- 「deep learning 是一門**工程學科**，你得去試，或者你得知道那些 hack。」
  「Meta 為什麼要開瘋狂的價碼挖那幾個研究員？因為他們**真的知道那些 hack**。」

## 案例二：喚醒詞偵測（trigger word detection）

**先講清楚產品架構**：語音助理不是單一模型，是**模型串接（cascade）**，為了省電：
1. 極輕量的活動偵測（有沒有聲音）
2. 喚醒詞模型（Alexa / Hey Siri / OK Google）
3. 才叫更重、更慢、更耗電的理解模型

（順帶：Amazon 當年為了選哪個字吵很久——**要選日常對話不會用到的字**，不然助理一直被喚醒。
「activate 其實是個很糟的選擇，Alexa 也不算理想。」）

### 資料分佈的坑（全部由學生答出來）

- **口音**：第一版模型「我的德國朋友一個都用不起來」，只好去找他當時的兩個德國室友補錄。
- **年齡**：校園平均年齡比 Palo Alto 低，頻率分佈不同。
- **語速**：對人類差別不大，但**只看數字和頻率的話兩者完全不一樣**，模型很吃虧。
- **性別**：頻率分佈不同。
- **背景噪音**：史丹佛校園聽不到地鐵 → **這個模型很可能對天天搭地鐵的紐約人失效。**

### 標籤方案的人體實驗（本講最漂亮的一段）

播三段義大利語音檔，學生扮演模型：
- **方案一**：只告訴你「第 1 和第 3 段裡有那個詞」→ 幾乎沒人猜得到。
- **方案二**：標出詞出現的**位置** → 馬上有人猜出來（pomeriggio）。
- > 「**對你比較容易，對模型就比較容易。**」
- 關鍵論證：方案一標起來比較省事，但模型**大概需要一千倍的資料**才學得會；
  而方案二的標註成本**並沒有貴一千倍**。所以答案很清楚。
- 補充：這也是解 **cold start** 的辦法——先用資訊密的標籤方案讓模型「開竅」，後面的資料再換標法。

### 類別極度不平衡的工程 hack

- 如果整段只有一個 1，「全部猜 0」就有 99.9% 準確率，梯度會往全 0 倒。
- 解法：把 1 的區段**拉長**，讓正負標籤沒那麼失衡。
  Kian 自己講得很白：「**純粹是工程 hack，背後沒什麼科學。**」
- 架構是 RNN，最後一層是**每個時間步一個 sigmoid**，loss 是**逐時間步的 binary cross-entropy**。

### 三小時做出上百萬筆訓練資料（合成資料 pipeline）

三個資料庫：
1. 正例詞（親自錄）
2. 負例詞（deactivate、kitchen、lion、dog…——刻意包含**和正例發音接近的負例**）
3. **背景噪音（線上幾乎免費，影音平台抽音軌就有）**

做法：去線上抓**自由授權**資料（他特別說「搞懂授權模式本身就是一項技能，學一次受用一輩子：
CC BY、CC BY-NC、MIT、Apache」），再雇幾個人帶手機到校園錄人講 activate 和其他詞，
把詞精準剪出來，然後寫一個 Python 腳本把詞**隨機、不重疊地**插進 10 秒背景噪音裡。

> **關鍵在於：腳本知道它把 activate 插在哪裡，所以它可以自動標註。**

一千個 activate × 一萬個其他詞 × 無限背景噪音，再加資料增強（升降頻、加速減速）
→ **三小時內生出上百萬筆資料。**

**但測試集不能這樣做。** 測試集要盡量真實，必須人工標，不過量小很多。

### 架構搜尋：去問專家

「我那時候的學習是：**去找專家，問他們試過什麼，從他們的失敗學。**」
他提到 Awni Hannun（在 Gates 大樓一樓）一看就知道那個架構會失敗、而且知道為什麼，
因為他做過太多語音專案。「**所以你的 TA 就是幹這個用的**，去找他們問『我這樣做對嗎、下週該往哪走』。」

## 案例三：人臉驗證 → 辨識 → 分群

情境：學校想用人臉驗證取代刷學生證（餐廳、健身房、泳池）。

- 解析度 **412×412×3**，比日夜分類高得多，因為連瞳孔顏色都要分得出來。
  「機場快速通關的解析度比這還高得多，他們是要看到**虹膜**那個層級。」

### 為什麼不能直接比像素

- **光線**：兩張圖左上角像素差值接近 255，但那個像素根本不重要——「它會在完全不影響判斷的地方懲罰你」。
- 平移/旋轉/縮放不變性：人往右三個像素，逐像素比較就完全不同了。
- 非幾何因素：眼鏡、帽子、髮型、鬍子、年齡（學生證上的人總是比較年輕）。

### 解法：encoding + 門檻

兩張圖過**同一個**網路 → 各拿一個 128 維向量 → 算距離（0.4）→ 設門檻（0.5）→ 判定。
- 門檻決定 true positive / false positive / false negative 的取捨。
- 「**機場的門檻和史丹佛餐廳的門檻當然不一樣。**」
- 學生問「128 維裡面到底是什麼特徵？」→ 「**現在我答不出來**，除非我去做那個研究。
  deep learning 的重點是你設計一個 loss function，逼參數去學出特徵。」（再次伏筆 Lecture 10）

### triplet loss（現場帶學生推導出來）

- 用白話講目標：**同一個人的不同照片要有相近的向量，不同人的照片要有相遠的向量。**
- 資料是三元組：anchor / positive（同一人）/ negative（不同人）。
- 現場投票題（A/B/C，結果 47 : 23 : 3，A 正確）：關鍵在題目寫的是 **minimize**，
  最小化 anchor-negative 距離的相反數，等於最大化它。
- alpha（margin）：沒有它的話「全部輸出 0」就是合法解，會造成不穩定。
- 來源：**FaceNet, 2015（Schroff et al.）**。Kian 說他投影片一律附論文連結，很多學生拿去做專案。
- 「恭喜，你設計了你的第一個 loss function。」
- 註：negative 只在**訓練時**存在，測試時只有相機那張圖過網路再比對，「那只是訓練用的技巧」。

### 驗證 vs 辨識（用機場解釋，很好用）

| | 定義 | 生活例子 |
|---|---|---|
| verification | 給定兩張，是不是同一人 | 歐洲海關：先放護照，再拍照比對 |
| identification | 只給一張，你是誰 | 美國 Global Entry：什麼都不用放，看鏡頭就走 |

- 辨識的做法：**資料庫存向量而不是存圖**，然後跑 **K nearest neighbors**。
- 每人存三個向量，若最近的三個都指向同一人，可信度更高；機場可以做到 10-NN。
- 不在資料庫裡的人 → 最近向量的距離會超過門檻 → 擋下來。

### 分群

手機相簿自動把媽媽的照片歸一類：**k-means 在 embedding 上跑**。
手機大概是存一個「媽媽的 centroid」，新照片離哪個 centroid 近就丟進哪個資料夾。

## 第三段：自監督學習（本講的重頭戲）

問題：**標註很貴，如果完全沒有標籤要怎麼訓出上面那個 encoder？**

（學生一時卡住，Kian 逼問得很細：「你不能先分群，因為分群是靠 encoder 才work 的；
我給你一個隨機初始化的網路，你拍我週六和週日的照片，向量完全對不上，你怎麼開始？」）

### 答案：用資料增強自己造監督訊號

- 狗的照片旋轉 90 度還是同一隻狗。人腦用的是「旋轉不變性 + 語意理解」。
- 那就設計一個 loss，逼這兩張圖的向量靠近。
- 或者把同一張臉遮左半 / 遮右半，告訴網路「這兩個應該幾乎同一個向量」。
- **不需要 triplet 了**，一張圖加各種變形（雜訊、旋轉、裁切、平移）就能成對。
- 論文：**SimCLR**。**這叫 contrastive learning。**

> **「從 2015 年 FaceNet 的監督式 triplet，到自監督的 pairs——這就是為什麼現代模型能用『數十億張未標註影像』訓練。」**
> 「其實比大家想的簡單，寫個腳本去爬就好，最後複雜的地方是算力。」

### 文字：next token prediction 就是自監督

「self 來自於**不是你手動標的**。」

**現場做的五個接龍，每個對應一種「湧現行為」**（這段可以整段搬進文章）：

| 句子 | 學生答案 | 逼出來的能力 |
|---|---|---|
| I poured myself a cup of ___ | tea / coffee / water | 東西要**裝得進杯子**、而且是**液體**；還有文化差異（哪個國家答 tea 哪個答 coffee） |
| The capital of France is ___ | Paris | **編碼真實世界事實** |
| She unlocked her phone using her ___ | face / password / fingerprint | 語意分群：這些東西都是**用來解鎖的** |
| The cat chased the ___ | dog / mouse / ball | **機率推理**（同一句在資料裡有很多不同結尾） |
| If it's raining I should bring an ___ | umbrella | **推理與推論**：把條件連起來 |

> 定義：「**湧現行為＝在規模化之下，由簡單訓練目標產生的、未被明確教導或標註的非預期能力。**」

- 對照：以前做人臉驗證要刻意造 triplet 並宣告「這是人臉驗證任務」；
  現在直接爬全網做 contrastive learning，**你根本沒定義過人臉驗證這個任務，它就會了。**
- 伏筆：Lecture 5 會講機器人與遊戲裡的湧現行為（AlphaGo）。

### 其他模態怎麼自監督

| 模態 | 任務 |
|---|---|
| 音訊 | 遮掉 20 個時間步再補回來 |
| 影片 | 抽掉幾個 frame |
| 生物 | 遮掉蛋白質結構 / DNA 的一段再補 |
| 自駕 | 多模態，之後的課會談 |

「限制只有算力和規模。」

## 第四段：弱監督與多模態

- 連接文字與影像需要成對資料（image caption）。但這**不叫監督式，叫 weakly supervised**：
  > 「你並不是在幫圖片標註說明文字，你是在**利用世界上自然出現的配對**。」（例：Instagram 的貼文與圖）
- 學生現場丟出的自然配對（很好用的清單）：
  影片與其音軌（狗叫的畫面＋狗叫的聲音）、電影與字幕、音樂與歌名、基因型與表現型、
  醫學影像與超音波、遊戲畫面與鍵盤操作、表情。
- **ImageBind（Meta）**：大多數模態都透過**單一樞紐**互相連接——熱成像連到影像，影像連到文字，
  所以熱成像透過影像連到了文字。
  - 「大多數東西都連到文字，所以**文字通常就是你要的共享空間**。」
  - Demo：輸入文字 "drums" → 拿到鼓聲，也拿到向量空間中最接近的影像；
    輸入「狗叫聲 + 海灘照片」→ 得到「狗在海灘上」。
  - 「把這些共享空間綁在一起，大概是過去幾年最大的創新之一。」
