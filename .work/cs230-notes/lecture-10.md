## ★ 開場案例：你是 frontier lab 的模型訓練員

情境設定得很好，可以整段當文章開頭：

> 你在訓練一個 **2000 億參數**的模型。昨晚一個新的 checkpoint 通過了訓練 sanity check，
> 但出現幾個問題：
> - **推理 benchmark 變差**
> - **部分安全 eval 沒過**
> - 在 agentic workflow 裡**工具使用的延遲出現奇怪的尖峰**
>
> 你的 VP 問：「發生什麼事了？」
> **在你碰任何程式碼、重新訓練之前，你要先看哪些證據？**

學生依序答出（Kian 一路追問「這些都是全域的答案，如果要**從內部**更精確地檢查模型呢？」）：

- error analysis：找失敗案例的**模式**
- 訓練 loss 是否**平滑、有沒有大尖峰**；validation loss 應該跟著同一條曲線但略高
- **最後一批訓練資料是不是被下毒或偏向某個類別**
- 比較 checkpoint，定位問題出現的時刻（梯度爆炸／消失）
- 硬體故障（因為是一夜之間發生的）
- **attention map**：「這個 token 跟那個明明沒關係，但模型好像覺得有」
- 敏感度分析：optimizer、learning rate schedule 是不是沒調好
- **scaling law 比對**：模型是不是該訓久一點？還是模型相對於資料量太小？
- **mixture of experts 的問題**（他自己補的，很重要）：
  > 「可能某些 expert 失效了，或者 **router 一直選同一個 expert**，因為它找到一個很好、
  > 很通用的 expert，其他都沒被用到。**那模型就不是在以 2000 億參數運作，它在以一個更小的模型運作。**」

# 第一部分：卷積網路（六種方法）

## 情境

你幫動物園做了動物分類器，但他們**不願意在沒有人監督的情況下使用**，因為他們不理解模型的決策過程。
你要怎麼緩解他們的疑慮？

## 方法一：saliency map（顯著圖）

對**輸入像素**求「狗」這個類別分數的導數：`∂S_dog / ∂X`

> 「白話說就是：**當你移動像素時，狗的分數怎麼變？**」

亮的像素＝梯度高＝改它會影響狗的分數。暗的＝改了完全沒差。

**★ 一個常見誤解（他特別強調）：要用 softmax 之前的分數，不是之後的。**
> 「softmax 之後的分數**不只取決於狗，也取決於所有其他分數**。
> 你可能動了一個像素，結果它剛好改變了『貓熊』的分數（因為背景有隻貓熊），
> 這就污染了你想展示的東西。**你只想要狗的分數被影響。**」

**用法**：可以當快速的分割 sanity check。而且——
> 「如果你算完梯度，發現亮的像素**散得到處都是**，那大概是模型**根本沒在看對地方，它只是運氣好。**」

**缺點**：只看到像素層級，語意上不太合理——「模型永遠不會看到一隻只有一個像素不同的貓或狗，那太不連續了。」

## 方法二：integrated gradients（整合梯度）

saliency map 的延伸，更常用。做法：從**全黑的圖**漸變到目標影像，
沿路把梯度積分起來。

**實例**：視網膜影像，integrated gradients 標出來的位置**正好是病灶的標註位置**。

## 方法三：occlusion sensitivity（遮擋敏感度）

最直觀的一個：拿一個深色方塊在圖上掃過去，記錄「狗」的分數怎麼變，畫成機率圖。

> 「很簡單，但**計算很貴**——你得把同一張圖跑過模型非常多次。」

**三個實例（第三個特別有意思）：**

| 真實標籤 | 觀察 |
|---|---|
| 博美犬 | 方塊蓋住臉的中央時分數掉下來——合理，因為要分辨**品種**得看臉 |
| 車輪 | 方塊蓋住輪子時分數掉下來 |
| **阿富汗獵犬** | 蓋住狗時分數掉，**但蓋住左邊人臉時分數反而上升**——「你等於是在**移除多餘的干擾資訊**，讓它更容易找到真實類別」 |

## 方法四：class activation map（CAM）— 需要改架構

情境升級：動物園要**即時**的決策過程視覺化，你只有一天。前三個方法都是**事後**分析，
這裡要一個能**插進網路裡持續運作的模組**。

### 先找出架構的弱點（他讓學生答出來）

原架構：`conv-relu-maxpool × N → flatten → FC → FC → FC → softmax`

> **弱點是那三層全連接層。** 「你同時看所有像素、把所有東西混在一起，而且做了三次。
> 三層下來資訊已經完全混掉，你**再也找不到 conv 和 maxpool 保留的那些局部化資訊**。」

### 解法：global average pooling

把 `flatten + 三層 FC` 換成 `global average pooling + 一層 FC`。

最後一個 conv block 給出一個 volume（例如 4×4×6）。GAP 把**每一個 channel（feature map）
平均成一個數字**，得到長度 6 的向量。

> 「為什麼這樣有意思？因為**我們沒有失去局部化資訊**。我們沒有把東西混在一起，
> 只是給每張保留下來的 feature map **指派了一個數字**。局部化資訊還留在前一個 volume 上。」

**CAM 的做法**：拿最後那層 FC 中**對應「狗」這個分數的權重**，
去加權疊加最後那六張 feature map，就得到「狗」的 class activation map。
（注意：**改架構後那一層要重新訓練**。）

換成「貓」就用不同的權重，貢獻度自然不同。

改良版：**Grad-CAM**。

**學生的好問題**：影片裡模型有時候在看沒意義的東西。Kian 的回答很誠實：
> 「不意外。這是**上一代**的模型，而且你看的是影片。它是分類網路，
> 有時候會看到根本沒被標註的東西，只好去找最接近的類別，可能完全沒道理。
> **這正是你要建這種視覺化模組的原因——去理解『這個網路其實沒那麼好用』。**」

## 方法五：class model visualization（梯度上升）

新問題：動物園開始擔心——**模型到底懂不懂什麼是狗，還是只是在亂 pattern matching？**

做法：**問模型「你心目中的狗長什麼樣」**。

```
maximize  S_dog(X)  +  正則項
```

- 一樣用 **softmax 之前**的分數（否則可以靠壓低其他類別來作弊）
- 正則項是為了讓像素留在 0–255、看起來自然
- 從**完全隨機**的影像開始，梯度**上升**更新像素

**★ 結果非常有啟發性（這幾個例子可以直接搬）：**

| 類別 | 模型生出來的東西 | 意味著什麼 |
|---|---|---|
| **大麥町** | 白底上的黑點 | 「模型可能沒完全理解什麼是狗，**但它就是這麼認為的**」 |
| **鵝** | **一大群鵝** | 「模型大概**總是看到成群的鵝、很少看到單獨一隻**。也許標註資料把一群鵝標成 goose，所以模型認為**整群**才是那個標籤。」 |
| **紅鶴** | 同樣是一大群 | 同上 |

（研究者後來靠改良正則化讓這些圖對人眼更好看、更容易判讀。）

**★ 同樣的方法可以用在網路內部的任何一個激活上**：
「給我那張能最大化這個激活的輸入圖」——這就給了你**神經元層級**的探測工具。

## 方法六：dataset search（今天最常用的）

> 「這是**今天最常被使用的方法，因為它太簡單也太直觀了。**」

挑一張 feature map，掃過整個驗證集，找出**讓它激活最強的前五（或前九）張圖**。

- 如果那五張全是襯衫 → 這個 filter 學會偵測襯衫
- 如果全是邊緣 → 它學會偵測邊緣

### ★ 為什麼那些圖都是裁切過的：感受野（receptive field）

他用一個很好的提問帶出來：「你挑的那個激活，**它看得到整張輸入圖嗎？**」

- 第一層：那個激活只看得到 filter 覆蓋的範圍
- **越深，單一激活看得到的輸入範圍越大**
- 最後的輸出看得到整張圖

> 「所以那些圖是裁切過的——**是根據那個激活在輸入空間裡實際看到的範圍去裁的**，
> 這在計算上很容易做到。」

## 方法七：deconvolution（反卷積 / 轉置卷積）逆向工程

**這是本講數學最重的一段，但結論很實用。**

### 先建立：卷積就是矩陣乘法

1D 卷積、輸入補兩個零、filter 大小 4、stride 2 → 輸出大小 5。
把它寫成聯立方程組，就能寫成一個 **5×12 的權重矩陣乘以輸入向量**。
畫出來是**對角線上有值、其餘為零**的矩陣。

### 兩個假設（他很誠實地標明這是工程近似）

1. 假設 `W` **可逆**，於是存在 `H = W⁻¹` 使得 `X = HY`
2. 假設 `W` **正交**，於是 `W⁻¹ = Wᵀ`

> 「有時候真的成立——想想一個邊緣偵測器，它確實可逆，而且逆矩陣就是轉置。
> **也許不總是成立，但在深度學習裡成立到足以能用。這是工程學科。**
> 這就是為什麼文獻裡常把 deconvolution 叫做 **transposed convolution**。」

### ★ 實作口訣（他說如果只記一件事就記這個）

> 要把一個卷積反轉：
> 1. **把 filter 翻轉**
> 2. **做輸入的 subpixel 版本**（在數值之間插零，再加 padding）
> 3. **stride 除以二**
> 4. 照一般卷積跑
>
> 「我們只是把卷積**改寫成另一個卷積**，只是超參數不同——**這樣很好寫程式，你就是重用同一套 code。**」

### unpooling 的 switches（很聰明的細節）

**max pooling 不可逆**：你知道 6 是那四格裡的某一格，**但你不知道是哪一格**。而位置很重要。

**解法**：前向傳播時用一個**很輕量的二元矩陣**記下 max 發生在哪裡（叫 **switches**），
反向時把 switches 傳回來。

**ReLU 的處理更 ad hoc**（他自承是經驗性的）：
反向重建時**就再用一次 ReLU**，而不是真正的 ReLU backward——
目的是「從 feature map 上最高的激活出發，**持續把正訊號傳回輸入空間**」。

### 完整流程

送一張狗的圖進網路 → 挑一張 feature map → 找出最大激活的位置 →
**把其他所有位置歸零** → 反轉網路（unpool + 反 ReLU + deconv，有幾個 block 就做幾次）
→ 得到**這個激活究竟被什麼像素最大化**的裁切圖。

## 實際的視覺化成果

**Zeiler & Fergus**（5 萬張驗證圖）：
- 第一層：每個 filter 的**前九張最強激活**（就是 dataset search）；
  第一層**可以直接把 filter 印出來**看（邊緣偵測器印出來就長得像邊緣偵測器）
  ——**但第一層之後就不行了**
- 第二層起：用 deconv，256 張 feature map 各找 top-1 或 top-9，
  可以看到某些 filter 明確在偵測圓形、某些在偵測特定形狀
- 第三層：「filter 捕捉的資訊更複雜了。**這就是第一講說『越深特徵越複雜』的證明。**」

**Jason Yosinski 的 Deep Visualization Toolbox**（他放了影片，並現場對照方法名稱）：
- 第一層某個神經元對**亮→暗**的邊緣反應強，隔壁那個對**暗→亮**反應強
- 到第五個 conv 層，特徵已經代表**抽象概念**——「這個神經元似乎對**臉**有反應」
- 用 deconv 可以看出「如果眼睛更暗、嘴唇更紅，它會反應更強」，
  而且「**它在乎頭和肩膀，但忽略手臂和軀幹**」，甚至「**對貓臉也有一定程度的反應**」
- 還能追出這個單元最依賴前一層 conv4 的哪幾個單元、conv3 的哪十幾個單元

# 第二部分：frontier model

## CNN vs 現代模型的核心差異（一句話）

| | 處理的東西 | 視覺化的是 |
|---|---|---|
| **CNN** | 局部化資訊 | 邊緣、紋理、形狀 |
| **LLM** | **關係** | **概念與 token 之間的關係與意義** |

因為 transformer 建立在 **attention** 之上。

## 兩個可視化的抓手

**1. attention pattern**
- 看某個 token 和其他 token 的關係
- 「每個 attention head 學到不同的模式：**把代名詞連到名詞、追蹤結構、強制某種順序**」
- 出處：**Jesse Vig, 2019** 的視覺化與部落格文章
- > 「這**就是 CNN 的 saliency map 在 transformer 上的對應物**。」

**2. embedding + 降維**
- 用 **t-SNE**（他提到「這在生技和醫療領域教得很多，Stanford Hospital 那邊用得很兇」）
- 語意相近的 token 應該靠在一起，無關的應該遠離
- > 「這是一種**檢查模型是否真的學到有意義的表示**的方法。」
- 他說以現在的程度「**你已經可以去讀 BERT 那篇論文了**」

## ★ 但可解釋性其實還沒被解決（很誠實的一段）

> 「不幸的是，現代 transformer 複雜到——**即使是最前沿的研究，也只能解釋兩層的 transformer。**」

他指出目前最好的成果來自 **Anthropic**，並連了兩篇：
1. **A Mathematical Framework for Transformer Circuits** — 解釋 transformer 內部各元件如何互動，
   引入 **circuit** 的概念
2. **In-context Learning and Induction Heads** — 「**induction head 大概是我們目前最好的、
   能看見 transformer 內部發生什麼事的工具。**」

## 訓練與 scaling 診斷（training telemetry）

要看的：訓練 loss、驗證 loss（**全域的，以及分資料子集的**）、**梯度範數**、
learning rate schedule、**硬體效率指標**（判斷算力有沒有被低估使用）。

- loss 上的突然跳動 → 可能是**某個 batch 被汙染**；或者「你在它上面表現好到不該那麼好，那就該亮紅燈」
- 梯度爆炸／消失也在這裡看
- > 「我記得以前甚至有部落格專門讓大家貼**自己最醜的 loss function**，上面有一大堆。」

**★ 為什麼你在外面看不到這些：**
> 「frontier lab **很少公佈這些儀表板，因為那是 IP**——會洩漏他們架構的關鍵資訊、
> 什麼有效什麼無效。所以你通常是**一年一年慢慢知道**：
> 你會學到三四年前那個模型的做法，因為他們現在願意分享了。這很常見。」

## ★ scaling law 與 Chinchilla（講得很清楚）

- 出處：**DeepMind, 2022, Chinchilla**
- 做法：**固定其中兩個變數，變動第三個**（算力 / 資料集大小 / 參數量），
  看 test loss 的冪次關係是否成立
- **結論**：Chinchilla 分析 GPT-3 後指出——
  > 「**GPT-3 相對於它的規模表現得不夠好，因為它訓練得不夠久。**
  > 如果你繼續訓練 GPT-3 更久，效能會好非常多。**問題不在模型大小，模型其實沒被充分利用。**」
- 具體對比：**Chinchilla 700 億參數 vs GPT-3 1750 億參數，Chinchilla 表現更好**
- 圖的讀法：**點在線上方 = 你的模型應該再訓練久一點**；點在線上 = 符合 scaling law

**為什麼這件事重要（金錢論證）：**
> 「訓練一次的成本非常高。沒有公開，但**我們估計 GPT-5 大概在數億美元的量級**。
> 所以你會想知道：**我該不該把這個模型訓練兩倍長？**那是個很大的財務決策。
> scaling law 讓你判斷——**該投資在算力、在擴大資料集、還是在放大模型容量？**」

## benchmark 與汙染

### ★ 他對公開 benchmark 的態度（值得整段引用）

> 「**我不太看 foundation model 供應商自己發布的 benchmark。**
> 或者換個說法，我會看模型之間的**相對值**，而不是**絕對值**。
>
> 然後你會等社群在 agentic workflow 上、在他們自己的任務上測試它，
> 人們慢慢就會嚐出它能不能用、在什麼地方能用。
>
> 比如說，**社群花了一段時間才意識到 Claude 在寫程式上有多好。**
> 從 benchmark 上看不太出來——benchmark 上看起來別人也都很好。
> 但隨著時間過去，大家開始覺得『喔哇，它寫程式真的很強』。」

（學生舉了 **Llama 4** 當例子：benchmark 好看，社群實測後不行。）

### 怎麼偵測測試集被汙染

| 方法 | 做法 |
|---|---|
| **n-gram 搜尋** | 取 7、8 個 token 的序列，在訓練集裡找測試集的相同 n-gram |
| hash | 同上，用雜湊 |
| **embedding 搜尋** | 抓**語意上**的重複——「也許不是逐字相同，而是語意相同」 |

汙染來源他舉的例子很具體：「也許它訓練到一篇部落格文章，有人在介紹那個 benchmark；
也許它訓練到 GitHub 上某個很陰暗的角落裡，有個 text 檔列出了部分測試集的資訊。」

**發現汙染後的處置**：測試集比較小，把可疑的例子拿掉，**換成全新的、離線保存在
一個不上網的資料夾裡的題目**。

### ★ 這些儀表板的實際用途（很實務的一句）

> 「這些儀表板決定了發布的 go / no-go，**也決定了 RLHF 要做在哪裡**。
> 因為監督式微調和 RLHF **都很貴**，你會想把它做在**正在失敗的東西**上。
> 如果你精確辨識出哪些 eval 在失敗，你就能把 RLHF 聚焦在那個問題上，
> **省下大量的錢和人力時間。**」

## 資料診斷

### 分佈檢查（用 The Pile 舉例）

**The Pile（2020）**：800GB 的多樣化文字資料集，**而且保留了資料的 domain 標記**
（Free Law、Wikipedia、Stack Exchange、GitHub…）。

> 「所以你不只能畫**整個資料集**的 loss，還能畫**每個 domain 各自**的 loss，
> 那給你更多關於它在哪裡失敗、在哪裡有效的直覺。」

**為什麼 domain 比例重要**：某個 domain 在資料裡代表性不足，模型在那個 domain 的表現就會掉。
（他回指 Lecture 6 的語音例子：**零太多、一太少，模型就學不會一**。）

### ★ 線上學習的風險（這段很好，站上沒有）

> 「frontier model 是**即時在學的**，資料不斷被餵進去。
> 假設**上個月那批資料裡程式碼資料很少**，那訓練的最後一段，coding domain 的頻率就比其他 domain 低。
> **如果你不小心，你就會看到某個特定 domain 的效能掉下來。**」

**解法：聰明的取樣。** 而且他直接回指 Lecture 5：
> 「還記得強化學習裡的 **experience replay** 嗎？我們把經驗存進 replay memory 再從裡面取樣。
> 就是那類取樣方法，讓模型供應商能確保**訓練的不同階段，各 domain 的資料頻率維持一致。**」

### token 統計

追蹤關鍵 token 的頻率變化。「如果**微分符號**代表性不足，那你要模型做微分時效能就會差很多。」
所以實驗室會監控 **token drift**，再用取樣修正。

實際的異常報告範例：**「新一輪網路爬取之後，非英語 token 從 12% 上升到 19%」**
——這代表那個語言的 domain 相對其他語言變重了，可能導致某個語言的效能升或降。

## ★ 收尾問答：資料快用完了嗎（很有料的一段）

**學生問：合成資料的未來？**

> 「一般來說，做資料增強、用合成資料是好主意。**但我會一直盯著 token 頻率**——
> 因為合成資料便宜太多，如果你生了某個 domain 的大量合成資料，
> **它會排擠其他 domain、拉低其他部分的效能**，那就是問題。
>
> 實務上我認為**合成資料的報酬在某個點會 plateau**。
> 最近的消息、以及 DeepMind 那篇論文，大概是說：
> **現在多數 domain 缺的是高品質資料，而不是缺合成資料。**」

**他推薦的 Epoch AI 研究報告（數字需查證，他自己說「我忘了確切的數字」）：**

| 時間 | 預測 |
|---|---|
| 2025 | frontier lab 用完網路上的**低品質文字資料** |
| 2027 | 用完**音訊、影像、影片**的低品質資料 |
| 2030 | 用完**高品質資料** |

> 「到那個時候……**大概資料就不再是瓶頸了，會變成模型架構的問題。**」

**★ 為什麼「產生的資料比用掉的多」不構成反駁（這段論證很好）：**

> 「我們產生的資料是不是比用掉的多？大概是，**但這不代表模型沒有 plateau。**
>
> 你去用 Python 寫程式，**你的 Python 程式碼 99% 大概已經在網路上某處了**，
> 所以模型其實**沒從裡面學到多少**。那只是**更多**資料，不是**更高品質**的資料，
> 我認為 plateau 就在這裡。
>
> 也許世界上最好的放射科醫師寫了一篇獨特到就定義而言是高品質的研究論文——
> **但我們能期待多少這種東西？**」

**AI 生成的資料回流：**
> 「今天的程式碼資料**越來越多是生成出來的，然後又被餵回去**。長話短說：
> **對訓練來說就沒那麼有意思了。**」

**學生問「訓練 Claude Code 只需要程式碼資料嗎？」**（他標明自己不在 Anthropic、是推測）：
> 「已經有研究顯示**某些 domain 會改善另一些 domain 的效能**。我想像在寫程式上，
> **數學資料也許真的會幫助程式碼的效能**，尤其是函數式程式設計那種比較數學的語言。
>
> 但我也很清楚，如果他們拿全網爬取的東西去訓練 Claude Code，效果不會好，
> **因為裡面有太多跟你要做的事無關的垃圾資料。所以這中間有個平衡。**」
>
> 相鄰 domain 的推測：Python 對 C++ 有幫助、C++ 對 Java 有幫助、
> Elixir 和 Scala 那類函數式語言之間也大概互相有幫助。
> 「如果 **Rust** 變紅、資料分佈裡 Rust 的 token 頻率上升，會不會影響其他語言的效能？
> **我猜會。而怎麼追蹤它？就是我們今天講的全部。**」
