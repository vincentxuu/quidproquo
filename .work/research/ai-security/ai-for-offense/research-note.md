# AI 如何做攻擊：研究與篇目草案

日期：2026-10-22。此為規劃研究，尚未安裝工具、執行攻擊、操作真實目標或建立靶場。

## 範圍與工具

使用者已修正範圍：邊界是**授權，不是本機**。涵蓋 CTF、公開訓練平台的指定實驗、自己架設的雲端靶場、獲明確授權的真實系統，以及 bug bounty 明確 scope；另分析公開歷史攻擊鏈。教學中的合成工單系統只是可重現的共同案例，不是第三線的全部。

Groundlane-first：重新搜尋完整 callable inventory，以 name 包含 groundlane 檢查，結果 0；依父代理已完成的全量 inventory 結果，Groundlane 未掛載。實際使用 Exa MCP search/fetch。沒有使用退役工具或公開網頁以外的資料。先讀 deep-research SKILL.md 與 references/mcp-tools.md；用指派的子題與邊界開始研究。沒有發送 secrets／認證內容／私有資料。

## 母群與選案偏誤

母群：能讓模型觀察環境、提出假設、呼叫工具、驗證目標狀態的公開原作者框架／評測，以及平台官方 scope 說明、第一手事件調查。排除只有問答測驗／工具廣告、沒有環境或判分規則的高成功率宣稱。

主讀 5 份：Cybench 原作者正文 O2、PentestGPT README O3、AutoPenBench README O5、CyberSecEval autonomous_uplift 方法頁 O6、NIST 反證正文 O7。補讀 O1 項目頁、O4 短入口、O8/O9 授權範圍、O10 真實事件正文。這些是完整抓取的網頁／README 文字，不等於讀完連結論文。長論文只有搜尋片段，沒有援引其數字。Cybench O1/O2 同一研究團隊，不能算獨立實證。CTF 偏向已知有洞、明確終點與較乾淨環境；供應商事件有可視性與利益立場限制。不得把這些來源推成所有模型、所有目標的現況排名。

## 七篇攻擊線：篇目、前置、實作、驗收

| 篇 | 聚焦主題與前置 | 實作 | 驗收與接線 |
|---|---|---|---|
| C1 AI 如何接手一次滲透測試：人與模型各決定什麼 | 共用資料流／scope 基礎；辨別 advisor、copilot、autonomous | 用公開 framework trace 畫人類／模型／工具決策，選 CTF、訓練平台、雲端或書面授權專案 | 交任務界線、可用動作、停止條件與人工介入表；不要求全自主 |
| C2 偵察不是一直掃：AI 怎麼把觀察整理成下一個問題 | HTTP／服務／身分概念；C1 | 在指定訓練平台實驗或自架雲端工單助理，將允許範圍的端點、角色與回應建成資產／假設表 | 每個假設連觀察與下一個最小測試；離開 scope 的建議被攔下；可給調查線作基準 |
| C3 AI 找到的洞是真的嗎：從原始碼假設到測試對照 | C2；讀得懂 API | 用有洞與修補的兩個版本，讓模型定位缺少授權的路徑並提出測試 | 相同請求在兩版本呈不同預期結果；必須顯示服務端效果；對接防護線修補 |
| C4 從漏洞到可驗證利用：CTF flag 與真實影響差在哪 | C3；請求重播 | 使用獲准 CTF 題，將辨識、觸發、取得目標狀態分成里程碑；真實系統只在書面許可測試帳號與最低影響範圍驗證 | 不靠回覆宣稱成功；獨立 evaluator／測試帳號證據；修補後重播失敗 |
| C5 讓模型調工具：狀態、回傳、重試與失控的邊界 | C2–C4；工具 schema | 比較人工複製命令、受控 tool calling、分階段 agent；保存工作目錄、工具輸出、action budget | 具可重播 transcript；超時／重複操作／越權轉向停止；不將工具退出碼等同利用成功 |
| C6 AI 怎麼串起攻擊鏈：讀真實案例，再在授權環境重建關鍵轉折 | C5 | 以 O10 公開案例做階段／人工決策／可觀測證據圖；在指定雲端靶場或合成工單服務演練「資訊取得 → 權限缺口 → 受控目標狀態」 | 每一跳有前提、證據、可斷鏈防護與可偵測日誌；真實案例只分析，不重攻受害組織 |
| C7 成功率為什麼會騙人：人工協助、答案污染與失敗復盤 | C1–C6 | 同任務比 unguided／guided；重新產生秘密值，隱藏 evaluator、答案及 walkthrough；加無漏洞對照 | 同列失敗、假陽性、成本、人工提示與完成度；抽 transcript 防 grader gaming；產生可交防護／調查線的回歸案例 |

這是教學設計推論，不是來源原有課程。真實系統不預先承諾有漏洞或成果；允許產出「未確認漏洞＋已排除假設」。自動化頻率、外部模型能否接觸程式／輸出、允許工具與測試時間都要回個別書面規則確認。內容教 AI 如何攻擊的機制與實證，不把章節改成一般防禦清單。

## 關鍵主張與反證

- ✅ 動作循環、子任務及最終狀態：O2/O5/O6 可交叉支持，不依賴成果數字。
- ✅ 「編排能力＝全面成功」不成立：O7 顯示分數可被污染；O10 報告幻覺；O3 自述歷史分數不保證現行產品。
- ✅ 邊界為授權／scope，不是部署位置：O8/O9；平台規則也不授權第三方資產。
- 單一一手事件來源限制：O10 是供應商調查，不能作獨立歸因或通用自主程度的證明。已用 O7 的不同評測調查交叉檢查「成功宣稱需驗證」這個方法主張，沒有假稱其驗證同一事件。
