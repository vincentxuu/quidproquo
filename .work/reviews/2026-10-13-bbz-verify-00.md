## Verdicts

### Contradicted: none. Outdated: none.

### Misframed / needs attention

1. Misframed (link/sentence mismatch): list item 3 of the Meta section, "內部攻擊者情境另計。同一頁的附加規則寫…" (zh line 66; en line 66 "The same page says…").
   - The item follows the scope-page link (item 2), so "同一頁" reads as the scope page. The scope page (bugbounty.meta.com/scope/) contains no internal-scenario table.
   - The text is on the payout page (payout-guidelines/private-processing/), "Additional Considerations": "vulnerabilities limited to internal attack scenarios will follow…". The table gives code execution up to $50k, privilege escalation $50k, data leaks $50k, VM escape N/A, persistence $5k.
   - The numbers are correct; the pointer is wrong. A reader who clicks the scope link will not find the sentence.
2. Misframed (minor): "Chrome 在非沙盒行程的 RCE 最高 25 萬" (zh line 86; en "up to $250K for Chrome RCE in a non-sandboxed process").
   - The 2024 review (Mar 7, 2025) says: "we increased our maximum reward for a single issue to $250,000 for demonstrating RCE in the browser or other non-sandboxed process, and more if done directly without requiring a renderer compromise." It also lists "MiraclePtr Bypass Reward to $250,128".
   - 25 萬 is the stated base figure, but the original says higher amounts exist, so "最高" overstates it slightly. Suggest "起跳／最高約 25 萬，若不需先攻破 renderer 還更高".
3. Misframed / Unverifiable (action item 2): "讀一個已公開的 hypervisor 逃脫分析，例如 CVE-2024-49117 這類 Hyper-V guest-to-host 案例，估算自己複現需要多久" (zh line 101; en line 101).
   - The CVE-is-guest-to-host half is Confirmed (see claim list). The "published analysis" half is not supported.
   - I found no technical root-cause write-up for this CVE. Microsoft's advisory has no mechanics (the CVE record is title-only, CWE-393).
   - The only "explainers" are aggregator pages. One (cve-news.ghost.io) is clearly auto-generated: it dates the CVE to June 2024, shows a made-up PoC and a Patch Tuesday of June 11, 2024. SentinelOne's DB page (AI-generated, per its own disclaimer) says no verified public PoC. securityvulnerability.io claims a "public PoC" with no verifiable source.
   - Suggest not presenting this CVE as a reproducible public analysis, or swapping in a case that has an actual write-up.

### Unverifiable
- Negative claims: "Hyper-V 頁面沒有 Azure 加成", "沒找到任何 Llama 沙盒逃脫獎金條文", "Meta 官方 LLM Bounty 最高 30 萬 對不上". They are correctly hedged as "I did not find it". On the pages I read, the Azure bonus is indeed absent and there is no Llama sandbox clause. Absence is not proof; I only read the 2 Meta pages, the Hyper-V page and the Google rules.
- Meta payout page shows "$300k*" with an asterisk. The footnote text did not appear in the extraction, so I cannot say what the asterisk qualifies. The article drops the asterisk.

### Omission worth noting (not an error)
- The Hyper-V page also says "Higher awards are possible, at Microsoft's sole discretion", "Bounty awards range from $5,000 up to $250,000", and that a PoC needing a debugger (suspending threads or modifying memory) is not counted as a high-quality report. "最高 25 萬" is accurate as the table figure but not an absolute cap.

### Confirmed (all sources fetched in full)

Hyper-V (https://www.microsoft.com/en-us/msrc/bounty-hyper-v, page revision history through Apr 7, 2026). Risk: high. Sources: 1 authoritative (vendor page), single-source; no independent second source exists for a vendor's own reward table.
- L1 guest escape RCE: functioning exploit + high quality $250,000; no exploit + high $200,000; + medium $100,000; + low $50,000. ✓ (zh/en tables match)
- L2 guest escape: $150,000 (exploit + high), with $100,000 / $50,000 / $25,000 below. ✓ "最高 15 萬"
- DoS: $15,000 / $10,000 / $5,000. Info disclosure: $25,000 / $15,000 / $5,000. ✓
- L1 definition (compromise hypervisor, escape to host, escape to another L1 guest). ✓
- Azure bonus: no mention of an Azure bonus. Azure appears only in scope ("server hosting scenarios (such as Azure)"). ✓ matches "I did not see one".

Meta Private Processing payout (https://bugbounty.meta.com/payout-guidelines/private-processing/). Risk: high; vendor page, single-source.
- Code execution / RCE within TEE incl. bypassing code attestation: $300k; privilege escalation $300k; data leaks $150k; VM escape ("escapes to the host") $300k; persistence $10k. ✓ zh/en tables match.
- Internal scenarios: code exec $50k, priv-esc $50k, data leaks $50k, VM escape N/A, persistence $5k. ✓ ("降到 5 萬、VM 逃脫 N/A" is accurate; persistence's $5k is not mentioned in the article, which is fine.)
- Page says target is "the Trusted Execution Environment (TEE) that supports WhatsApp Private Processing". ✓ Not Llama.

Meta scope (https://bugbounty.meta.com/scope/). Risk: high; vendor page.
- "WhatsApp Private Processing: Access is by invitation only… Rewards for impactful findings is up to $300K USD." ✓
- Meta AI paragraph: interest in "integral privacy or security issues associated with Meta's large language models, including… leak or extract training data through… model inversion or extraction attacks." Functionality problems go to github.com/facebookresearch/llama and codellama; risky generated content goes to llama_output_feedback. ✓ (the article's paraphrase "GitHub 或回報表單" is accurate)
- Duplicates: "we award a bounty to the first person to submit an issue." ✓ A "Conditions for closing reports as invalid" list exists. ✓

Meta Engineering blog (https://engineering.fb.com/2025/04/29/security/whatsapp-private-processing-ai-tools/, Apr 29, 2025). Risk: low.
- Confidential-computing / TEE (CVM) environment for AI processing of messages (summaries, writing suggestions) so that Meta and WhatsApp cannot access them. ✓ It never mentions Llama. It also states the bounty scope would be expanded to include Private Processing. ✓

Google VRP rules (https://bughunters.google.com/about/rules/google-friends/google-and-alphabet-vulnerability-reward-program-vrp-rules). Risk: high; vendor page, plus the blog below as a second authoritative source on 101,010.
- RCE (S0) row, "Vulnerabilities giving direct access to Google servers": T0 $101,010; T1 $101,010; T2 Normal Google apps (examples *.google.com, *.youtube.com, *.blogger.com, *.admob.com) $75,000; T3a acquisition Tier 0/1 domains $10,000; T3b other acquisitions / sandboxed / lower priority $1,337–$5,000. ✓ zh/en table matches. T0 is "Tier 0 domains, or global impact". ✓ ("帳號級" is a paraphrase of footnote [0]: compromise of a user's account or code execution on their system.)
- Report quality: "0.8x, 1x, or 1.2x" (Low 0.8 / Good 1 / Exceptional 1.2). ✓
- Example: "An RCE in a server serving accounts.google.com, report is of exceptional quality (1.2x). (T0, S0) $101,010 * 1.2 = $121,212". ✓
- 75,000 × 1.2 = 90,000. ✓ arithmetic; the "9 萬 = 第三層 (T2) + 最高品質" framing holds.
- Note: the article's "第三層" is the third column (T2). The table has 5 columns, and T0 and T1 share the same price. Fine, but "第三層" could be read as "third price level", which would be wrong (T0 and T1 are one price level, and T2 is the second). Optional wording check.

Google July 2024 announcement (https://bughunters.google.com/blog/increasing-google-alphabet-vrp-rewards-up-to-151515). Risk: high.
- Published Jul 11, 2024. "maximum reward of $151,515 USD ($101,010 for an RCE in our most sensitive products, with a 1.5x modifier applied for exceptional report quality = $151,515)". ✓ "2024 年 7 月公告 151,515＝101,010×1.5".
- Old modifiers were 1.5x / 1x / 0.5x vs the current page's 1.2x / 1x / 0.8x. ✓ so "現行規則頁係數上限是 1.2" is accurate.
- FAQ: "An RCE on a tier 0 domain, with exceptional report quality will receive $101,010 * 1.5 = $151,515." ✓

Google 2024 review (https://blog.google/security/vulnerability-reward-program-2024-in/, Mar 7, 2025). Risk: high; vendor blog, same-vendor corroboration from the rules page for the multiplier context.
- "Mobile VRP is now offering up to $300,000 for critical vulnerabilities in top-tier apps." ✓ in original text.
- "Chrome awards now peak at $250,000" and "increased our maximum reward for a single issue to $250,000 for demonstrating RCE in the browser or other non-sandboxed process, and more if done directly without requiring a renderer compromise." ✓ in original text (see Misframed #2 for the hedge).
- Also states Google VRP max $151,515 and Cloud VRP top tier $151,515, consistent with the Jul 2024 post.

CVE-2024-49117. Risk: medium. Sources: (a) ZDI "The December 2024 Security Update Review" (Dustin Childs, Dec 10, 2024, https://www.zerodayinitiative.com/blog/2024/12/10/the-december-2024-security-update-review): "CVE-2024-49117 - Windows Hyper-V Remote Code Execution Vulnerability. They could also perform a cross-VM attack… the attacker does need to be authenticated… only requires basic authentication – nothing elevated." Table: Critical, CVSS 8.8, not public, not exploited. (b) CVE record via OpenCVE (mirror of CVE.org/NVD data, https://app.opencve.io/cve/CVE-2024-49117): title "Windows Hyper-V Remote Code Execution Vulnerability", published 2024-12-10, CVSS 3.1 8.8 `AV:L/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H`, CWE-393; affects Windows 11 22H2/23H2/24H2 and Server 2022/2022 23H2/2025. The scope-changed, low-privilege local vector is consistent with a guest-to-host escape.

Caveat: I could not load the MSRC page (the vendor primary), so the guest-to-host wording rests on ZDI's reading of the MSRC advisory plus consistent CVE-record metadata, not on MSRC text I read myself.
