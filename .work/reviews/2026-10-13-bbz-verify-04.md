## 3. 站內兩篇日報（已讀全文）

### 3.1 LangGraph（2026-08-27）
本文描述：「框架讀出儲存的狀態後做 msgpack 反序列化，加上前一個漏洞讓攻擊者能偽造那筆資料，兩段串起來就是未授權 RCE」；標題「SQL injection 串接不安全反序列化」；「已修補」。
日報內容：攻擊面分析段寫明 SQLi（CVE-2025-67644）→ UNION SELECT 偽造 checkpoint 列 → `loads_typed()` 走 msgpack `ormsgpack.unpackb(..., ext_hook=_unpack_ext_hook)`，ext hook 等同匯入任意模組／取屬性／呼叫（CVE-2026-28277）；tldr 與影響範圍段寫「未授權遠端程式碼執行」、「均已修補」。
Verdict：🟢 一致，歸為路徑二（不安全反序列化）恰當。
補充（資訊，非錯誤）：文中「未授權」省略日報的前提——攻擊者要能影響傳入 `get_state_history()` 的 filter 鍵（日報攻擊面分析首段）。對入門篇可接受。日報本身的事實依賴 Check Point 等來源，本次未回原始來源覆核（見範圍聲明）。

### 3.2 Manus（2026-10-03）
本文描述：「不是這篇範例的 shell 拼接，但根源相近，都是不可信的內容被送進會執行的環境。日報描述，Agent 把信件內容送進會實際執行程式的管線，結果在雲端 sandbox 裡跑了攻擊者的程式」。
日報內容：事件類型寫「Indirect Prompt Injection → RCE（郵件酬載，JSFuck 編碼繞過護欄）」；機制是郵件內容進入 agent 的執行管線，agent 被請求「解碼 JSFuck」後呼叫 Node.js 執行，解碼動作本身即執行合法 JavaScript；護欄在執行後才警告；sandbox 環境變數放 OAuth token。日報對應 OWASP LLM01（Prompt Injection）、LLM02、LLM06。
Verdict：
- 🟢 與日報描述一致（事實層沒有錯）。
- 🔵 Misframed 風險（框架層）：本篇標題與主軸是「Command Injection 與不安全反序列化」。Manus 兩者都不是：沒有應用程式程式碼把輸入字串拼進 shell，也沒有反序列化物件還原；它是 LLM agent 被間接 prompt injection 誘導、自行呼叫解釋器執行了攻擊者可控內容，加上憑證與執行環境未隔離。文中「根源相近」把「不可信內容進入會執行的環境」當共同根源，抽象層級上成立，但這個抽象同樣能涵蓋 XSS、SSTI、SQL injection，並不特指本篇兩條路。對入門讀者，緊接在「對應路徑二」之後放 Manus，容易讀成「第三個同類範例」。文中已寫「不是這篇範例的 shell 拼接」，這是好的緩衝，但沒有說它也不是反序列化、而是 prompt injection 這一族。
- 建議（只報告，是否採納由作者決定），由輕到重：
  1. 保留但改框架：標題改為「對照：不屬於這兩條路，但同樣是 RCE」，並明說「這是 prompt injection 串到執行環境，下一階段／別篇再談」；把「根源相近」改成「共通點只有一個：不可信內容碰到了能執行程式的東西」。
  2. 移出「真實案例」，改放「限制與下一步」作為「還有別條路」的一句話附帶連結。
  3. 若篇幅要精簡，直接刪 Manus，只留 LangGraph；LangGraph 已足以支撐「RCE 常是幾個小問題串成」這個結論（該結論在 Manus 日報同樣成立：prompt injection + 編碼繞過 + 憑證同環境，但不需要 Manus 來支撐）。
  推薦 1 或 3。
- 附帶發現（日報本身，不在本篇範圍，供作者參考）：Manus 日報「影響範圍」段的「Meta 當時正籌劃併購 Manus，交易後來並未完成，兩家公司維持獨立營運」與同段英文 "negotiations" 夾雜，且此句未在日報參考資料中找到對應來源；如本篇要引用該日報，建議另行查證那一句。本次未查。

## 4. 沙盒重跑（python3 -I，Python 3.13.16，uid=0）
- 範例一（shell=True）：輸出 `Hello, Ann` / `Hello, Ann` / `uid=0(root) gid=0(root) groups=0(root)`，與文中逐字一致。🟢
- 範例二（參數陣列）：`Hello, Ann` / `Hello, Ann; id`，一致。🟢
- 範例三（pickle／json）：五行輸出與文中逐字一致，含 `UnicodeDecodeError` 與 `{'title': 'hello', 'pinned': False}`。🟢
- 英文版三段程式碼也各自重跑，輸出與英文版「Actual output」逐字一致（英文版的輸出字串是翻譯後的，且確實跑過）。🟢
- root 說明：我的沙盒 `id` 回 uid=0，同樣是 root；文中「沙盒剛好以 root 身分跑，所以印出 uid=0(root)；真實伺服器上是網站服務帳號，權限取決於部署」與 OWASP Example 6（`uid=33(www-data)`）一致。🟢
- 可重現性提醒：`UnicodeDecodeError` 這個例外型別取決於 pickle 位元組開頭（0x80）被 json 當成 UTF-8 解碼失敗，3.13 如此；3.14 之後 pickle 預設協定改為 5，開頭位元組同為 0x80，預期相同，但我只有 3.13 可驗，未驗 3.14+。「Python 3.13」的標注是準確的限定。
