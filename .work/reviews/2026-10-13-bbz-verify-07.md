### (6) `vmx`／`svm` 旗標名稱（文中標為未查證）

- 查得來源：Linux 核心原始碼 `arch/x86/include/asm/cpufeatures.h`（master，全文 fetch）。檔頭註解：引號中的字串即為 `/proc/cpuinfo` 顯示的旗標名。條目：
  - `X86_FEATURE_VMX ( 4*32+ 5) /* "vmx" Hardware virtualization */`，位於「Intel-defined CPU features, CPUID level 0x00000001 (ECX)」。
  - `X86_FEATURE_SVM ( 6*32+ 2) /* "svm" Secure Virtual Machine */`，位於「More extended AMD flags: CPUID level 0x80000001, ECX」。
  - 附帶：`ept`（Intel Extended Page Table）、`npt`（Nested Page Table support）也在清單。
- 佐證：Linux 核心文件 Nested VMX（docs.kernel.org/virt/kvm/x86/nested-vmx.html）寫「On Intel processors, KVM uses Intel's VMX (Virtual-Machine eXtensions)」，並說 qemu 預設 CPU 型號 qemu64 不列 VMX，需明確開啟（`-cpu host` 或 `+vmx`）。這與文中「guest 沒拿到硬體虛擬化功能，所以不能在裡面再跑硬體加速 VM」的推論方向一致，但那份文件講的是 KVM／QEMU，不是這個沙盒的實際組態。
- 結論：「`vmx`＝Intel、`svm`＝AMD 的硬體虛擬化旗標，會出現在 `/proc/cpuinfo`」→ 🟢 Confirmed（single-source：Linux 核心原始碼，另有核心文件旁證）。
- 未取得：Intel SDM 與 AMD APM 原文（PDF）沒有直接讀到。搜尋摘要看到二手引述 CPUID.1:ECX.VMX[bit 5] 與 Fn8000_0001 ECX[SVM]，但搜尋摘要不能作為依據，不採用。若作者想把限制段「沒有去查 Intel 或 AMD 的官方手冊」改寫，可寫成「`vmx`／`svm` 旗標名稱已對照 Linux 核心的 cpufeatures.h；Intel／AMD 手冊本身沒讀」。
