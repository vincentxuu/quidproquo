## 摘要

- 沒有任何一處把此案例暗示或放大成「已被完整利用的 RCE」。「公開分析沒有完整 RCE 攻擊鏈、公開 PoC 只展示當機」這個框架成立。
- 兩個需要作者注意的框架缺口（皆非事實錯誤）：
  1. Akamai 執行摘要的措辭比文章引用的更強，文章沒有交代（見 B-1）。
  2. MSRC 表格 L1 逃脫格在「沒有 functioning exploit」時仍有 $200,000 / $100,000 / $50,000 三列，文章只講 $250,000 要 exploit，會讓「差別在能示範到哪一步」顯得比表上更陡（見 B-2）。

## 🔵 Misframed / 需作者決定（數字對，但框架有缺口）

**B-1. Akamai 對 RCE 的措辭比文章呈現的強**（中文 L82、tldr L14；英文 L82、tldr L14）
- Akamai 漏洞文 Executive Summary 原文：「The vulnerability allows for both remote code execution and denial of service. Exploiting it allowed an attacker with an Azure virtual machine to take down whole regions of the cloud, as well as run arbitrary code on the Hyper-V host.」用過去式，語氣是「已能做到」。
- 同文正文：「This ability can be the basis for two exploitation scenarios. If the OidRequest member contains an invalid pointer, the Hyper-V host will simply crash. Another option is to make the host's kernel read from a memory-mapped device register. This, in turn, will trigger additional, device-specific side effects (namely, code execution).」以及「With a more complex exploitation chain, the vulnerability can grant the attacker RCE capabilities.」
- Akamai 全文沒有公開 RCE 的步驟、payload 或展示，也沒有展示當機畫面（當機畫面是 0vercl0k README 的）。
- 文章的處理：正確引用「兩種利用情境」「更複雜的利用鏈」，虛線標為研究者描述的可能，並寫「公開分析只展示了當機」。這個框架對公開可驗證內容是誠實的。缺口是：文章沒告訴讀者 Akamai 執行摘要用過去式斷言「能執行任意程式碼」，讀者若自己去讀原文，會看到比本文更強的說法，可能覺得本文低估。
- 另外 tldr 的「公開分析只展示了當機」精確說法是「公開的 PoC（0vercl0k）只展示當機；Akamai 文章宣稱兩種情境但沒有展示」。目前寫法把 PoC 與「分析」混在一起，略有簡化，不算錯。
- 判定：框架成立，建議（由作者決定）在「5b」一節加一句「Akamai 摘要寫作者能在 Azure VM 上對主機執行任意程式碼，但文中沒有公開展示步驟」，讓「研究者主張」與「公開展示」的落差對讀者更透明。

**B-2. 獎金表只講 $250,000 需要 working exploit，漏了同格其他列**（中文 L90、L95、L114；英文 L90、L95、L114；tldr）
- MSRC 頁（2026-10-13 讀取）L1 Guest Escape 實際四列：RCE + Functioning Exploit Yes + 報告品質 High = $250,000；Functioning Exploit No + High = $200,000；No + Medium = $100,000；No + Low = $50,000。
- 文章表格只列「有可運作的 exploit 且報告品質高 = 250,000」，並說「兩格相差十幾倍，差別在你能示範到哪一步」。若只看是否有 exploit，差距是 $250,000 對 $200,000（同格），不是對 $15,000。真正的分界是「漏洞能否被認定為 RCE 類型」，而不是 exploit 有沒有寫出來。
- 文章用詞「最接近 DoS 那格」已明確標為「我的判斷，不是來源的結論」，這部分誠實。問題在於省略了同格無 exploit 的列，使「250k vs 15k」的對比看起來比表上實際更單純。
- 建議（由作者決定）：在表格加一句「沒有 functioning exploit 時，同格仍有 $200,000 / $100,000 / $50,000 三列」，並把「差別在能示範到哪一步」改為更精確的說法。
- 附帶：該頁的「Publicly-disclosed vulnerabilities which have already been reported to Microsoft or are already known to the wider security community」屬於「通常不給獎金」項。文章已有「放到今天的表上看，不是當年拿了多少」的說明，足夠。

## 🟢 Confirmed

CVE 事實（NVD API、Akamai Wayback 全文、BleepingComputer 全文、兩份 GitHub README）：
- 發布日 2021-05-11：NVD `published: 2021-05-11T19:15:09.133`；australeo「Patch Date: May 11, 2021」。（高風險，NVD + australeo 兩源）

- 2021 年 5 月修補：Akamai「In May 2021, Microsoft assigned ... CVSS score of 9.9 and released a patch」；BleepingComputer「received a patch ... in May」。
- 2019 年 8 月首次出現：Akamai「first appeared in a vmswitch build from August 2019」（BleepingComputer 同）。
- 弱點分類：NVD `NVD-CWE-noinfo`（Primary, nvd@nist.gov）。文章「沒有給分類」正確。
- 影響產品（文章 L39）：Akamai 逐字「Windows 7, 8.1, and 10, and Windows Server 2008, 2012, 2016, and 2019」。NVD 列的是更細的版本（Windows 10 多個版本、Server 2008 R2、2012 R2、Server 2004/20H2 等），與 Akamai 概括一致。BleepingComputer 寫「Windows 10 and Windows Server 2012 through 2019」，範圍較窄，文章選用 Akamai 說法並標明出處，可。
- NVD 列各版本修補後建置號（`lessThan` 如 10.0.17763.1935）：文章「NVD 列出各受影響版本與對應的修補後建置版本號」正確。
- Akamai 發文日 2021-07-28：確認（Akamai、BleepingComputer 同日）。
- 位置 vmswitch.sys、虛擬機送特製封包、OID_SWITCH_NIC_REQUEST、除錯記錄程式「never validates the value of OidRequest」、「netvsc 不送此 OID 但設計缺陷使 vmswitch 仍接受」、Akamai 結語「hypervisor bug 加上 too-permissive communication channel」：全部確認（Akamai Wayback 全文）。
- hAFL1「開跑兩小時內找到」：hAFL1 文「Within two hours from the moment hAFL1 started running – it found a critical, CVSS 9.9 RCE vulnerability」。確認。

- BleepingComputer 引述 Harpaz：「I won't be surprised if this bug stays unpatched for a very long time in organizations」，文章轉述正確，且標明是研究者觀察、非統計。
