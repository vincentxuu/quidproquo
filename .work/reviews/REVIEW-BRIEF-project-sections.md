# CS50 AI 專案節改寫的複審任務書（2026-10-13）

各週導讀的專案節依 `.work/cs50ai-rewrite/PROJECT-SECTION-SPEC.md` 改寫：解題思路、虛擬碼、容易出錯的地方、怎麼檢查在前，完整參考實作摺疊在最後並加政策警語。先讀那份規格。只審不改檔，結果附加在該週審稿報告的「專案節複審（2026-10-13）」一節，記兩檔完整 sha256（審前審後各一次）。不要跑 pnpm dev／build，不要 commit。

逐項檢查（附行號與證據）
1. 規格符合：七個小節的順序與內容；摺疊區塊的 summary 與警語是否照規格、連到政策頁；摺疊區塊以外有沒有任何可以直接當作業繳交的實作（含片段、關鍵幾行）。逐一檢查摺疊外的每個 `def` 與每個程式碼區塊：是不是官方 distribution code 的逐字節錄或講課原始碼。
2. 虛擬碼的尺度：是不是把 Python 換個寫法的逐行翻譯。課程政策允許「用圖解或虛擬碼討論解法，但不用實際程式碼」；請判斷目前的細緻程度是否還在這條線內，太細的指出哪幾行、建議怎麼改粗。
3. 「容易出錯的地方」：每一條是不是真的會發生。作者說是實跑看到的現象；請挑至少三條自己重現（照作者留在工作目錄的腳本或自己改壞一份），數字與錯誤訊息要對得上。標成推論的要有標。
4. 「怎麼檢查自己寫的對不對」：每一項讀者是否真的能自己跑、預期結果是否正確（自己跑或手算）；有沒有哪一項等於洩漏解答。
5. 摺疊區塊裡的程式碼是否與上一輪審過的版本逐字相同；接官方檔重跑一次。
6. 解題思路裡的站內錨點與錄影時間連結：錨點是否對得上該檔的標題（用 github-slugger 規則），時間連結的文字與秒數是否與講課導讀裡同一處相同。
7. 講課導讀是否未被動到（作者說明有動的地方逐一看）。
8. 學習檢核清單、更新紀錄、參考資料的連帶修改；中英一致；替換表用語。
9. 指派訊息列的「需要人判斷」事項。

回覆：仍須修的清單全文（沒有就明說「無必須修」）、建議修每項一行、你沒做的事。
