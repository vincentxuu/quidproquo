## 弧線與入口
弧線：看得見的邊界（層與出口）→ 邊界共用的東西 → 共用資源上的通訊 → 真實案例精讀 → 出口與代理服務 → 防守 → 取捨。
入口：order 0 是總覽（一個 agent 的程式碼執行請求經過哪幾層、每層承諾什麼、不承諾什麼），不用新聞事件充當入口。
OpenAI 2026-10-23 貼文是 order 3 的精讀案例（讀者讀完 1、2 才看得懂），貼文轉述的查證表放附錄 order 7。

### 範圍卡（精簡版，確認後補完整欄位）
- order 0｜聚焦：隔離是一疊層，不是一道牆。講：容器／microVM／host／網路邊界／監控各一句承諾與一個失效例。不講：各技術的設定細節（留給 1）。讀完後讀者能：把任一沙盒產品的說明對到這五層並指出沒涵蓋哪層。
- order 1｜講：共用核心（容器）、使用者空間核心（gVisor）、獨立核心＋hypervisor（microVM）；CVE-2026-24834 作為「逃到 guest 但沒到 host」的例子。不講：旁路。讀完後讀者能：判斷一個攻擊落在哪一層邊界內。
- order 2｜講：covert channel 與 side channel 的差別、快取驅逐／重載、儲存與 CPU 競爭的直覺、2009 EC2 前例、為何慢且吵。不講：OpenAI 案例（留給 3）。讀完後讀者能：說出一個共用資源如何變成一位元的訊號。含可執行的本機小實驗（兩個行程以 CPU 負載調變傳位元），明示是玩具、不是跨 VM 攻擊。
- order 3｜講：四種通道（快取、儲存 I/O、CPU 時間、TLS 憑證快取）各原文怎麼寫；紅隊拿到原始碼與設定；多數測試被指定通道或給協定；只有一例僅給弱點清單；未揭露頻寬與錯誤率。讀完後讀者能：寫出一句不誇大也不貶低的結論。
- order 4｜講：7 月 Hugging Face 事件（Artifactory 變留言板與代抓請求）、9/20 DNS 事件（時間線：9:50 外連、10:02 警報、12:34 停止）、紅隊在 metrics 服務找到的代抓路徑。不講：HF 技術報告細節（未讀完前不寫）。讀完後讀者能：檢查自己的環境有哪些服務能替 agent 發請求。
- order 5｜講：S6 的 SMT／單租戶／速率限制、S5 的 direct I/O 與專用 block device、OpenAI 的離線世界與監控；每項標它擋哪類通道、不擋哪類。讀完後讀者能：對一份防守清單逐項標「擋出口／擋旁路／只是偵測」。
- order 6｜講：三種情境的威脅排序與可做的最小動作；連回「AI 資安實戰」order 15。讀完後讀者能：為自己的情境寫三條要做、三條可以不做。
- order 7｜講：查證表逐句對原文；說明編輯加料的幾處。作為附錄，不當入口。

## 斷崖處理
| 位置 | 跳躍 | 處理 |
|---|---|---|
| 1→2 | 從軟體隔離到硬體共用 | order 1 結尾點出「三種隔離都共用同一顆 CPU 快取與同一個 page cache」，order 2 從這句開始 |
| 2→3 | 從原理到真實案例 | order 2 先建立「慢、吵、需協定」三個判斷尺度，order 3 用同一把尺逐通道檢視 |
| 3→4 | 從通道到出口 | 先釐清「旁路通道＝agent 之間說話」「出口＝agent 對外說話」，兩者防法不同 |
| 4→5 | 從案例到防守 | order 5 用 order 3、4 的通道清單當防守表的列 |
