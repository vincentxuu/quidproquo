# 系列規劃：AI 通病（ai-common-failures）

使用者確認：2026-10-28

研究筆記：`.work/research/ai-common-failures/research-note.md`（母群、覆蓋矩陣、偏誤、通病卡、來源讀取狀態；來源 71 筆在同目錄 `sources.jsonl`）。本表「對應來源」只列讀過正文（✅）或明確標示只讀到摘要（🟡）的來源。

## 為什麼寫

本站 tldr 常被 agent 寫成空話：Cloudflare Agents SDK 入口文連退三輪，三版分別是指示型摘要、鉤子、否定式對比（2026-10-28）。站上沒有任何以 LLM 寫作句型、摘要寫法或 AI 腔為主題的文章或系列（研究筆記一節）。外部已有實證：否定式對比、意義抬高、過度概括都有語料統計或受控實驗，而且成因能追到偏好資料與獎勵模型。

## 目標讀者

- 用 LLM 寫文件、摘要、文章，或要審 AI 草稿的人：想知道哪些句子是空話、怎麼改。
- 替團隊或自己的網站建寫作 pipeline、prompt、檢查器的工程師：想知道哪些防護有用、哪些會反效果。

不需要懂模型訓練；成因篇用到的偏好資料、獎勵模型在篇內講直覺，細節連回訓練階段導讀。

不寫給：要做 AI 文字偵測器、判斷某篇是不是 AI 寫的人（本系列明講特徵不能拿來判個別文本）。

## 入口

order 0 是總覽：「AI 通病」指的是什麼（讀起來有資訊、其實沒給答案或給錯範圍的寫法）；四個通病各一句定義和一個例子；它們背後是同一個成因；為什麼只禁字面會換形；讀者依身分該從哪篇讀起。用本站 tldr 連退三輪當開場案例，但入口講的是全系列地圖，不是那篇事件。

## 弧線

```
order 0 總覽
  → 句子層：否定式對比（1）→ 意義抬高（2）
    → 摘要層：指示型摘要（3）→ 過度概括（4）
      → 為什麼：偏好資料放大（5）
        → 怎麼防：規則與檢查器（6）→ 禁令與換形（7）
          → 護欄：別矯枉過正（8）
            → 延伸：寫作以外的同一個病，agent 宣稱完成（9）
```

排序原則：

- 可見先於不可見：先看讀者每天會碰到的句子（1、2），再看整段摘要（3、4），最後才講訓練端成因（5）。
- 動機先於方法：四篇通病都讓讀者先認得、再修；防護（6、7）等讀者認得通病後才講。
- 證據最強的放第一篇：否定式對比中英文都有語料統計、成因實驗與反證。
- 螺旋式加深：每篇通病用一段帶到成因與反證，5 與 8 再統整，不每篇重講。
- 作者主張與實證分開寫：Wikipedia、Pangram、工具作者的紀錄標成觀察或廠商數字；只有受控實驗與語料研究寫成「研究發現」。
- 不寫成「LLM 都這樣」：Peters 的過度概括 Claude 各版本沒有顯著差異；Zamaraeva 的模型間差異也大。

## 每篇範圍卡

```
Order 0：AI 通病｜讀起來有資訊、其實沒給答案的寫法
  聚焦問題：哪些寫法讀起來像有資訊、其實沒有？我該先讀哪篇？
  邊界：
    - 講：四個通病各一句定義＋一個例子；同一個成因一句話；為什麼不能只禁字面；依讀者身分的閱讀路線
    - 不講：各通病的證據細節、訓練機制（留 1–8）
  讀完後讀者能：在自己的草稿裡指出四種通病各一句，並知道該讀哪篇修
  例子／推導：本站 Cloudflare 入口文 tldr 三版對照四個通病
  自我檢查與答案／判準：給 4 句 tldr，讀者分類；答案附在折疊區
  前置：無
  連結：成因 → order 5；訓練階段 → ai/2026-08-26-understanding-ai-models-training-stages

Order 1：否定式對比｜「不是 X，是 Y」什麼時候是空話
  聚焦問題：為什麼 AI 老是先否定一個沒人說過的說法？什麼時候該留？
  邊界：
    - 講：三型（替換、否定、加強）；中英文頻率證據；煩人用例的特徵（稻草人 X）；判準「X 有沒有人真的主張」；三連排比併一節（Economist 例句是否定＋三連）
    - 不講：成因實驗細節（只一段，留 5）；禁令換形細節（只一句，留 7）
  讀完後讀者能：用「X 有沒有人主張」判斷一句對比該刪 X 直接寫 Y，還是保留
  例子／推導：本站「四個起點不是四種功能，是四種 loop 歸屬的安排」→改寫；Kusama 條目
  自我檢查與答案／判準：5 句含對比的句子，判斷留或改並改寫；判準與參考改寫附答案
  前置：order 0
  連結：Pangram 三倍被中文轉錯成「不是A而是B」→ 本篇事實更正段

Order 2：意義抬高｜把普通事實包裝成重大意義
  聚焦問題：為什麼普通事實會被包裝成重大意義？怎麼改回具體？
  邊界：
    - 講：抬高這個動作（句尾分詞評論、「扮演關鍵角色」）；AI 詞彙只當例子並說明會退燒；模糊歸因、公式化結尾各一段
    - 不講：完整詞表（會過期）；中文語料統計（沒有，明講）
  讀完後讀者能：把一句抬高句改成具體事實或刪掉
  例子／推導：Wikipedia 收錄的條目修訂；本站 tldr 的「真正／關鍵在」命中
  自我檢查與答案／判準：一段含抬高的段落，標出並改寫；參考答案
  前置：order 0
  連結：Reinhart 的指令微調 vs base → order 5

Order 3：指示型摘要｜tldr 只預告、不給答案
  聚焦問題：為什麼 tldr 寫了「這篇談什麼」卻沒說結論？怎麼寫出答案？
  邊界：
    - 講：indicative vs informative；NISO §7.4；BLUF；鉤子與自指併入（答案被延後、被替換）；什麼時候指示型才是對的（篩選用途）；檢法「遮掉正文只看 tldr」
    - 不講：過度概括（給錯範圍，留 4）
  讀完後讀者能：把一則指示型 tldr 改寫成資訊型，並用 Q&A 檢法驗證
  例子／推導：Cloudflare 入口文 tldr 三版與最後改寫；本站自指命中抽樣
  自我檢查與答案／判準：3 則 tldr 改寫；判準「讀者能不能照著做決定」
  前置：order 0
  連結：本站規則 → order 6；「LLM 特別愛寫指示型」沒有直接研究，明講

Order 4：過度概括｜摘要把限定條件丟掉
  聚焦問題：為什麼摘要會把「在某條件下有關聯」寫成「X 會造成 Y」？
  邊界：
    - 講：Peters & Chin-Yee 的設計與結果；量化陳述→泛稱、過去式→現在式、描述→建議三種轉換；模型間差異（Claude 例外）；溫度與 prompt 的影響
    - 不講：「要求準確反而更糟」的禁令機制（一段，細節留 7）
  讀完後讀者能：拿原文對摘要，逐句檢查對象、條件、時態有沒有保留
  例子／推導：論文 Table 3 原句對照
  自我檢查與答案／判準：一段原文＋LLM 摘要，找出被放大的句子；答案
  前置：order 3（區分「沒給結論」與「給錯範圍」）
  連結：本站 post skill anti-shortcuts「濃縮最容易放大強度」

Order 5：成因｜偏好資料把這些寫法放大
  聚焦問題：這些寫法是誰教給模型的？
  邊界：
    - 講：三層證據（偏好資料直接實驗→微調後變窄→同機制的諂媚）；Tülu 3 反例；結論寫成「被偏好的形式會被放大，各家差很多」
    - 不講：RLHF 演算法細節（連回導讀）
  讀完後讀者能：解釋為什麼換模型或換 prompt 只能減輕、不能根除
  例子／推導：獎勵模型最小對照（同長度非對比子句仍輸）
  自我檢查與答案／判準：「RLHF 造成 AI 腔」這句哪裡講過頭？答案
  前置：order 1–4 至少讀一篇；直覺段先講偏好資料是什麼
  連結：ai/2026-08-26-understanding-ai-models-training-stages、ai/2026-09-30-cs224r-rlhf-dpo-preference-optimization、ai/2026-09-29-cme295-preference-tuning

Order 6：怎麼防（一）｜規則、檢查器與審稿
  聚焦問題：寫規則、加 linter、找 LLM 審稿，各擋得住多少？
  邊界：
    - 講：規則要進到產出點（本站 post-polish 早有規則，tldr 仍大量命中）；linter 精確率（vale-ai-tells 實測、本站 regex 標注）；LLM 審稿與人類一致性低；改寫才是瓶頸；Wikipedia「特徵只當線索」
    - 不講：prompt 禁令（留 7）；pipeline 層級設計（連回前作）
  讀完後讀者能：替自己的寫作流程選一個檢查點，並說出它的誤報率怎麼量
  例子／推導：本站 writing-guide 規則＋check-post-quality 警告，與人工標注的精確率
  自我檢查與答案／判準：給一份命中清單，判斷哪些是誤報
  前置：order 1–3
  連結：ai/2026-05-10-llm-writing-pipeline-learnings、learning/2026-10-14-site-case-agents、tech/2026-08-21-zh-tw-terminology-linters-tested

Order 7：怎麼防（二）｜prompt 禁令有用嗎
  聚焦問題：在 prompt 裡寫「不要用 X」會發生什麼？
  邊界：
    - 講：禁令有效但不穩（取決於模型與目標詞基準機率）；accuracy 型禁令反效果；字詞層替代有實證、句式層只有跡象；解碼期與訓練期的做法（Antislop）
    - 不講：「禁令一定會換形」（證據不支持，明講）
  讀完後讀者能：把一條「不要 X」改寫成「改寫成 Y，因為 Z」的指示，並知道要量什麼
  例子／推導：本站 tldr 三輪改寫（禁一型、換一型）當觀察，不當實驗
  自我檢查與答案／判準：3 條禁令改寫；判準
  前置：order 6
  連結：order 4（Peters accuracy prompt）

Order 8：護欄｜別矯枉過正
  聚焦問題：看到這些句型就判定是 AI、全部刪掉，會錯在哪？
  邊界：
    - 講：人類也這樣寫（修辭傳統、人類基準不是零）；非專家判斷偽陽性約五成；偵測器誤判；人類趨同；過度矯正的案例
    - 不講：偵測器怎麼做
  讀完後讀者能：在審稿時把「這句像 AI」換成「這句缺什麼資訊」來判斷
  例子／推導：《荷塘月色》AI 疑似度；em dash 已退燒
  自我檢查與答案／判準：5 句人類名句，哪些會被規則誤擋；答案
  前置：order 1–7
  連結：order 6 的精確率

Order 9：延伸｜agent 宣稱完成
  聚焦問題：agent 說「已完成」為什麼不能信？
  邊界：
    - 講：false success 的定義與比例；LLM 評審被自信收尾語言騙；和寫作通病同構（空話被當成資訊）；驗證要看產物不看自述
    - 不講：agent 評測方法全貌
  讀完後讀者能：替自己的 agent 流程加一個「讀回產物再判定完成」的檢查點
  例子／推導：tau2-bench 軌跡的收尾語句 vs 實際狀態
  自我檢查與答案／判準：3 段 agent 收尾，判斷哪些沒有證據
  前置：order 0、6
  連結：諂媚 → ai/2026-09-30-cs2881r-lecture-11-emotional-reliance
```

## 斷崖處理

| 位置 | 問題 | 處理 |
|---|---|---|
| order 4→5 | 從讀者看得到的句子跳到訓練資料與獎勵模型 | order 5 開頭先用一段直覺講「偏好資料是兩個回答選一個」，演算法細節連回導讀 |
| order 3→4 | 兩篇都在講摘要，容易混 | order 4 開頭一句區分：3 是沒給結論，4 是給了錯的範圍 |
| order 6→7 | 6 有本站實測、7 多是外部研究且句式層證據薄 | 7 明講證據分層（字詞層實證／句式層跡象），不硬接 |

## 研究足夠的判準

五關結果見研究筆記七節。摘要：

- 已過：否定式對比、指示型摘要、成因、反證四段五關全過。
- 部分過，動筆該篇前補：
  - order 1：Zamaraeva 2026 只讀約六成，補讀 §1–4 與附錄 H。
  - order 2：中文意義抬高沒有語料統計（⚪，已試 Exa ×3、Tavily ×1、Jina arXiv ×3），改用本站 tldr 標注資料並明講。
  - order 4：沒找到 Peters 的獨立重複驗證，補搜 replication／follow-up。
  - order 7：句式層「禁令導致換形」沒有受控實驗（⚪），寫成跡象不寫成發現。
  - 候選 9：Advani 2026 只讀摘要與引言片段，納入前讀正文。
- 本站原創資料：tldr 命中數的分母要固定定義（研究筆記重算為 2,377 篇中文非 daily），regex 精確率要先人工標注一批樣本，order 3、6 才能引用。
