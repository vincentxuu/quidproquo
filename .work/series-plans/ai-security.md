## 使用者方向與範圍
使用者選兩線並新增AI攻擊線；明確質疑本機限制，故實作環境納入CTF、公開訓練平台、自架雲端、經授權真實系統與Bug Bounty允許範圍。本機只是入門選項，不是整個系列的上限。
範圍包括AI作為攻擊目標與AI輔助攻擊／資安工作的流程、實作與限制；真實公開攻擊鏈會作一手來源案例分析。研究本身不對第三方執行測試。
延伸候選：深偽／釣魚社交工程、惡意程式分析、模型訓練污染／權重攻擊、硬體／TEE、AI alignment，先不塞進核心篇目。

## 弧線與入口
弧線：共用資料流／授權／證據／環境 → 攻擊假設與驗證 → 分層防護 → 調查修補 → 整合演練。
入口：order 0 是全景總覽，以一筆工單請求介紹三線與閱讀選擇，不用新聞事件充當入口。
分流閱讀：共用0–3後，攻擊線4–9；防護線10–16；調查修補線17–22；最後23會合。可從任一線開始，依範圍卡補讀前置。

## 斷崖處理
| 位置 | 跳躍 | 處理 |
|---|---|---|
| 0→1 | 從三線全貌到授權 | 一筆登入後換工單ID的允許／拒絕對照，先不教完整OAuth |
| 2→3→4 | 從證據概念到攻擊操作 | 先完成scope、環境、成功條件；每個工具動作回到原始輸出 |
| 6→7 | 從一般漏洞到AI注入 | 重用同一資料流，指出低信任資料何時影響動作 |
| 10→12→13 | 從內容防護到身份與MCP | 先教單次動作授權，再拆協定與工具來源 |
| 15→16 | 從設定到效果判定 | 每項設定配允許與拒絕測試，補judge誤判反例 |
| 18→19 | 從程式修補到事件調查 | 用同一輪攻擊的trace教事件ID、時區與缺漏，不突然引完整SOC術語 |
| 各線→23 | 各自結果無法整合 | 統一case ID、版本、finding ID、trace與回歸結果格式 |

## 共用練習產物
貫穿例子為雙租戶客服工單助理，可在本機或自架雲端操作。另選CTF／公開訓練平台與授權目標作遷移練習，先核對平台規則，不宣稱不同環境的結果可直接比較。
資料包含合成文件ACL、工單、事件紀錄、工具呼叫、攻擊案例、預期finding及修補回歸。第三方平台不允許植入內容或匯出資料時，以其既有任務與原始紀錄驗收。
每篇至少一個可操作產物；涉及實測的結果必須真正跑過才寫進文章。
