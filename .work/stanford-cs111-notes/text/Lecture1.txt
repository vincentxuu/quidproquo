Phase 1: Hardware Expensive, Humans Cheap
●   Goal: maximize machine utilization
     ○ Get user out of the loop

●   Simple batch monitor:
     ○   User submits deck of punched cards describing a series of operations (job)
     ○   Output is given back as a print out
          ■ Program output
          ■ Print out of memory contents on errors (core dump)

●   OS = program to load and run user programs and take memory dumps after
    crashes
     ○   Makes better use of hardware, but more difficult to debug.

1960s Improving Efficiency (machine utilization)
●   Overlap of input/output (I/O) and computation
     ○   Hardware: data channel & interrupts

●   Buffering and interrupt handling in OS
     ○   OS: Handling many things happening at the same time

Simple Batch Monitor Issues
●   Still one job at a time → utilization often bad
     ○   Couldn't run something else while job was waiting for I/O

●   No protection
     ○   Misbehaving job could damage batch monitor

●   Short jobs wait for long ones
     ○   Ideally we could reorder jobs

What OSes Do Today
●   Managing shared resources efficiently

●   CPU: Concurrency: allow several tasks to share processors

●   Memory: share memory among processes

●   I/O devices: manage operations efficiently

●   Files: share storage across users

●   Networks: allow computers to work together

●   Security: protect participants from each other
                               CS111 Lecture Notes - Introduction
The OS Kernel
Code that implements these functions is called the kernel

Kernel code occupies reserved area of memory

Has control over the entire system

User application code is restricted
