                           Naming aside: Lock
●   The word lock is both a noun and a verb
     ○ Bike lock, Combo lock, Pad lock, Deadbolt lock.
     ○ Lock the door. Lock the bike. Lock the car.
●   Lock the lock?
●   C++ language designers disliked lock.lock(); …; lock.unlock()
     ○ Want something to create critical sections
         ■ Need a mutual exclusion mechanism (mutex)




                            CS111 Lecture Notes - Locks and Condition Variables
                Locks (C++ class std::mutex)
●   lock()
    ○   Block until the lock is free

    ○   Mark the lock as held by the calling thread

●   unlock()
    ○   Mark the lock as free

    ○   Unblock a waiting thread

●   try_lock() - Like lock() except return error rather than blocking if lock held

CS111 Lecture Notes - Locks and Condition Variables
Need a way of waiting/blocking inside of a critical section
●   Condition Variable
     ○   Atomically release lock and go to sleep waiting for a condition to change

●   Useful mental model: Special kind of list a thread can go to sleep on




                               CS111 Lecture Notes - Locks and Condition Variables
Condition Variables in C++
●   std::condition_variable
     ○   wait(lock):
          ■   Release lock and puts threads to sleep (block)
          ■   Re-acquire lock went awoken

     ○   notify_one():
          ■   Wake up one thread if there is one sleeping

     ○   notify_all():
          ■   Wake up all the threads that are sleeping


Note: Notified thread might not re-acquire lock right away

Condition might not be valid when awoken thread executes again

How many locks should you use?
How many locks should you use?

●   More locks
     ○   May permit more concurrency (less lock contention)

●   Less locks:
     ○   More locks lead to complexity, potential for problems like races & deadlock (Monday's lecture)
     ○   Lock acquisition is relatively expensive
          ■ Fewer locks may result in less overhead

●   Terminology: course-grained locking vs fine-grained locking

●   Examples: Linux and Python

                               CS111 Lecture Notes - Locks and Condition Variables
Best approach
●   Few locks as possible, while providing an acceptable level of lock contention
●   Good general approach:
     ○   Associate a lock with a collection of related variables
     ○   Example: monitors

Monitor style locking
●   Monitors contain:
     ○   A shared data structure
     ○   A collection of methods
     ○   A lock

●   Lock must be held whenever accessing the shared data
     ○   Typically each procedure acquires the lock at beginning and releases before returning

●   One or more condition variables used for waiting

●   Language support: Example: Java synchronized keyword
