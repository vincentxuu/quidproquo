# 產品評估：「幫別人快速做出 AI 部落格」

評估日期：2026-07-27　｜　狀態：建議先驗證，不要先建

結論先講：**這個題目裡有兩個產品，你直覺講的那個（快）是沒有防禦性的那個。** 有防禦性的是另一個（對）。而且你已經規劃好的文章系列，正好是驗證它最便宜的工具——不用先建任何東西。

---

## 1. 「快速做出 AI 部落格」這句話裡的矛盾

上一份規劃（`docs/ai-beginner-research-blog-series-plan.md`）已經定位出四個市場缺口：雙軌兼容、研究層、把關層、長期治理。**這四個沒有一個是「快」。** 它們全部是「慢而對」。

如果產品的承諾是「快速做出 AI 部落格」：

- 它吸引到的是想要**量**的顧客。
- 想要量的顧客會踩到 Google 的 scaled content abuse——官方明寫適用於任何產製方式，[「no matter how it's created」](https://developers.google.com/search/docs/essentials/spam-policies)。
- 顧客被降權 → churn。**產品的成功條件與顧客的成功條件是分岔的。**

這不只是道德問題，是留存問題。一個交付「快」的產品，會系統性地招到最快流失的那群人。

---

## 2. 市場現況：兩端都已經飽和，中間是空的

### 上游（做出網站）——完全商品化

Wix、Squarespace、GoDaddy Airo、Framer、Durable、Lovable、10web、Dorik、Duda、Elementor Angie⋯⋯「我要一個部落格，快」這個需求已經被十幾家吃滿，而且多數有免費層。Elementor 的 Angie 甚至已經是 agentic——會規劃並執行整站任務，不只生成單段文字。

**你在這一層的勝算是零。** 而且這一層的顧客（A 觀望者）付最少、要最多客服。

### 下游（大量產文）——飽和且正在被 Google 修理

Frase、Surfer、Copy.ai Workflows、Jasper、Writesonic、Sai by Simular。Sai 甚至已經做到「丟一篇 15 頁研究論文，產出部落格文 + 社群貼文 + 圖 + email + podcast 腳本」的全流程。

這一層不缺工具，缺的是**願意承擔品質責任的人**。

### 中間（研究紀律 + 品質閘門 + 跨工具可攜）——空的

沒有人賣「怎麼確保你發出去的東西是對的」。原因很簡單：**這東西不能自動化到底**，所以做不成漂亮的 SaaS demo。但這正是它有防禦性的理由。

### 已經有人在賣 skill pack（規模不大但真實）

- 有人開了 CLI marketplace 專門賣 SKILL.md 套件，一行指令安裝。
- 個人賣家自陳：$99 一份、約 50 天賣了 $5,000，另有一筆 $1,000 顧問升級單；另一位號稱 $10K。

⚠️ 這些是賣家自己的行銷內容，沒有第三方查證，**當成「這個形式存在且有人付錢」的訊號就好，不要當成市場規模估計**。

重點是：**目前這些 skill pack 幾乎清一色只做 Claude Code**。而 Agent Skills 已經是開放標準，同一份 SKILL.md 在 Codex、Cursor、Gemini CLI、Copilot 上都能跑。這是個沒人吃的分發優勢，而且**你為了寫文章系列本來就要做這件事**。

---

## 3. 兩個產品，選一個

| | **P1「快」** | **P2「對」** |
|---|---|---|
| 賣什麼 | 部落格模板 / starter repo，一鍵起站 | 研究→寫作→查核的產線 + 品質閘門 |
| 賣給誰 | A 觀望者（沒站的人） | B 手動派 / C 工具人 / D 營運者（有站但產出很空） |
| 對手 | Wix、Framer、Lovable、一堆免費模板 | 幾乎沒有正面對手 |
| 防禦性 | 無。一週就能被抄 | 高。抄得走檔案，抄不走判準與踩過的坑 |
| 客服負擔 | 高（不會用終端機的人最會卡） | 低（顧客已經有技術基礎） |
| 願付價格 | 低（<$50，甚至期待免費） | 中高（一次性 $99–299 合理） |
| 你的既有籌碼 | 幾乎用不上 | 全部用得上 |

**你的籌碼盤點**：671 篇真實文章、7 個內容 skill、一道 `pnpm verify` 閘門、`.agents/skills` ↔ `.claude/skills` 雙軌同步、治理章程、事實查核流程。**這些全部是 P2 的資產，對 P1 一點幫助都沒有**——P1 需要的是漂亮模板和客服，那不是你有的東西。

### 你自己的研究直接反對 P1

你在 [`product/2026-07-25-digital-product-value-validation`](/posts/product/2026-07-25-digital-product-value-validation) 裡整理過：**AI 產品在 <$50/mo 級距的 GRR 只有 23%，>$250/mo 是 70%**。

P1 註定落在低價級距（因為對手免費），也就是註定落在 23% 那一格。P2 才有機會定到留得住的價位。

## 4. 建議：做 P2，但先不要建

你已經規劃好的 11 篇系列，本身就是**最便宜的驗證工具**。理由用你自己整理的框架：

- Testing Business Ideas 的排序：**意見 < 意向 < 行為**。訪談和問卷給你的是意見；文章底下有人問「這個可以直接買嗎」是行為。
- The Mom Test：**讚美是社交潤滑劑，承諾才是證據**。承諾的貨幣依重量是時間 < 名譽 < 金錢。
- 你自己寫的：**一場結束於「保持聯絡」的訪談是弱負向結果。**

所以路徑是：

### 第一階段：先發 5→6→7（B 動線那三篇）

**不是**從第 1 篇開始。理由：

- 第 1–4 篇服務 A（觀望者），而 A 是 P1 的顧客——你不打算做 P1。
- 第 5–7 篇服務 B，B 是 P2 的顧客。第 7 篇（發文前三道關卡）是全系列最有立場、最可能被引用的一篇。
- 這三篇本來就設計成「不預設讀者跑過建置三篇」，可以獨立發。

**要觀察的訊號**（依重量排序）：

| 訊號 | 代表什麼 | 貨幣 |
|---|---|---|
| 「這套流程可以直接給我嗎」 | 想要成品不想自己組 | 時間 |
| 有人公開說自己照做了 | 方法可複製 | 名譽 |
| 有人問「多少錢」 | 真需求 | 金錢 |
| 只有「寫得真好」 | **弱負向**——沒花任何貨幣 | 無 |

門檻要**在發文前訂死**，否則會退化成確認偏誤製造機。建議：三篇發完後 6 週內，若沒有出現 3 筆以上「金錢貨幣」訊號，P2 也不做，就純粹把系列寫完當內容資產。

### 第二階段（若訊號成立）：skill pack，不是 SaaS

形式建議：

- **一次性付費的 skill pack**，$99–199。內含 `deep-research` / `post` / `post-review` / `post-verify` / `tag-audit` 五個 skill、一份 AGENTS.md 範本、一份檢查腳本。
- **賣點是跨工具**：Claude Code、Codex、Cursor、Gemini CLI 都能裝。這是目前市面上 skill pack 幾乎沒人做的事，而你為了寫第 8、9 篇本來就得做。
- **不要做 SaaS**。訂閱制要你扛 runtime、扛顧客的 API 成本、扛支援，而你的東西本質是檔案。檔案賣一次就好。
- **升級路徑走高價服務**：$1,000+ 的「幫你把現有部落格接上這套產線」一對一設定。你的研究裡那位賣家的 $1,000 顧問單就是這個形狀。高價、低量、高毛利，適合一人。

### 明確不要做的

- ❌ **託管服務 / SaaS**——扛不動，而且跟「檔案是你的」這個核心主張矛盾。
- ❌ **賣給 A（沒站的人）**——客服會吃掉你所有時間，且他們付最少。
- ❌ **「一鍵生成部落格」**——正面對上 Wix/Framer，且招到會 churn 的顧客。
- ❌ **先建再驗**——你已經有一個幾乎零成本的驗證管道（文章），沒理由跳過。

## 5. 這條路的真實風險

| 風險 | 說明 | 怎麼看待 |
|---|---|---|
| **市場太小** | 「已經在用 agent 寫部落格、且在意品質」的人，交集可能只有幾千人 | 這是最大的風險。但一人產品不需要大市場——$99 × 300 人就成立 |
| **可被官方吃掉** | Anthropic / OpenAI 隨時可能內建類似的內容工作流 | 真實。護城河不在 skill 本身，在判準與踩過的坑，那部分要靠內容持續累積 |
| **skill 生態快速變動** | 標準與路徑半年就變 | 反而是賣點——你維護，顧客不用追。但這是持續成本 |
| **內容變產品後品質降級** | 為了賣東西而把文章寫成業配 | 系列必須先寫完、寫好，產品是副產品。順序反了兩邊都毀 |
| **時間排擠** | 做產品會排擠寫作 | 這是最該誠實面對的——你的 671 篇是主資產 |

---

## 6. 建議的下一步（照順序）

1. **不改變原計畫**——文章系列照寫，但**發文順序改成 B 動線優先**：5 → 6 → 7，再回頭補 1–4。
2. **在第 7 篇底部放一個明確的行動呼籲**（不是 fake door，是真的收信箱）：「想要這整套 skill 的，留個信箱」。這是最低成本的意向訊號蒐集。
3. **第 8、9 篇照寫**——跨工具 skill pack 的內容，本來就是產品的雛形。寫完文章你就有了 80% 的產品。
4. **6 週後回來看訊號**，再決定要不要包裝成產品。

這條路的好處是：**不管產品成不成立，文章系列都不會白寫。** 產品失敗的下檔風險趨近於零。

---

## 7. 待你拍板

1. **發文順序改成 B 動線優先（5→6→7）**，還是維持 1→11 的線性順序？（這是唯一會改變既有規劃的決定）
2. **收信箱要不要做**——若要，需要一個 landing page 或表單，這是小工程。
3. **驗證門檻訂在哪**——我建議「6 週內 3 筆金錢貨幣訊號」，但這個數字該由你訂，且必須在發文前訂死。
