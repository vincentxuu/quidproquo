## 一、選題原則

### 不對稱優勢在哪

1. **Autonomy stack 可以用 RAG 系列同一套方法論拆。** 站上已有 36 篇 RAG 文章在做「把系統拆成可獨立驗證的元件」，無人機的感知 → 定位 → 規劃 → 控制結構同構。寫這題的人多半是航太背景而非軟體背景，工程取捨講不清楚。
2. **核心軟體全開源，筆電就能跑。** PX4、ArduPilot、ROS 2、MAVLink、ExpressLRS 都能在 SITL / Gazebo 驗證，可產出第一手素材。
3. **台灣視角 + 既有的四條件框架**（見 `tw-stock-screen` skill）。地圖文已把缺口定位在產業鏈第 3 層，可往下鑽。

### 不要寫

| 題材 | 為什麼不寫 |
|---|---|
| 軍事戰術評論 | 沒有一手來源，會退化成軍事頻道的二手轉述 |
| 市場規模預測 | 各家報告不可比（地圖文已論證），預測本身沒有增值 |
| 廠商併購八卦 | 需持續追蹤，一篇就過期 |
| 器材推薦清單 | 沒飛過的人寫推薦，讀者看得出來；且該關鍵字全是聯盟行銷內容 |
| 各國國家隊逐一介紹 | 資訊密度高但沒有觀點，容易寫成維基百科 |

## 二、規劃用的五個軸

### 軸一：讀者意圖（決定同一事實怎麼寫）

| 意圖 | 讀者心裡的問題 | 對應形態 |
|---|---|---|
| 認識 | 這是什麼？ | 地圖、名詞解釋、產業結構 |
| 判斷 | 該不該在意？是不是泡沫？ | 對照、反方觀點、週期史 |
| 定位 | 這裡有沒有我的位置？ | 職業地圖、能力對照 |
| 參與 | 我要怎麼進來？ | 路徑指南、創業、投資、接單 |
| 動手 | 我要開始做 | guide、實作、器材決策 |
| 精進 | 我已經在裡面了 | 技術深潛、踩坑、工具比較 |

**這一軸最容易被忽略。** 同一份供應鏈知識，寫給「判斷」的人是「哪一層有護城河」，寫給「參與」的人是「我該投哪家履歷」，寫給「動手」的人是「這顆模組買得到嗎」。

### 軸二：主題領域

完整清單見第三節。

### 軸三：地域

不是獨立軸，是每篇內部的處理方式。三種類型：

| 類型 | 例子 | 處理 |
|---|---|---|
| 只有國外有 | Part 108、FCC Covered List、EASA 三級制 | 台灣讀者要知道，但沒有平行制度可比 |
| 只有台灣有 | 無人機國家隊、亞創中心、442 億計畫、民航法專章 | **內容護城河**，中文圈寫得清楚的極少 |
| 兩邊都有但差很大 | 職業市場、玩家門檻、產業鏈位置 | 對照本身就是價值 |

**不做「國外篇／台灣篇」分冊**——那會讓每個主題被切成兩半、兩邊都不完整。改成每篇內建台灣段落，整個系列挑 2–3 篇做完整國際對照。

### 軸四：文章形態

`deep-dive` / `guide` / `debug` / `project` / 對照比較 / 時事解讀。

站上 `tech` 幾乎全是 `debug` 和 `deep-dive`，缺 `guide` 和 `project`。無人機這題**最有機會產出 `project` 類**（自己組一台、自己跑一次任務），是整個系列唯一沒人能複製的內容。

### 軸五：深度

`difficulty` 欄位（入門 / 進階 / 深度）目前站上少用，這個系列建議用起來——因為同一主題會有給玩家和給從業者的兩個版本。

## 四、已定案的三個寫法決策

### 決策一：作者沒飛過、沒考照 → 玩家線改寫法

**不寫**「無人機入門推薦」。
**要寫**「一個研究過產業、但沒摸過實機的人，從零開始的紀錄」。

這個角度只有本站能寫——已有一篇產業地圖，知道供應鏈每一層長什麼樣，卻連飛都沒飛過。**這個落差本身就是題目**：紙上的產業理解，跟真的把東西飛起來，差距在哪。

拆成兩種，寫作條件不同：

| 類型 | 能不能現在寫 | 一手來源 |
|---|---|---|
| 制度解析（民航法、操作證制度、註冊流程） | ✅ 可以 | 法規條文、民航局公告 |
| 實作紀錄（買什麼、第一次飛、考照） | ❌ 要真的去做 | 自己的紀錄 |

制度解析類要在文中**標清楚哪些是查來的、哪些是做過的**。

**⚠️ 2026-08-07 修正：上表把「實作紀錄」當成唯一出口，是錯的。**

決策一真正的約束是「不要假裝有經驗」。買機器只是滿足它的其中一種方式，卻被寫成前置條件。同樣的落差（懂供應鏈但沒飛過）還有另外三個出口，而且都是**純公開資料**：

| 原題 | 需要買／飛？ | 改寫後的視角 | 素材 |
|---|---|---|---|
| D1 我怎麼決定買哪一台 | ❌ 不需要 | 讀規格表的方法——看過五層供應鏈的人，在規格表上看的是「這格是誰做的」而非「參數多大」 | 公開規格表 × A1 的層級框架 |
| D2 第一次飛、第一次炸 | ❌ 不需要 | 炸機的解剖學——不是我的炸機，是**別人的**：運安會調查報告 + PX4 Flight Review 公開 log | 見下方素材確認 |
| D3 考照全紀錄 | ❌ 不需要 | 題庫結構分析——民航局把題庫全文公開，題目分佈就是主管機關在意什麼的直接證據 | 見下方素材確認 |

三篇的 `type` 因此從 `project` 改為 `deep-dive`，並且**不再叫「從零開始」**——那個名字預設了會去做。新定位是「沒飛過的人，靠公開資料能懂到什麼程度」，落差本身仍然是題目，只是誠實地標在裡面。

**素材確認（2026-08-07 查證）：**

- **題庫是全文公開的**。民航局[遙控無人機學科測驗題庫](https://www.caa.gov.tw/Article.aspx?a=3833&lang=1)提供 docx／odt／pdf 三種格式，共五份：普通操作證【115.2.2 更新】、專業操作證【114.5.28 更新】、屆期換證（一般／簡易）、以及英文版 *Drone Remote Pilot License Written Test (Examples)*【113】。**頁面連下載次數都公開**——專業題庫 pdf 29,318 次 vs 普通題庫 pdf 10,939 次，考專業證的人準備得比考普通證的人積極得多，這個比例本身是可寫的觀察。
- **運安會有無人機事故調查報告與統計**。2019-04-24 修正的《運輸事故調查法》把遙控無人機納入調查範圍，2020-03-04 發布《遙控無人機重大飛航事故調查作業處理規則》規範通報義務。[台灣飛安統計報告 2015-2024](https://www.ttsb.gov.tw/media/9223/台灣飛安統計報告2015-2024.pdf)：納入調查迄 2024 年底共 **4 起重大飛航事故，3 架全毀、1 架失蹤，無人員傷亡**。門檻定義（行政院公報，2019-08-01 生效）是「造成人員死亡或傷害／**最大起飛重量逾 25 公斤**遭受實質損害／其他經運安會認定」——**所以 25 公斤以下的炸機根本不進統計，4 起這個數字要這樣讀**。已知個案：110-03-09 海巡署北部分署 AXH-E230RS 於淡水河口作業時墜海全損。另民航局設有非懲罰性的[遙控無人機安全自願報告](https://www.caa.gov.tw/article.aspx?a=4153&lang=1)系統。
- **PX4 Flight Review 有公開 log 列表**（`is_public` 欄位＋ browse 頁），B2 已鋪了「讀真實 ULog」這條線，可以直接接上。

**註冊架數那條線索（已寫入 D2，但仍標為推論）**：運安會歷年報告載 2021 年底 **75,240**、2022 年底 **40,134**、2024 年底 **38,683**（機關法人 10,176＋自然人 28,507，內部自洽）。一年掉三萬五。法源找到了——《遙控無人機管理規則》**第 10 條「註冊號碼之有效期限為二年」**，而管理規則 2020-03-31 施行，首波註冊潮正好 2022 到期。但運安會沒說明統計口徑、民航局也沒說明落差，所以 D2 只放數列＋法條，明講「這是推論不是結論」。**若日後找到民航局的口徑說明，這條可以獨立成篇。**

（另注意：第 10 條的「註冊號碼效期二年」與操作證效期是兩件事，不要混用；操作證的部分以 C2 為準。）

### 決策二：職業線拆三篇，不寫「全解析」

一篇打三種讀者對誰都不夠用。拆法：

- **職業地圖**（全族群）：十種角色、各自在產業鏈哪一層、要什麼能力
- **從軟體業轉進來**（最有立場的一篇）：能力遷移對照
- **教育與訓練路徑**（學生／家長）：科系、證照、機構、競賽

### 決策三：投資線走「框架與風險」，不走「標的清單」

三個理由：

1. 無人機在台股是政策題材股，訂單不連續、波動大，報明牌的風險報酬不對稱
2. 站上已有四條件框架，套用比列名單更有價值
3. 這類文章需走 `post-verify` 的查證標準，成本高，寫少而準比較划算

### ⚠️ 若日後要排程發布：不得有前向連結

URL 含日期（`/posts/<category>/YYYY-MM-DD-<slug>`），而 `src/pages/posts/[...slug].astro` 的 `getStaticPaths` 用 `getPublishedPosts()`——**未來日期的文章根本不會被建置，連過去就是 404**。

因此：**已發布的文章絕不能連到日期更晚的文章。** 排程時必須讓連結圖全部指向更早或同日的文章。

實務做法：

- 上表的順序就是依此排的——每篇支線只回連 hub 與更早的支線
- **hub 不列個別支線連結**，改成描述五個方向 + 指向 `/tags/drone`。tag 頁會隨發布自動更新，不需要人工維護，也不會產生前向連結
- 新增排程文章後，用這段檢查（無輸出即通過）：

```bash
python3 - <<'EOF'
import re, glob, os
for path in glob.glob('src/content/posts/**/*.md', recursive=True):
    txt = open(path, encoding='utf-8').read()
    m = re.search(r'^date:\s*(\d{4}-\d{2}-\d{2})', txt, re.M)
    if not m: continue
    for tgt in re.findall(r'\(/posts/[a-z]+/(\d{4}-\d{2}-\d{2})-[a-z0-9-]+\)', txt):
        if tgt > m.group(1):
            print('FORWARD LINK:', os.path.basename(path), m.group(1), '->', tgt)
EOF
```

（既有的 2026-03 至 2026-04 舊文有數處前向連結，但那些目標日期都已過去，不影響。無人機系列目前全部同日發布，因此不受此約束——但只要有任何一篇改成未來日期，整個連結圖就要重新檢查。）

1. **一手統計資料常常比二手報導更有力，但不會出現在搜尋結果第一頁。** A1 原本用「外銷金額 ÷ 出口架數 ≈ 每架 2.4 萬元」推論台灣出口的是低單價小型機；查證時才找到[財政部統計通報](https://service.mof.gov.tw/public/Data/statistic/bulletin/114/2025_22_UAV.PDF)直接按起飛重量拆了結構（2–7 公斤占 88.1%），是直接證據而非推論，且獨立驗證了那個推算。**寫台灣產業題目時，財政部／經濟部／主計總處的統計通報值得先翻一遍。**

2. 如果整篇都卡，問「**是題目真的需要，還是我把題目寫成需要**」
3. 如果確定需要某種材料，再問「**這材料真的不可得，還是我只是還沒去找**」——上市櫃財報、政府決標紀錄、事故調查報告、官方題庫都是免費且權威的
4. 訪談不是比查證高一階的材料。**單一受訪者的樣本偏差可能比公開財報還大**，而且數字問不出「為什麼」，「多少」也不必問人

目前全系列沒有任何題目被硬性阻擋。

## 七、互連結構

**hub-and-spoke，不是線性系列。**

理由：五個入口對應五種不同讀者，而非同一讀者的五個階段。讀者會從搜尋直接落在中間任何一篇（「無人機 證照」「無人機 產業 台灣」「空拍機 推薦」是完全不同的人），線性序號反而是負擔。

### 7.1 為什麼「無人機」是 tag 而不是 category

參考 Medium、Substack、Vocus 的做法，三者都把**容器**與**主題**分開：

| 平台 | 容器（一篇只能屬於一個） | 主題（一篇可多個） |
|---|---|---|
| Medium | Publication | Topics／Tags，上限 5 個 |
| Substack | Section（獨立郵件清單，讀者可個別退訂） | Tags（組首頁分區與封存清單，不影響寄送） |
| Vocus | 沙龍 → 房間 → 分頁 | 標籤 |

[Substack 官方 FAQ](https://faq.substack.com/p/how-to-use-sections-on-substack) 的判準：*「如果你只是想整理文章、不想建立獨立的郵件清單，那你要的是 Tags」*；Section 只在「希望訂閱者能單獨退訂某主題」時才用。

[Vocus 創作者指南](https://vocus.cc/article/65703596fd89780001ec8712)給了一個直接相關的反例：

> 如果將作品的前篇、中篇、後篇分別放置於不同房間，或是直接使用小說名稱來命名房間，隨著作品數量累積，可能導致沙龍導覽列變得超～級～長

**對應到 quidproquo**：`category` 扮演的是容器角色（決定資料夾、URL、導覽、分類頁配色），一篇只能有一個且 URL 永久。無人機是橫跨多個容器的主題，在上述三個平台都會是 tag。

所以 category 要問的不是「這篇在講什麼」，而是**「這篇長期要跟哪些文章住在一起」**。

### 7.2 `/tags/drone` 就是現成的 topic hub

已確認 `src/pages/tags/[tag].astro` 的 `getStaticPaths` **沒有 category filter**：

```js
props: { posts: posts.filter(p => p.data.tags.includes(tag)) }
```

因此 `/tags/drone` 會自動聚合全部 15 篇，不論它們躺在 `tech/`、`career/`、`policy/` 還是 `investing/`。**支線散在不同分類是安全的**，跨分類發現機制早就存在。

### 7.3 Tag 紀律（硬規則）

- 15 篇**全部帶 `drone`**，無一例外——這是整個 hub 能不能成立的關鍵
- 每篇再配 1–2 個切面 tag：`taiwan` / `supply-chain` / `regulation` / `career` / `uav`
- 總數維持在站規的 3–7 個（與 Medium 的 5 tag 上限相容）
- 核心主題在前，即 `drone` 永遠排第一

### 7.4 連結實作

- 地圖文當 hub，每篇支線首段回連 hub
- hub 之後補一段「延伸閱讀」導向各支線
- `series` 欄位**只給支線 D 用**（它有真正的時序），其他支線各自獨立
- 每篇至少雙向連結 2 篇同系列文章（避免孤兒頁，見 `docs/blog-improvement-plan.md` 的 de-orphan 做法）

### 7.5 已知缺口（不在本規劃範圍內）

Substack Section 有一件 tag 做不到的事：**讀者可以只訂閱某條線**。站上 RSS 目前是全站單一 feed，15 篇灌進去對只看 AI/RAG 的訂閱者是噪音。

正解是 **per-tag RSS**，不是改 category——用容器硬湊訂閱粒度就是上面 Vocus 那個反例。這是獨立的平台功能決定，需要另外評估，**不要為此調整內容規劃**。

次要缺口：`/tags/[tag]` 目前只是列表，沒有 tag 描述（Medium／Substack 的 topic 頁都有）。屬於 code 變更，同樣不在本規劃範圍。
