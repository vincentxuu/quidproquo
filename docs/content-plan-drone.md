## 一、選題原則

### 不對稱優勢在哪

1. **Autonomy stack 可以用 RAG 系列同一套方法論拆。** 站上已有 36 篇 RAG 文章在做「把系統拆成可獨立驗證的元件」，無人機的感知 → 定位 → 規劃 → 控制結構同構。寫這題的人多半是航太背景而非軟體背景，工程取捨講不清楚。
2. **核心軟體全開源，筆電就能跑。** PX4、ArduPilot、ROS 2、MAVLink、ExpressLRS 都能在 SITL / Gazebo 驗證，可產出第一手素材。
3. **台灣視角 + 既有的四條件框架**（見 `tw-stock-screen` skill）。地圖文已把缺口定位在產業鏈第 3 層，可往下鑽。

### 不要寫

| 題材 | 為什麼不寫 |
|---|---|
| 軍事戰術評論 | 沒有一手來源，會退化成軍事頻道的二手轉述 |
| 市場規模預測 | 各家報告不可比（地圖文已論證），預測本身沒有增值 |
| 廠商併購八卦 | 需持續追蹤，一篇就過期 |
| 器材推薦清單 | 沒飛過的人寫推薦，讀者看得出來；且該關鍵字全是聯盟行銷內容 |
| 各國國家隊逐一介紹 | 資訊密度高但沒有觀點，容易寫成維基百科 |

## 二、規劃用的五個軸

### 軸一：讀者意圖（決定同一事實怎麼寫）

| 意圖 | 讀者心裡的問題 | 對應形態 |
|---|---|---|
| 認識 | 這是什麼？ | 地圖、名詞解釋、產業結構 |
| 判斷 | 該不該在意？是不是泡沫？ | 對照、反方觀點、週期史 |
| 定位 | 這裡有沒有我的位置？ | 職業地圖、能力對照 |
| 參與 | 我要怎麼進來？ | 路徑指南、創業、投資、接單 |
| 動手 | 我要開始做 | guide、實作、器材決策 |
| 精進 | 我已經在裡面了 | 技術深潛、踩坑、工具比較 |

**這一軸最容易被忽略。** 同一份供應鏈知識，寫給「判斷」的人是「哪一層有護城河」，寫給「參與」的人是「我該投哪家履歷」，寫給「動手」的人是「這顆模組買得到嗎」。

### 軸二：主題領域

完整清單見第三節。

### 軸三：地域

不是獨立軸，是每篇內部的處理方式。三種類型：

| 類型 | 例子 | 處理 |
|---|---|---|
| 只有國外有 | Part 108、FCC Covered List、EASA 三級制 | 台灣讀者要知道，但沒有平行制度可比 |
| 只有台灣有 | 無人機國家隊、亞創中心、442 億計畫、民航法專章 | **內容護城河**，中文圈寫得清楚的極少 |
| 兩邊都有但差很大 | 職業市場、玩家門檻、產業鏈位置 | 對照本身就是價值 |

**不做「國外篇／台灣篇」分冊**——那會讓每個主題被切成兩半、兩邊都不完整。改成每篇內建台灣段落，整個系列挑 2–3 篇做完整國際對照。

### 軸四：文章形態

`deep-dive` / `guide` / `debug` / `project` / 對照比較 / 時事解讀。

站上 `tech` 幾乎全是 `debug` 和 `deep-dive`，缺 `guide` 和 `project`。無人機這題**最有機會產出 `project` 類**（自己組一台、自己跑一次任務），是整個系列唯一沒人能複製的內容。

### 軸五：深度

`difficulty` 欄位（入門 / 進階 / 深度）目前站上少用，這個系列建議用起來——因為同一主題會有給玩家和給從業者的兩個版本。

## 四、已定案的三個寫法決策

### 決策一：作者沒飛過、沒考照 → 玩家線改寫法

**不寫**「無人機入門推薦」。
**要寫**「一個研究過產業、但沒摸過實機的人，從零開始的紀錄」。

這個角度只有本站能寫——已有一篇產業地圖，知道供應鏈每一層長什麼樣，卻連飛都沒飛過。**這個落差本身就是題目**：紙上的產業理解，跟真的把東西飛起來，差距在哪。

拆成兩種，寫作條件不同：

| 類型 | 能不能現在寫 | 一手來源 |
|---|---|---|
| 制度解析（民航法、操作證制度、註冊流程） | ✅ 可以 | 法規條文、民航局公告 |
| 實作紀錄（買什麼、第一次飛、考照） | ❌ 要真的去做 | 自己的紀錄 |

制度解析類要在文中**標清楚哪些是查來的、哪些是做過的**。

### 決策二：職業線拆三篇，不寫「全解析」

一篇打三種讀者對誰都不夠用。拆法：

- **職業地圖**（全族群）：十種角色、各自在產業鏈哪一層、要什麼能力
- **從軟體業轉進來**（最有立場的一篇）：能力遷移對照
- **教育與訓練路徑**（學生／家長）：科系、證照、機構、競賽

### 決策三：投資線走「框架與風險」，不走「標的清單」

三個理由：

1. 無人機在台股是政策題材股，訂單不連續、波動大，報明牌的風險報酬不對稱
2. 站上已有四條件框架，套用比列名單更有價值
3. 這類文章需走 `post-verify` 的查證標準，成本高，寫少而準比較划算

## 七、互連結構

**hub-and-spoke，不是線性系列。**

理由：五個入口對應五種不同讀者，而非同一讀者的五個階段。讀者會從搜尋直接落在中間任何一篇（「無人機 證照」「無人機 產業 台灣」「空拍機 推薦」是完全不同的人），線性序號反而是負擔。

實作：

- 地圖文當 hub，每篇支線首段回連 hub
- hub 之後補一段「延伸閱讀」導向各支線
- `series` 欄位**只給支線 D 用**（它有真正的時序），其他支線各自獨立
- 每篇至少雙向連結 2 篇同系列文章（避免孤兒頁，見 `docs/blog-improvement-plan.md` 的 de-orphan 做法）
