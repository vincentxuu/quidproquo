# 多來源導讀與英文練習：寫作規則

日期：2026-10-10
狀態：讀者問題由 agent 決定、英文原音導讀預設附英文練習，已依使用者確認整合到 post skill；定期收集與發文排程另議。

## 目的與範圍

把值得理解的文章、訪談、影片、演講、官方文件與實作案例，整理成讀者能理解並採取行動的雙語文章。有英文原音時，另提供適合跟讀的短摘錄與中文對照。

每篇由 agent 先決定並寫出一句：讀者現在遇到什麼問題，看完能做什麼。依使用者提供的來源、本站既有文章與目標讀者，選擇有具體用途、可靠證據、能補足既有內容的角度；不要求使用者先替文章出題。來源由這個問題決定，不因某網站有新文就直接開寫。

使用者只給連結時，agent 自行選題、定標題與大綱並繼續研究；只有無法查證的個人經驗或會改變任務範圍的必要條件，才提出精準問題。不能以自主選題為由編造事實。

## 1. 來源按用途分工

| 用途 | 來源 | 寫作要求 |
|---|---|---|
| 核心內容 | 原始訪談、演講、作者文章、論文、官方文件 | 指出這篇主要在導讀什麼，閱讀實際內容 |
| 核實技術細節 | 官方 repo、產品文件、release note、原始數據 | 用於確認命令、功能、授權、數據定義與版本 |
| 中文／背景解說 | 媒體、作者導讀、章節摘要 | 幫助找到問題與理解脈絡；寫明轉述，追查其原始來源 |
| 寫法參考 | INSIDE、AIN3XT、Ernest Chiang 等 | 借用敘事方法，不直接沿用他人的句子、排序與結論 |
| 英文練習 | 與原音相符的英文逐字稿／字幕 | 附時間連結、中文對照、字幕性質及必要的核對說明 |

同一來源可以有多種用途，但不能因為編排好看，就把它當成技術或數據的一手證據。

## 2. 選題要有具體收穫

- 能回答一個具體問題，例如「怎麼讓 coding agent 自己驗證」。
- 能提供至少一個案例、方法、取捨或可操作的動作。
- 與既有站內文章相比，有新問題、新證據或新應用；只有重複觀點就優先更新既有文章。
- 不以熱門程度、標題數字或來源名氣作為唯一理由。
- 初始來源池可用本次使用者提供連結、docs／.research 既有記錄與原始來源的引用鏈；不是全網完整清單。

## 3. 先閱讀，再下結論

- 分清全文、部分內容、摘要、轉引與未讀。截斷的字幕不標成完整逐字稿。
- 影片先找官方逐字稿，再找現成字幕；沒有現成文字才考慮授權音訊的 ASR。
- `list` 成功只代表發現字幕軌；取得全文另驗證內容非空、末段時間與相同版本的影片長度相符。
- 自動字幕要標示；實際引用或供跟讀的短段落需回聽核對，尤其是專名、數字與否定詞。
- 只有二手整理也可寫有限範圍的導讀，但明示轉述，不冒充親聽、不編造原話。英文原話與 shadowing 區暫不加入，待原音文字核實。
- 工具失敗先查版本、回應與替代路徑。可沿用已驗證的隔離環境，不能把首次工具失敗直接當成來源沒有逐字稿。

## 4. 多來源不等於多個獨立證據

- 敏捷三叔公、PJFP 或其他媒體若都整理同一場直播，它們是同一原始內容的不同解說。
- 引用數字要保留日期、口徑與說話者；自述產出不寫成經稽核績效，PR 數量不直接等於成果品質。
- 不同場次、不同日期的演講各自標示，不把後一場補充拼成前一場的原話。
- 來源彼此不一致時，列出差異與目前能確認的範圍，不自行選最大的數字。
- 作者的解讀、來源主張與本站實測分開表達。沒有做過的事不寫成自己的經驗。

## 5. 主文以讀者問題排，不照來源清單排

建議骨架：讀者問題 → 主題與來源 → 給誰／前提 → 核心方法 → 具體例子 → 限制與取捨 → 怎麼用。

需要比較、流程或因果關係時再加入表格／圖解。每篇至少有一個可執行動作，不用把每個來源都各寫一節。查證細節留研究筆記，正文只留下會影響讀者判斷的限制。

文章產出中英兩版，交叉連結與事實範圍對齊；英文版文章和英文逐字稿是不同產物，不能互相替代。

## 6. 英文練習依媒材選擇

- 有英文原音的導讀預設附英文練習區：嵌入原始影片／音訊，附可取得的官方逐字稿入口，再挑可引用的短段落做英中對照，不需逐篇詢問是否加入。
- YouTube 英文練習嵌入使用 `captions: en`，可搭配 `start` 定位；字幕能否顯示仍取決於來源與播放器。
- 若字幕或逐字稿尚未核實，明示練習區待補與取得障礙，不編造原話，也不宣稱完整交付。
- 跟讀區必須在同一節提供一段意思連貫的英文原字幕短摘錄、中文意思與對應原音播放器／定位連結；短語表、摘要與自擬句不能取代原字幕。播放器優先顯示同步英文字幕，提供起訖範圍與重播方式。引用長度須符合來源授權與使用範圍，較長內容連回原站字幕。
- 挑段先試約 15–30 秒，以自然停頓決定邊界；這是開始練習的建議，不是效果保證。
- 入選條件：意思完整、讀者能理解、表達可用、聲音清楚。過難就縮成一句。
- 每段標說話者、來源、時間、英文原話與自然中文。練習提示指出一個可套用的表達，不把每句變成大量文法註解。
- 另寫的練習句清楚標示，不能冒充講者原話。語音合成不能冒充原音。
- 只有文字：提供英文閱讀或表達練習，不標成原音 shadowing。原來源只有中文時，不把英文改寫叫作英文原稿。
- 連回官方全文供連續聽讀；未確認完整轉載授權時，不在本站重新發布整集逐字稿或完整翻譯。

## 範例：Poteto 信任階梯

參考文章：[Poteto 的信任階梯](https://quidproquo.cc/posts/ai/2026-10-07-poteto-trust-ladder-verification-first/)。本次讀取站上文章與本機 Markdown；沒有重新查證其所有外部技術與人物宣稱。

| 角色 | 文章使用的來源 | 規則如何套用 |
|---|---|---|
| 原始內容 | Matt Pocock × Lauren Tan 直播 | 確认完整字幕或原音，標示取得程度 |
| 官方實作 | pstack repo 與 guide | 查功能、命令與程式碼授權；程式碼 MIT 不等於訪談也可全文轉載 |
| 中文理解 | 敏捷三叔公 | 抽出讀者問題與白話案例，原話回到原音核對 |
| 章節導航 | PJFP | 幫助定位原音；不當成第二個獨立實驗 |
| 另一場演講 | Redreamality 的字幕分析 | 明確分開場次、日期與主張 |
| 英文練習 | 原始直播英文字幕 | 取得與回聽核對後再加入，不能從中文整理反譯冒充原話 |

這篇目前已明示對談內容主要為二手轉述、未取得逐字稿。訂規則不代表已重新查證或更新這篇；後續若要補英文練習，另依 post-update 流程處理中英兩版。

## 尚待決定

- 來源池要先人工維護，還是接成定期收集與選題流程。
- 來源優先序、發文頻率與單週篇數：本規則不自行指定。
