# Ask AI Sidebar 伴讀重新設計

## 1. 使用者意圖

讀者在閱讀技術文章時，想要即時降低理解門檻：
1. **看懂這篇文章** — 遇到不懂的段落或術語，要即時解釋
2. **找到相關內容繼續讀** — 讀完想知道還有什麼延伸閱讀
3. **驗證自己的理解** — 用自己的話問問題，確認理解正確

核心：agent 是**閱讀伴侶**，不是客服機器人。

## 2. 現況苦工

| 苦工類型 | 現況問題 |
|---|---|
| 空白恐懼 | 浮動面板打開是空白對話框，讀者不知道該問什麼 |
| 脈絡斷裂 | 面板遮住文章，想回頭看某段得關面板→看文章→再開面板 |
| 信任斷裂 | AI 不知道讀者在看哪篇（page context flag 沒開），回「問題太模糊」 |
| 入口混亂 | InlineAsk + ChatFloating 兩個入口功能重疊 |

## 3. Agent 介入設計（模式 C 進化：sidebar 伴讀）

### 設計原則

- agent 嵌在閱讀流程裡，不是在旁邊開 chat
- 預設快捷按鈕取代空白對話框（心法 1：不做純 chat）
- AI 已知讀者在看哪篇（心法 5：從意圖反推 UI）

### UI 流程

#### 桌面版（>= 1024px）

1. **未開啟**：右下角小巧的「✦ Ask AI」按鈕（圓角膠囊，不是圓形）
2. **開啟 sidebar**：
   - 文章區域平滑縮窄（CSS transition）
   - 右側推出 360px sidebar（不是浮動面板，是佈局的一部分）
   - sidebar 與文章並排，不遮擋任何內容
3. **sidebar 初始畫面**：
   - 頂部：「📄 目前文章」chip，顯示文章標題（可按 × 切回全站模式）
   - 中間：三個快捷按鈕（不是建議問題列表）
     - 「重點摘要」— 一鍵取得文章摘要
     - 「術語解釋」— 列出文章中的關鍵術語並逐一解釋
     - 「相關文章」— 找站內相關文章
   - 底部：自由輸入框（「問我任何關於這篇文章的問題...」）
4. **對話中**：
   - 快捷按鈕在首次互動後收起（不佔空間）
   - 對話區域顯示問答歷史
   - 底部始終有輸入框
5. **關閉**：點 sidebar 的 × 或再按按鈕，文章恢復全寬

#### 手機版（< 1024px）

1. **未開啟**：同桌面版，右下角「✦ Ask AI」按鈕
2. **開啟**：從底部向上滑出面板（佔螢幕 60%），上方仍可看到文章
3. **可拖曳調整高度**：上拉到全螢幕、下拉到收起
4. **其餘同桌面版**

### 入口統一

- **砍掉 ChatFloating**（浮動彈窗）在文章頁的使用
- **砍掉 InlineAsk**（文章底部輸入框）— 功能併入 sidebar
- ChatFloating 只保留在非文章頁（首頁、分類頁等），作為全站 Ask AI 入口
- `/chat` 獨立頁面不受影響

### 後端需求

1. **開啟 page context flag**：`rag_flag_page_context` 設為預設開啟
   - 讓 AI 在文章頁能讀到該篇文章內容
   - 這是最基本的前提，沒有這個什麼 UI 改造都沒用
2. **快捷按鈕走 skill prompt**：
   - 「重點摘要」→ 固定 prompt：「請用 3-5 個重點摘要這篇文章：{article_content}」
   - 「術語解釋」→ 固定 prompt：「列出這篇文章中的關鍵技術術語並逐一解釋：{article_content}」
   - 「相關文章」→ 走現有 RAG 搜尋，不需要 LLM

## 4. 可控性檢查

- [x] 每個 agent 動作前後都有使用者可介入點（快捷按鈕 = 主動觸發）
- [x] 結果落在使用者預期內（「重點摘要」→ 預期就是摘要）
- [x] 可重生 / 微調 / 不用整個重來（每個回答獨立，輸入框隨時可追問）
- [x] 不是右邊一個 chat 視窗（有預設快捷按鈕，融入閱讀流程）
- [x] 手機版有合理的降級方案（底部向上展開）
