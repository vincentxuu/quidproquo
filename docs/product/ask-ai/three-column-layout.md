# 文章頁三欄版面取捨（本文／TOC／Ask AI）

- 狀態：草案，待拍板
- 日期：2026-10-16
- 來源：讀者回報「Ask AI 面板打開後出現巨大空格、本文被壓縮」的排查
- 相關文件：`sidebar-redesign.md`（面板本身）、`page-context PRD.md`（面板內容）
- 方法：`agent-ux-design` 五步驟（心法 4「融進流程」、心法 5「從意圖反推 UI」）

## 0. 與同層 PRD 的對齊

三欄規格是對**現況架構（body `padding-right` + `position: fixed` 面板）**的修正，不是回歸 `sidebar-redesign.md` 原訂的「PostLayout flex 佈局、sidebar 是佈局一部分」。理由：

- flex 佈局下開關面板會縮文章寬度，本文行長會跳動，違反「開關面板時讀者眼睛不需要重新定位每一行」。
- 採此規格則**不做** `sidebar-redesign` Phase 2 的 flex 改造；現況的 `padding-right` + fixed 做法保留，並透過本規格的門檻與 CSS 變數修正對齊問題。

寬度與門檻以本規格為準，並同步修正 `sidebar-redesign.md` 的舊值：

| 項目 | sidebar-redesign 舊值 | 本規格 | 備註 |
|---|---|---|---|
| 面板寬 | 360px | **380px** | 與 `ChatSidebar.tsx` `SIDEBAR_WIDTH` 對齊 |
| 桌面側欄門檻 | ≥1024 | **≥1140** | 1024 時三欄擠在一起，本文僅剩約 216px，不可讀 |
| 三欄並存門檻 | — | **≥1520** | 本文 + TOC + 面板同時存在的下限 |

`page-context PRD.md` 的 chip 與建議問題不受佈局門檻影響；面板收起 TOC 時，面板中的「重點摘要／相關文章」快捷鍵補足 TOC 導覽功能。

## 1. 使用者意圖

在文章頁，讀者的意圖只有一個：**把這篇讀完，需要時不被中斷地取得協助**。

三個元素的角色：

| 元素 | 角色 | 使用節奏 |
|---|---|---|
| 本文 | 主體 | 全程 |
| TOC | 導覽（跳段、知道還有多長） | 偶爾、短暫 |
| Ask AI 面板 | 伴讀（看懂、延伸） | 主動叫出、短暫 |

三者搶的是**同一條水平空間**。取捨原則因此是：

> **本文的可讀性第一；TOC 與 Ask AI 是輔助，輔助之間互相競爭，只有視窗真的夠寬才允許同時存在。**

## 2. 現況

### 2.1 現在的尺寸與門檻

| 常數 | 值 | 出處 |
|---|---|---|
| body 一般 max-width | 800px | `PostLayout.astro:206` |
| body 文章頁 max-width（≥1000） | 1180px | `PostLayout.astro:214-215` |
| page gutter | 24px（<640→16px、<400→12px） | `PostLayout.astro:205,607,632` |
| `.post-grid` 兩欄（≥1000） | `minmax(0,1fr) 340px`、gap 40px | `posts/[...slug].astro:636-642` |
| Ask AI 面板寬 | 380px（`SIDEBAR_WIDTH`） | `ChatSidebar.tsx:6,45` |
| Ask AI 讓位方式（≥1024） | `body { padding-right: 380px + gutter }` | `chat.css:393-397` |
| Ask AI 面板定位 | `position: fixed; right: 0` | `chat.css:429-441` |

### 2.2 問題一：body「置中＋上限」對不上「貼齊 viewport」的面板 → 巨大空格＋本文壓縮

`padding-right: 380px` 要能對齊面板，前提是 **body 右緣等於 viewport 右緣**。但文章頁 body 是 `max-width: 1180px; margin: 0 auto`，視窗寬於 1180 時 body 比 viewport 窄又置中，於是這段 padding 不是「在畫面右邊讓出空間」，而是**從置中後的內容裡往內吃**——本文被壓縮，面板與內容之間露出沒被蓋住的 padding 變成一大條空白。

以 1512px 視窗實算：

| 量 | 結果 |
|---|---|
| body（置中、上限 1180） | x = 166 ~ 1346 |
| 扣掉 `padding-right: 380+24` | 內容只剩 **752px** |
| `.post-grid` 本文欄（1fr + 340 TOC + 40 gap） | **約 372px** ← 本文被壓縮 |
| 面板（fixed, right:0, 380） | x = 1132 ~ 1512 |
| 兩者之間露出的空白 | **約 190px** ← 巨大空格 |

視窗越寬，這條空白越大（1920 時約 394px）。`sidebar-redesign.md` 原訂「PostLayout 改為可縮窄的 flex 佈局、sidebar 是佈局的一部分」，但實作改成「body padding + fixed 面板」，才留下這個對不齊的破口。

### 2.3 問題二：沒有目錄的文章，TOC 欄仍固定佔 340px

`.post-sidebar` 一律渲染，≥1000 一律保留 340px 欄位；當文章沒有 h2/h3 也沒有 related video 時，這一欄是空的，本文被擠在左邊、右邊留一大塊空白。與面板無關，但同樣是「巨大空格」的來源。

### 2.4 問題三：沒有「三欄放不下時該犧牲誰」的規則

現在 1024px 就同時要放「本文 + TOC(340+40) + 面板(380)」，扣一扣本文只剩約 216px。程式沒有定義此時該退掉哪一欄，只會硬擠。

## 3. 取捨設計

### 3.1 固定常數

| 項目 | 值 | 理由 |
|---|---|---|
| 本文量測目標 | **712 – 760px**（上限 760） | 與現在舒適寬（752）一致，約 44 全角字／行 |
| TOC 欄 | 340px + gap 40px = 需要 380px | 現況 |
| Ask AI 面板 | 380px | 現況；與 `ChatSidebar.tsx` `SIDEBAR_WIDTH` 對齊 |
| gutter | 24px × 2 = 48px | 現況 |
| CSS 變數 | `--ask-ai-sidebar-width: 380px`<br>`--ask-ai-gutter: 24px` | 單一事實來源，避免 360/380 混用 |

### 3.2 三條規則

1. **本文優先**：任何組態下先把本文撐到 712（理想 ≥712，上限 760），剩下的寬度才分配給輔助欄。
2. **面板開啟時先犧牲 TOC**：Ask AI 是短暫狀態、且面板本身就有「重點摘要／相關文章」快捷鍵，TOC 的損失最小；關閉面板即恢復。
3. **只有容得下「本文 + TOC + 面板」時才三者並存**，否則 TOC 在面板開啟期間收起。

### 3.3 門檻與行為

由 3.2 反推門檻：

- 兩欄（本文 + TOC）：`712 + 380 + 48 = 1140` → **W ≥ 1140**
- 兩欄（本文 + 面板）：`712 + 380 + 48 = 1140` → **W ≥ 1140**（面板從 1024 提高到 1140）
- 三欄：`712 + 340 + 40 + 380 + 48 = 1520` → **W ≥ 1520**

| 視窗寬度 W | 本文欄 | TOC | Ask AI | 與現況差異 |
|---|---|---|---|---|
| **< 1140** | 全寬 | 文章內 accordion（≥1000 疊在本文上方，現況） | **bottom sheet**（60vh，現況的 <1024 行為） | 面板側欄門檻 1024→1140 |
| **1140 – 1519** | 712–760，置中 | 面板**關閉時**顯示；面板**開啟時收起** | 右側 380 固定面板 | 新增「面板開啟＝收起 TOC」 |
| **≥ 1520** | 712–760，置中 | 保留 340 | 右側 380 固定面板 | 三欄並存 |

> 無 TOC 文章（無 h2/h3、無 related video）：在 1140–1519 右側不渲染空欄，本文置中於可用區；面板開啟時行為同上（本文 + 面板）。

三個門檻組態下本文都落在 712–760，代表**本文寬度穩定、只有輔助欄進退場**——這是這個設計最重要的性質：開關面板時，讀者眼睛不需要重新定位每一行。

### 3.4 版面示意

```
W < 1140                      W = 1140–1519（面板關）      W = 1140–1519（面板開）
┌──────────────┐              ┌───────────┬───────┐        ┌───────────┬───────┐
│   TOC(疊上)  │              │  本文 712 │ TOC   │        │  本文 712 │ AskAI │
├──────────────┤              │           │ 340   │        │   (置中)  │  380  │
│   本文全寬    │              └───────────┴───────┘        └───────────┴───────┘
└──────────────┘
  Ask AI = 底部 sheet

W ≥ 1520（面板開，三者並存）
┌───────────┬───────┬───────┐
│  本文 712 │ TOC   │ AskAI │
│           │ 340   │  380  │
└───────────┴───────┴───────┘
```

### 3.5 為什麼是 1140 / 1520（而不是沿用 1024 / 1000）

- 1024 同時放三欄時本文只剩約 216px，不可讀；1140 是「本文 + 任一輔助欄」都能維持 712 的最小值。
- 1520 是「本文 + TOC + 面板」三者並存的下限。
- 兩者都不是魔術數字，是 3.1 常數直接推出來的；以後改面板寬或本文目標，門檻跟著算，不必憑感覺調。

## 4. 實作要點

### 4.1 讓「讓位」對得齊（修 2.2）

面板開啟時，**body 右緣必須等於 viewport 右緣**。做法是把寬度上限從 body 搬到內容層：

- 面板開啟時讓 body 不再受 `max-width: 1180px` 限制（`max-width: none`），繼續用 `padding-right: var(--ask-ai-sidebar-width) + var(--ask-ai-gutter)` 讓位 → 這段 padding 就會落在畫面右邊、被 fixed 面板精準蓋住。
- 把文章的量測上限改掛在內容層（`.post-grid { max-width: 1180px; margin-inline: auto }` 或等價寫法），避免本文在寬螢幕被拉太寬。三欄模式下本文欄再加 `max-width: 760px`，避免 1fr 在 ≥1920 螢幕被拉超過可讀上限。
- 面板開啟時本文欄上限 760px，於可用區置中。
- **開關面板時不要對本文欄寬度做 width transition**：body 從 1180 撐開到視窗寬、再縮回，若對寬度補動畫會造成本文突然變寬再變窄，讀者眼睛跳動。建議只對面板本身做 0.3s 滑入/淡出，本文欄寬度在各穩態下維持 712–760 不變。

### 4.2 TOC 缺省與收起（修 2.3）

- `.post-sidebar` 只有在「有 h2/h3 目錄」或「有 related video」時才保留 340px 欄位；否則整欄不渲染。用 class 或 `:has()` 判斷，別再讓空欄佔位。
- 面板開啟時收起 TOC（`body.has-chat-sidebar` 時 `display: none`），關閉即恢復；面板中的「重點摘要／相關文章」快捷鍵補上 TOC 的功能缺口。

### 4.3 狀態管理（新增）

- 開關狀態以 `body.has-chat-sidebar` 為單一事實來源，由 `ChatSidebar` 元件負責加/移除類名；`PostLayout` 不獨立操作同一個類名，避免兩邊互打架。
- 狀態存 `sessionStorage`（關標籤即忘，不跨瀏覽器階段殘留）。
- **切換文章時強制關閉面板並重置狀態**，避免在新文章頁殘留上一篇的面板與 TOC 收起狀態。

### 4.4 鍵盤與可及性（擴充）

- 開啟時把焦點移到輸入框，關閉時焦點回到 `✦ Ask AI` 觸發鈕；`Esc` 應可關閉面板。
- `aria-expanded`/`aria-hidden` 隨開關同步；TOC 收起時不需額外 screen reader 公告（狀態短暫、由面板快捷鍵補足）。
- 保留現有 0.3s transition 與 `prefers-reduced-motion` 的關閉（`chat.css:508-518`）。

### 4.5 長頁面與滾動（新增）

- 面板為 `position: fixed`，不跟隨頁面滾動；面板內容超過視窗高度時，**面板內部 `overflow-y: auto` 自行滾動**，不遮住頁腳、不與頁面 scroll 爭奪。
- 觸控設備（iPad 等）同樣支援 `Esc`（外接鍵盤）與點擊面板外關閉。

### 4.6 點擊面板外關閉（新增）

- 點擊面板外的本文/TOC 區域時關閉面板；點擊面板內部不關閉。這是「短暫狀態」的預期關閉方式，降低讀者被困在面板裡的機率。

### 4.7 印表機（新增）

- `@media print` 隱藏 Ask AI 面板與觸發鈕，TOC 與本文照常列印。

### 4.8 需要一起修的（2.3）

- 順手更新沿用舊門檻的同伴：`.chat-sidebar-quick-actions`（`chat.css:458`）、`.scroll-top` 讓位（`chat.css:522-527`）、bottom sheet 門檻（`chat.css:484`）。
- `ChatFloating` 在文章頁移除（與 `sidebar-redesign.md` Phase 4 一致），非文章頁保留。

### 4.4 順帶觀察（不在本範圍）

- `chat.sidebar.q.terms`（「術語解釋」）i18n 已存在，但 `ChatSidebar.tsx:59-70` 只渲染「重點摘要／相關文章」兩顆，第三顆遺漏。屬面板內容問題，另案。

## 5. 驗證

- 視覺回歸基線補：文章頁 × {1139, 1140, 1400, 1519, 1520, 1600, 1920} × {面板開, 面板關}，另加「本文右緣與面板左緣之間不得有 > gutter 的空隙」的斷言。
- 斷言：開關面板時本文欄寬度保持在 712–760（不跳動）。
- 手動清單：1140 / 1519 / 1520 三個邊界各開關一次面板，確認本文寬不跳動、無空白、TOC 依規則進退場。
- 沒有目錄的文章（無 h2/h3、無 related video）在 ≥1140 不得出現空的右欄。
- 鍵盤：Tab 循環、Esc 關閉、焦點回歸 `✦ Ask AI` 觸發鈕。
- click-outside：點擊本文/TOC 區域關閉面板。
- 跨文章：開啟面板後切換文章，面板應關閉且狀態重置。
- 無障礙：`aria-expanded`/`aria-hidden` 正確；screen reader 可辨識面板開啟/關閉。

| 項目 | 決定 | 理由 |
|---|---|---|
| 本文量測上限 | **維持 760** | 與現況 752 幾乎相同，走保守路線；日後若發現 1440 螢幕上行長過長再調 |
