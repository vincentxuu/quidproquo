# 這個部落格的規矩

給 AI 看的說明。Claude、Codex、Cursor 等工具都會讀這份檔案。

## 這是什麼

一個人的個人部落格，用 Astro 產生靜態網頁，放在 Cloudflare Pages 上。
文章是 Markdown 檔，放在 `src/content/posts/`。

## 檔案放哪裡

| 東西 | 位置 |
|---|---|
| 文章 | `src/content/posts/YYYY-MM-DD-英文檔名.md` |
| 網站設定（站名、作者、網址） | `site.config.ts` |
| 圖片等靜態檔 | `public/` |
| 關於頁 | `src/pages/about.astro` |

## 文章的設定區塊

每篇文章最上面要有這段，用 `---` 包起來：

```yaml
---
title: "文章標題"        # 必填。有冒號的話要用雙引號包起來
date: 2026-01-31         # 必填。格式是 年-月-日
description: "一兩句摘要" # 選填。會顯示在列表和搜尋結果
tags: [標籤一, 標籤二]    # 選填
draft: false             # 選填。true 就不會公開
---
```

**只有這五個欄位。不要自己加新欄位**，加了會建置失敗。

## 寫作規則

1. **沒有來源的事實不要寫。** 版本號、日期、價格、統計數字，都要有出處。
2. **引用寫成內文連結**，不要只在文末列一串。
3. **不要幫作者寫第一人稱的看法。** 「我覺得」「我踩過的坑」「我建議」這些必須是作者本人寫的。你可以留空白並標示「這裡需要你自己補」。
4. **只有單一來源的事情要講明白**，寫成「目前只查到一個來源」，不要當成已確認的事實。
5. 標題階層要能單獨讀懂，讓人掃一眼就知道整篇在講什麼。
6. 用繁體中文，除非作者另外指定。

## 新增文章的流程

1. 先研究，把來源列給作者看。
2. 確認方向後才開始寫。
3. 寫完自己檢查一遍設定區塊有沒有填對。
4. 發布前跑一次事實查核：把文章裡所有數字、日期、版本、引言抽出來對回來源。
5. 存檔到 `src/content/posts/`，檔名格式 `YYYY-MM-DD-英文小寫-用連字號.md`。

## 發布

把檔案推進 GitHub，Cloudflare 會自動建置並更新網站，通常一到兩分鐘。

建置前會自動跑 `node scripts/check-content.mjs`。如果有欄位沒填對，建置會失敗，
錯誤訊息會直接說哪個檔案、哪裡有問題、怎麼修。

## 不要做的事

- 不要改 `src/content.config.ts` 的欄位定義。
- 不要改 `scripts/check-content.mjs` 讓檢查變寬鬆。有問題就修文章，不要拆掉檢查。
- 不要動已經發布過的文章的檔名和日期，網址會壞掉。
- 不要一次新增很多篇文章。這是個人部落格，不是內容農場。
