| 四個條件 | Grok Bot |
|---|---|
| 你不在時繼續跑 | ✅ 跑在雲端電腦上，關掉 app、筆電或手機都不會停 |
| 醒來後自己決定做什麼 | ✅ L3：主 bot 會自己來找你；1.0 起會自己發現該做的事並提議接手 |
| 跨對話記得你的目標 | ✅ 每個 bot 有自己的記憶，名字、時區等少數事實所有 bot 共用 |
| 能代你對外做事 | ✅ 寄信、付款、發訊息、操作網站；Auto Review 決定哪些要先問你 |

SpaceXSI 的[設計文](https://x.ai/news/designing-grok-bot)裡，示範畫面的側邊欄不是一串對話紀錄，而是一排有名字、有頭像的 bot，每個都在回報自己的事：

- Kenny：「Need your yes on the Friday all-hands deck.」
- Justin：「8 intros drafted — sitting in the CRM till you send.」
- Tyler：「14 receipts in. Still missing your Uber from Tuesday.」
- Keith：「Acme's wobbling. Drafted a Thursday check-in.」

看起來像一個小團隊，各管各的。但[官方文件](https://docs.x.ai/grok-bot/computer-and-apps)寫得很清楚：這些 bot 用的是同一台電腦，共用檔案、瀏覽器登入和命令列憑證，「Do not use separate Bots as a security boundary」。

這篇講 Grok Bot 的一人多 bot：分工帶來什麼、共用了什麼，以及一件工作什麼時候該開新 bot。

## Grok Bot 是什麼

Grok Bot 由 SpaceXSI（原 xAI）推出，2026 年 8 月開始 beta，[11 月 11 日推出 1.0](https://x.ai/news/grok-bot-1-0)。它跟 Grok 聊天 app 是兩個不同的產品，[登入用的是 Cursor 帳號](https://docs.x.ai/grok-bot/faq)，電腦和後端由 Cursor 營運（SpaceX 已收購 Cursor）。

- **在哪裡用**：macOS、Windows、Linux 桌面 app，以及 iOS、Android app。也能在 X Chat 跟 bot 對話、在 X 上 tag @bot 把一則貼文交給它，團隊 bot 可以在 Slack 裡用。
- **方案**：含在 X Subscription 的 Premium、Super、Ultra，以及舊版 Cursor 的付費方案；免費版和 Plus 不含。
- **模型**：沒有模型選擇器。Grok Bot 每個任務自己挑模型，可能是 SpaceXSI 自家的，也可能是第三方的，而且不會告訴你這次用了哪個。

設計文說，他們把 agent 產品裡一大堆名詞收斂成五個你需要懂的東西：

| 物件 | 是什麼 |
|---|---|
| Bots | 有身分、記憶、執行環境和工具的常駐 agent |
| Chats | 跟某個 bot 對話的介面 |
| Prompts | 給 bot 的指示；用一次、存成 Skill，或設成定時觸發的 Routine |
| Tools | 讓 bot 存取資訊、採取動作的軟體、API、連接器、命令列、電腦操作 |
| Artifacts | bot 產出或修改的文件、設計、程式碼、資料 |

上一篇的 [OpenAI Dots](/posts/ai/2026-11-20-openai-dots) 目前一人一個 dot，OpenAI 說之後才會有多個 dot 組隊。Grok Bot 一開始就讓你開一整排。

## 分工帶來什麼

### 每個 bot 有自己的角色

[一個 bot](https://docs.x.ai/grok-bot/bots) 是「a durable AI teammate with a name, a job, its own conversation, and working context」。建好之後，第一則訊息就告訴它工作範圍、資料來源和核准界線，請它記住。之後要改它做什麼，直接在對話裡說。

設計文解釋為什麼要分開：法務 bot 可能需要一場糾紛的完整來龍去脈，財務 bot 需要好幾年的帳務紀錄。把這些塞進同一份大記憶，反而更難讓每個角色拿到它需要的東西。所以 Grok Bot 把兩種東西放在不同層級：

- **工具和技能放在帳號層級**：很多 bot 都要上網、處理文件、寄信。
- **記憶和例行工作（Routines）放在 bot 層級**：反映這個角色知道什麼、定期做什麼。

### 主 bot 替你協調

你的[主 bot](https://docs.x.ai/grok-bot/bots) 是主要聯絡窗口：它會自己來找你，也負責跟其他 bot 協調。設計文觀察到，使用者開了好幾個 bot 之後，有些人會設一個「Chief of Staff」bot 管其他專家 bot，只對它下指示，不用自己逐一檢查、分派。

跨角色的工作放在群組對話裡：設計師、工程師、PM、資料科學家 bot 在同一串裡交接，各自保留自己的記憶。實務上限大約是每個帳號 50 個 bot、每個群組 6 個。

### 例行工作與教它做事

- **Routines**：定時（每天早上 8 點、每 30 分鐘），或事件觸發（開了 PR、Slack 頻道有新訊息、Webhook 收到請求）。
- **Teach a task**：在電腦畫面上錄一段最長 10 分鐘的瀏覽器操作，bot 會把它轉成一份技能草稿，你檢查、測試後再用。官方建議先拿真實的一次性任務測技能，再把它變成例行工作。

1.0 再加上主動性：bot 會盯著進行中的專案，發現需要處理的事就提議接手，跟進沒做完的工作，需要判斷時把人拉進來。

## 共用了什麼

這是 Grok Bot 最需要弄清楚的地方。整理文件寫的：

| 每個 bot 各自有 | 同一帳號所有 bot 共用 |
|---|---|
| 名字、頭像、角色 | 一台雲端電腦 |
| 對話紀錄 | 電腦上的檔案 |
| 自己的記憶（大部分） | 瀏覽器 cookie 與登入狀態 |
| 自己的例行工作 | 命令列憑證 |
| 電腦上自己的一塊螢幕 | 連接的 app（整個帳號都能用） |
| | 工具和技能 |
| | 你的名字、時區等少數事實 |
| | 每週用量池 |

幾個容易踩到的地方：

- **登入一次，所有 bot 都登入了**：瀏覽器是共用的，你替一個 bot 登入某個網站，其他 bot 也拿得到那個 session。
- **每個 bot 的螢幕不是邊界**：文件寫「The screens are separate work surfaces, not separate security boundaries」。
- **連接的 app 是全帳號的**：你接上 Gmail，每個 bot 都能用。Gmail 一次只能連一個信箱，不想讓 bot 用就整個斷開。
- **刪 bot 不會清電腦**：刪掉一個 bot 會刪它的對話、記憶和例行工作，但它留在共用電腦上的檔案和登入狀態可能還在，要另外清。
- **團隊 bot 共用擁有者的東西**：擁有者加進團隊 bot 的 app、密鑰、技能和檔案，每個隊友跟它對話時都能用。

使用者之間的隔離是嚴格的：每個人的電腦都是專屬、硬體隔離的。問題只在同一個帳號裡面。

## 核准：Auto Review 和你的規則

[Auto Review 預設開啟](https://docs.x.ai/grok-bot/approvals-security-and-privacy)，每個動作執行前都會檢查：大多數直接跑，需要你同意的就在對話裡跳出核准卡片。

- **三個按鈕**：Allow once 只做這次；Always allow 做這次並存一條「自動允許」規則，之後同類動作不再問；Deny 不做。
- **兩種自訂規則**：Allow automatically、Ask first，各最多 20 條，每條最多 1,000 字。兩種都符合時，Ask first 贏。官方的例子是「Ask first before sending any external email」。
- **只有你的話算數**：Auto Review 判斷時看你自己傳的訊息，信件或網頁裡的文字不算你的要求。
- **背景工作的核准會失效**：從對話發起的工作，卡片會一直等你。從例行工作、收到的訊息或其他背景工作來的，30 分鐘沒回應就失效，動作不執行。
- **例行工作寄的信先存草稿**：bot 從它自己的信箱寄信時，例行工作或背景工作產生的信會先存成草稿，等你按寄出。

有一個跟付款有關的細節：**存在 Vault 的信用卡，結帳時會直接填入，不用每次另外核准**。想每一筆都自己核准，就不要把卡存進 Vault，輸入時不勾「Securely save to Bot's vault」。

關掉 Auto Review，bot 會不經檢查直接執行，你的自訂規則也會被隱藏、不生效。

## 用量池與 11 月的縮減

Grok Bot 的用量跟 Cursor、Grok app 共用同一個每週用量池，[計算方式](https://docs.x.ai/grok-bot/faq)是看 agent 走了幾步、用了多少 token，不是看你傳幾則訊息。一個大任務就可能用掉很多。

[TechCrunch 報導](https://techcrunch.com/2026/11/02/elon-musk-throttles-grok-bot-limits-due-to-unsustainably-high-costs/)，萬聖節週末有使用者醒來發現，每週用量從 50% 跳到 100%，即使他們沒在用。Musk 在 X 上回覆說這不是故障：

> The cost of serving Grok Bot was unsustainably high relative to revenue

報導刊出時，Musk 還沒說之後的上限會怎麼調整。

對常駐型 agent 來說這是一個實際的風險：它在背景替你做的事，都在吃同一個池子；廠商調整計價時，你的例行工作可能突然跑不動。要控制額外費用，在 grok.com/dashboard 把 Auto Top-up 關掉，或設每月額外用量上限。上限不會中斷正在跑的任務，所以可能會稍微超過一點。

## 實際用起來

[WIRED 記者 10 月的一天實測](https://www.wired.com/story/i-tested-every-major-ai-agent-for-a-day-heres-the-best-one/)：

| 測試 | Grok Bot 分數 | 說明 |
|---|---|---|
| 晨間選題 | 1 | 舊聞 |
| 訂午餐 | 4 | 購物車合理 |
| 發現行程衝突 | 2 | 沒發現；事後說之後會把自寄的提醒信也一起比對 |
| 旅遊行程 | 4 | 好讀，建議實用 |
| 失眠時的開放請求 | 5 | 提議早上再提醒他關心媽媽，讓他先放下 |

一位記者、一天的樣本，而且只測了單一 bot，沒有測多 bot 分工。

## 該開新 bot，還是交給既有的 bot

讀到這裡，判斷的原則其實很簡單：**開新 bot 是為了分開角色和脈絡，不是為了分開權限。**

**適合開新 bot：**
- 這是一份長期的職責，不是一次性的任務：例如每月對帳、追蹤某個客戶。
- 它需要自己的歷史，而且跟其他工作的歷史混在一起會干擾：法務糾紛和行銷活動不要放同一個 bot。
- 它有自己的節奏：每天早上、每週五、某個事件發生時。
- 你想用不同的界線管它：例如這個 bot 可以自己整理資料，但對外一律先問。

**交給既有 bot 就好：**
- 一次性的任務，做完就結束。
- 跟某個 bot 現有的工作脈絡重疊：同一個客戶、同一個專案。
- 你只是想試試看。既有的 bot 也可能主動建議開新 bot；想讓名單精簡，就請它開之前先問你。

**開新 bot 也不會隔開的東西**（要隔開，得用別的方法）：

| 你想隔開的 | 開新 bot 有沒有用 | 要怎麼做 |
|---|---|---|
| 某個網站的登入 | 沒用，瀏覽器共用 | 用完在共用電腦上登出那個網站 |
| 某個信箱或 app | 沒用，連接器全帳號共用 | 不要連；已經連了就斷開並到來源服務撤銷授權 |
| 敏感檔案 | 沒用，檔案共用 | 做完從 `/workspace` 刪掉 |
| 付款 | 沒用，Vault 共用 | 不存卡，每次在 Secure Form 輸入 |
| 完全分開的身分 | 沒用 | 另開一個帳號 |

最後一步：每個 bot 建好時，第一則訊息就寫清楚它的工作、資料來源和界線，請它記住。再加幾條窄的 Ask first 規則，管對外寄信、發布、刪除、付款。記憶只是它記得的事，界線要靠核准和規則撐。

## 適合誰、不適合誰

**適合：**
- 手上有好幾份長期職責、想各交給一個 bot 管的人。
- 已經在用 Cursor 或 X Subscription 的人。
- 需要事件觸發的例行工作，例如 PR、Slack 頻道、Webhook。

**不適合：**
- 想靠分開的 bot 隔開敏感帳號的人。
- 需要用量可預期的人：用量池共用，而且 11 月才被縮過。
- 想指定模型的人。

在台灣，官方文件沒有列地區限制，X Subscription 的 Premium 以上就能用。

這一篇是路線一的最後一篇，談的都是一個人怎麼用自己的 agent。下一篇的 Devin Bots 開始路線二：bot 不再是替你個人做事，而是被交給團隊、負責一整塊工作。
