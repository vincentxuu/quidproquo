## 這家公司做什麼

Runable 是一個「一條龍」AI Agent 平台——使用者用自然語言下指令，Agent 就會做出網站、App、簡報，接著自己接手日常營運，最後還會主動下廣告、發社群內容、做 SEO/AEO 來幫你的生意找客人。

公司一開始並不是做這個。創辦人 Umesh Kumar 與 Saksham Sarda 在 2025 年最初把 Runable 定位成 AI 基礎設施新創,做的是瀏覽器技術用來大規模抓資料。後來發現使用者一直拿這套瀏覽器 Agent 去做簡報、做網站,團隊乾脆順著使用者的行為轉向,把產品重做成通用型 AI Agent。今天的 Runable 能做網站、App、簡報、市場分析、名單開發、行銷影片,連資料庫、登入、金流、部署都包在裡面;上線後 Agent 會接手日常營運——跑 ChatGPT Ads、Meta、Google、LinkedIn、TikTok 上的付費廣告、排社群貼文、打陌生開發電話、追蹤競品與品牌口碑,還處理客服。

目前 Runable 有 1.5M 使用者,多數是 2 人小團隊的小型企業主(顧問、代理商、清潔公司之類),分布在美、英、日、巴西。2.0 版上線後 3 週內從零衝到 $2M ARR,15 人團隊撐起這個成長速度是這輪募資的核心賣點。

## 這筆融資的訊號

### 對 Agent 生態的意義

過去一年 AI Agent 新創大多卡在「建置」(Lovable、Replit、Cursor 這類幫你把東西做出來)或「成長」(11x、Artisan 這類幫你做業務開發)其中一段,兩段之間需要人工銜接。Runable 的賭注是把這兩段焊在同一個 Agent、同一份 context 和記憶裡——東西做出來之後,同一個 Agent 直接接手去賣。如果這個「建置到成長不斷點」的模式真的比拼裝多個單點工具更有效率,會逼現有的 Builder 類 Agent(B3 賽道)和 GTM 類 Agent(D2 賽道)重新思考自己的邊界要不要往對方延伸。

### 投資人在賭什麼

Nexus Venture Partners 合夥人 Jishnu Bhattacharjee 講得很直白:「多數 AI 工具停在『產出』這一步,但企業要的是『結果』:客戶、營收、進帳的現金。」這句話點出這輪投資的邏輯——市場上做「產出型」Agent(生內容、生程式碼)的競爭已經很擁擠,但能把 Agent 一路延伸到「營收結果」的很少。Susquehanna 與 Nexus 共同領投、Together Fund 與 Array VC 這兩家 Seed 輪投資人續投,顯示既有股東對創辦人從「瀏覽器抓資料」轉向「通用 Agent」這次 pivot 的執行力有信心。

### 值得觀察的數字

- 3 週從零做到 $2M ARR,換算年化營收約 $34.7M/人(以 15 人團隊計)——即使打七折算保守,人均產出仍遠高於同階段 SaaS 新創的常見區間;
- $21M 換來 $65M 投後估值,約 3.1x 的估值/募資倍數,對比同賽道 8 月其他 Series A(如 Naïve 的 $28.5M)偏保守,顯示這輪定價相對務實而非追熱錢;
- 1.5M 使用者、15 人團隊——使用者數與團隊規模的落差,是「Agent 自己接手營運」這個賣點最直接的數字證明,但目前僅有公司自報數字,尚待第三方數據交叉驗證。

## Watchlist 狀態

Runable 尚未在 watchlist 中。建議加入 section B3(Agent 平台 / Builder),追蹤重點:通用型 AI Agent、涵蓋建置到成長全流程、Series A $21M(Susquehanna + Nexus 領投)。因其成長端功能(廣告投放、陌生開發)與 D2(Sales / GTM)重疊,亦可交叉列入觀察。

## 今日收穫

過去看「AI Agent 新創」習慣先問「它是做哪一段的」——是建置工具、是客服 Agent、還是業務開發工具,彷彿這些天生就該是分開的產品。Runable 的 pivot 故事提醒我:這個分段本來就不是使用者的需求,而是現有工具鏈接不起來留下的縫。當一個 Agent 能共享同一份 context 和記憶橫跨「做出來」與「賣出去」兩端,分段本身可能只是暫時的技術限制,而不是產品該長的樣子。
