## 今日主題

Growth & Experimentation 題型考的不是「你有沒有想法」，是你會不會先把「成長」拆成正確的結構——尤其是雙邊市場（Marketplace）題目，很多候選人一開口就衝去講獲客管道，卻沒發現如果只衝 Guest 端的量，Host 端的供給跟不上，成長根本撐不住，甚至會反過來拖垮體驗跟評價。

這類題目常出現在 Airbnb、Uber、DoorDash 這種雙邊平台的面試裡，面試官想看的是你能不能同時處理「怎麼讓存量使用者更常回來」跟「怎麼讓成長不是一次性的活動，而是會自己滾動」這兩件事。今天用兩個框架練這個能力：一個看整體成長結構，一個看單一使用者怎麼養成回訪習慣。

## 核心框架速記

### Growth Flywheel：把單向 Funnel 換成會自轉的輪子

HubSpot 在自家部落格公開說明，他們捨棄傳統行銷 Funnel 的原因，是 Funnel 「產出了客戶，卻把贏得這些客戶所花的力氣直接丟掉」——每一輪都要從零開始，完全忽略既有客戶身上藏著的成長潛力。Flywheel 反過來把「顧客的滿意度」當成驅動下一輪成長的動能：

| 階段 | 做的事 | Airbnb 情境下的例子 |
|------|--------|------|
| **Attract** | 用內容、口碑或既有價值吸引對的人進來 | 房源被 SEO 收錄、朋友分享行程連結 |
| **Engage** | 提供解決方案，降低摩擦，讓對方順利完成第一次體驗 | 簡化搜尋與比價、即時通訊、彈性取消政策 |
| **Delight** | 超出預期的體驗，讓對方變成會主動推薦的人 | Host 提供的驚喜服務、Guest 留下五星評論並回訪 |

Flywheel 跟 Growth Loop（本系列 8/28 練過）邏輯相通，都是把「產出」重新餵回「輸入」；差別在於 Flywheel 更常用來檢視整個成長引擎有沒有卡點——如果某一段（例如 Engage 到 Delight）摩擦力特別大，整個輪子會被拖慢，這時候加碼 Attract（砸更多廣告）只會讓輪子轉得更費力，不會轉得更快。

### Hook Model：讓單一使用者自己想回來的四步迴圈

Nir Eyal 在《Hooked》中提出的 Hook Model，拆解的是「一個習慣怎麼被設計出來」，四個步驟依序是：

1. **Trigger（觸發）**：外部觸發（推播、通知、廣告）或內部觸發（無聊、焦慮、某種情緒）促使使用者打開產品。
2. **Action（行動）**：使用者做的最小動作，動作愈簡單愈好，重點是「使用者有沒有動機跟能力做這件事」。
3. **Variable Reward（不確定的獎勵）**：獎勵的時機或內容愈不可預測，愈容易讓人想一直重複；獎勵可能來自「獵物」（有用資訊或優惠）、「自我」（技能精進的成就感）或「部落」（他人的社會認同）。
4. **Investment（投入）**：使用者在拿到獎勵後，被引導去做一點「投資」——填資料、建立收藏、邀請朋友——這個投入會讓下一輪的 Trigger 更有效、Action 更容易、Reward 更誘人，同時也讓使用者更難離開。

Flywheel 回答的是「整個成長系統怎麼轉」，Hook Model 回答的是「單一使用者為什麼會自己回來」——面試時把兩者疊在一起用，通常比只講其中一個更有說服力。

## 今日練習題

### 題目

How would you 3x Airbnb's growth?

（來源：Exponent《52 Real Product Manager Interview Questions (2026 Guide)》收錄的真實 Airbnb 面試題）

### 拆解思路

1. **釐清問題**：先問清楚「3x」是指什麼指標（訂房量？營收？活躍使用者？）、多長的時間窗，以及現在的基準線是多少——這決定後面該衝哪一端。
2. **定義使用者**：Airbnb 是雙邊市場，Guest 跟 Host 缺一不可。只講「怎麼多找一些人來訂房」是不完整的答案，要同時談「怎麼讓供給跟上」。
3. **結構化分析**：用 Growth Flywheel 分別檢視 Guest 端跟 Host 端的 Attract-Engage-Delight，找出哪一段摩擦力最大；再用 Hook Model 設計一個能提高「Guest 想到旅行就先開 Airbnb」的習慣迴圈。
4. **提出方案**：挑一個槓桿最大、成本最低的切入點，而不是同時對兩邊下重本——例如先解決 Host 端「Delight 到 Attract」的斷點（滿意的 Host 沒有被鼓勵去推薦新 Host 加入），因為供給端瓶頸解除後，Guest 端的成長才有地方落地。
5. **定義成功**：不能只看訂房量成長，要同時看供給健康度指標（例如活躍房源數、Host 流失率）跟需求端的習慣養成指標（例如 Guest 的 App 開啟頻率、Wishlist 收藏轉訂房率），避免衝出「訂房量漲了，但體驗跟評價一起崩掉」的假成長。

### 範例回答（面試時可以這樣講）

> **先框問題**：在動手設計方案前，我會先確認「3x」指的是哪個指標、多久的時間窗，因為 Airbnb 是雙邊市場，Guest 端跟 Host 端要用不同的成長邏輯處理——如果只衝 Guest 需求，Host 供給跟不上，訂房量看起來漲了，但可訂房源少、價格被推高，體驗跟評分反而會往下掉，這種成長撐不住。
>
> **用框架拆解**：我會用 Growth Flywheel 分別畫出 Guest 跟 Host 兩條 Attract-Engage-Delight，找卡點。我猜供給端最大的斷點，是滿意的 Host（已經走到 Delight 階段）沒有被有效引導去推薦新 Host 加入——這代表 Flywheel 在這裡斷掉了，變成一次性的滿意，沒有變成下一輪的 Attract。針對需求端，我會用 Hook Model 設計一個習慣迴圈：把「查看已收藏的 Wishlist 房源價格變動」設計成一個不確定的獎勵（Variable Reward）——使用者不知道什麼時候會降價，這會讓他們更常打開 App，而不是等到真的要訂房才想起 Airbnb。
>
> **講清楚取捨**：我會優先投入 Host 端的推薦機制，而不是把預算全部砸在 Guest 端的獲客廣告，因為供給是這個成長引擎現在最緊的瓶頸——沒有解決這個，Guest 端的成長就沒有地方落地。成功的定義不是單看訂房量，而是「活躍房源數」有沒有跟著訂房量一起成長，加上「Wishlist 收藏轉訂房率」有沒有提升，這才代表我們養出了真正會回頭的使用者，而不是靠廣告硬推出來的一次性訂單。

## 今日案例

**Tinder：用 Hook Model 把「找對象」變成日常打開的習慣**

Tinder 的核心任務是幫使用者找到約會對象，但 GoPractice 對 Tinder 的 Hook Model 拆解指出，讓使用者每天回來的，其實不是「找到對象」這件事本身——多數使用時段裡，使用者根本沒有真的成功配對——而是產品把整個過程拆成了一個會自我強化的習慣迴圈：**Trigger** 是 App 圖示、配對通知、他人傳來的訊息（外部），或無聊、孤單感（內部）；**Action** 是滑動瀏覽並左右滑其他使用者的檔案；**Reward** 是不確定的「有人喜歡我」（配對與 Superlike）跟「有人傳訊息給我」，這兩種回饋既屬於「獵物型」獎勵（潛在對象），也屬於「部落型」獎勵（社會認同）；**Investment** 則是使用者花時間經營一個有吸引力的個人檔案——這個投入不只讓下一輪配對品質變好，也讓使用者更捨不得刪除帳號，因為刪除就等於丟掉所有配對紀錄。

GoPractice 特別指出一個反直覺的重點：Tinder（跟 Robinhood 這類產品）的「習慣」跟產品原本要完成的「任務」是分開的——找到約會對象或監控股價本身不會自動變成習慣，習慣是額外設計出來、疊加在任務之上的機制。

**面試連結**：這個案例可以直接用在「舉一個成功用 Hook Model 提升回訪率的產品例子」或「你會怎麼設計一個讓使用者每天回來的功能」這類題目，重點是強調「習慣迴圈不等於產品的核心任務」——今天練習題裡「Wishlist 價格變動」的設計邏輯，就是刻意在 Airbnb 的核心任務（訂房）之外，額外疊加一個 Variable Reward，讓使用者在還沒有訂房需求時也會想打開 App。
