## 什麼是這個系列？

本系列「教學文章怎麼寫」旨在記錄寫好教學、學習相關文章的完整過程，從規則、結構、查證到最終定稿的每一步。系列共 30 篇（order 0–29），設計為完整閱讀時按順序進行，每篇開頭會同步顯示「現在在哪一段」的小地圖。

## 閱讀順序

### order 0–6：一次完整流程
從規則、網站運作、獵人的工作台到寫報告，帶您走完一次真實的資安獵人流程。

### order 7–11：為什麼最貴的洞在底層
記憶體 → 溢位 → 虛擬機 → 真實逃脫案例 → TEE。

### order 12–13：TEE 篇與獎金地圖
TEE 篇的 WhatsApp 例子（在保護 AI），接著講 AI 產品的漏洞計畫收什麼；讀者已經懂 Web、記憶體、虛擬機、TEE 與 AI 產品，看一張頂級獎金地圖。

### order 14：結尾
依目標排接下來怎麼練、要不要考證照、值不值得投入；對應全系列每一篇。

## 閱讀原則

- **可見先於不可見**：先講瀏覽器看得到的請求，再謙伺服器，再講記憶體與硬體隔離。
- **能動手先於深原理**：讀到 order 6 已經做過一輪完整流程，後面才回答「為什麼底層更貴」。
- **難度落差靠銜接段處理，不靠分段標籤**：最大的落差在 6→7（Web 到 C），order 7 開頭給動機與 15 分鐘 C 讀法。
- **獎金表只當「難度與影響的參考」**：每篇最多一節、放在後段、佔全文 15% 以內。
- **一個比喻貫穿全系列：大樓**。系統是大樓、scope 是公告上開放檢查的樓層、請求是送到櫃檯的單子、XSS 是騙到別的住戶照你的紙條做事、IDOR 是櫃檯不核對就把別戶的包裹交出來、RCE 是拿到管理室鑰匙、記憶體溢位是寫字寫出格子蓋到隔壁欄、hypervisor 是隔開各戶的牆與管理室、TEE 是連管理員都看不到的保險室。每篇只延伸用到的部分，比喻失效的地方直接講。

## 結構地圖（每篇開頭會顯示）

每篇文章開頭都會同步顯示目前所在的 segment，讀者可以快速定位：

```
選計畫 → 讀規則 → 認識目標 → 偵察與攔截 → 找洞 → 確認影響 → 寫報告 → 分流 → 修補／獎金／重複
```

## 如何使用

- **完整閱讀**：從 order 0 開始，按順序讀完 order 29，即可學會完整的寫作與審查管線。
- **主題抓取**：只想看某個主題（如 XSS、RCE、TEE），直接讀對應 order（4、5、7–13）。
- **作為指南**：想復習某個環節（如查證規則），直接翻到對應 order 並讀該篇的「影片嵌入」與「查證過程不寫進門面」一節。
