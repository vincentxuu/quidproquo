## 本文定位

這篇是沙箱系列的「安全篇」（order 24）。它不講沙箱技術細節（在 order 2–18），也不講可觀測性（在 order 23），而是聚焦 **受管行業（金融、醫療）用沙箱的合規要求與審計流程**：

1. **哪些合規框架適用？** —— SOC 2、HIPAA、GDPR、ISO 27001、EU AI Act
2. **沙箱要符合什麼控制項？** —— 存取控制、審計日誌、資料加密、身份管理
3. **審計怎麼做？** —— 內部稽核、外部稽核、證據蒐集
4. **資料主權與跨境限制** —— 資料必須留在特定地區
5. **合規檢查清單** —— 可直接使用的檢查表

## 合規框架概覽

### SOC 2 (Service Organization Control 2)

SOC 2 是美國會計師公會 (AICPA) 的信任服務標準，包含五個信任服務準則：

| 準則 | 相關控制項 | 沙箱如何滿足 |
|------|-----------|-------------|
| 安全 (Security) | 邏輯存取控制、網路防護 | 沙箱隔離、網路 allowlist、非特權執行 |
| 可用性 (Availability) | 系統監視、容量規劃 | 沙箱生命週期管理、自動擴縮容 |
| 處理完整性 (Processing Integrity) | 資料處理準確性 | 工具呼叫記錄、輸出驗證 |
| 機密性 (Confidentiality) | 資料存取控制 | 檔案系統隔離、憑證代理 |
| 隱私性 (Privacy) | 個資蒐集與使用 | 資料分類、同意管理 |

### HIPAA (Health Insurance Portability and Accountability Act)

HIPAA 是美國醫療資料隱私法，適用於處理受保護醫療資訊 (PHI) 的實體。

| 要求 | 沙箱如何滿足 |
|------|-------------|
| 審計控制 | 記錄所有 PHI 存取與操作 |
| 唯一使用者識別 | 每個使用者有唯一 ID，委譲鏈身份 |
| 存取控制 | 最小權限原則，基於角色的存取控制 (RBAC) |
| 傳輸安全 | 資料傳輸加密 (TLS 1.2+) |
| 協商夥伴協議 (BAA) | 與沙箱供應商簽署 BAA |

### GDPR (General Data Protection Regulation)

GDPR 是歐盟資料隱私規範，適用於處理歐盟居民個資的所有組織。

| 要求 | 沙箱如何滿足 |
|------|-------------|
| 資料處理記錄 (Article 30) | 記錄個資蒐集、處理、傳輸 |
| 資料主體權利 | 支援資料存取、刪除、移植請求 |
| 資料保護影響評估 (DPIA) | 沙箱部署前進行風險評估 |
| 跨境傳輸限制 | 個資不得未授權傳輸至非充足保護地區 |
| 資料最小化 | 只處理必要個資，沙箱內不存無關資料 |

### ISO 27001

ISO 27001 是國際資訊安全管理系統標準。

| 附錄 A 控制項 | 沙箱如何滿足 |
|-------------|-------------|
| A.5 (組織控制) | 資訊安全政策、角色與責任 |
| A.6 (人員控制) | 遠端作業、機密保護協議 |
| A.8 (資產控制) | 資料分類、媒體處理 |
| A.9 (存取控制) | 使用者存取管理、特權存取管理 |
| A.12 (作業控制) | 作業流程、變更管理、日誌監控 |
| A.13 (通訊安全) | 網路安全、資料傳輸安全 |

### EU AI Act

歐盟 AI 法案 (2026 年生效) 對「高風險 AI 系統」有特別要求：

| 要求 | 沙箱如何滿足 |
|------|-------------|
| 風險管理系統 | 沙箱部署前風險評估、持續監控 |
| 資料治理 | 訓練資料與執行資料的品質控制 |
| 記錄保存 | 代理程式執行記錄保留適當期間 |
| 透明度 | 使用者知道正在與 AI 互動 |
| 人工監督 | 高風險決策需要人工核准 |

## 沙箱合規控制項清單

以下是受管行業部署沙箱時的合規控制項清單：

### 存取控制 (Access Control)

- [ ] 每個使用者有唯一識別碼
- [ ] 基於角色的存取控制 (RBAC)
- [ ] 特權存取需要多因素驗證 (MFA)
- [ ] 沙箱內程式碼以非特權使用者執行
- [ ] 定期審查存取權限

### 審計日誌 (Audit Logs)

- [ ] 記錄所有工具呼叫、檔案操作、網路請求
- [ ] 日誌不可篡改 (HMAC 簽章或 WORM 儲存)
- [ ] 日誌保留符合法規要求 (通常 1–7 年)
- [ ] 日誌可輸出至 SIEM (Splunk、Datadog、Sentinel)
- [ ] 權限決策記錄 (允許/拒絕 + 原因)

### 資料保護 (Data Protection)

- [ ] 靜態資料加密 (AES-256)
- [ ] 傳輸資料加密 (TLS 1.2+)
- [ ] 金鑰管理 (Key Management Service)
- [ ] 資料分類與標記
- [ ] 資料保留與銷毀政策

### 身份管理 (Identity Management)

- [ ] 委譲鏈身份記錄 (user → agent → tool)
- [ ] 單一登入 (SSO) 與多因素驗證
- [ ] 服務帳戶與個人帳戶分離
- [ ] 離職人員存取即時撤銷

### 網路安全 (Network Security)

- [ ] 沙箱預設無出網 (no-egress)
- [ ] 網路允許清單 (allowlist)
- [ ] 內網隔離，防止橫向移動
- [ ] DNS 重繫向防護

## 資料主權與跨境限制

受管行業（尤其是金融與醫療）通常有嚴格的資料主權要求：

### 資料主權原則

| 原則 | 說明 |
|------|------|
| 資料留在地內 | 個資必須儲存於特定國家或地區 |
| 處理留在地內 | 資料處理必須在特定司法管轄區進行 |
| 跨境傳輸限制 | 跨境傳輸需要充分保護或主體同意 |

### 沙箱部署選擇

| 選項 | 合規適合度 | 說明 |
|------|-----------|------|
| 公有雲端 (同區域) | 中等 | 資料留在同一雲端區域，但供應商可能跨國 |
| 私有雲端 | 高 | 資料完全在自有基礎設施 |
| 混合雲端 | 中高 | 敏感資料在私有雲端，非敏感在公有雲端 |
| BYOC (Bring Your Own Cloud) | 高 | 在自有雲端部署沙箱控制平面 |

### 跨境傳輸的防護措施

1. **資料不出境**：敏感資料不跨國傳輸，沙箱在當地部署
2. **標準合約條款 (SCCs)**：與跨國供應商簽署 SCCs
3. **約束性公司規則 (BCRs)**：跨國公司內部資料傳輸規則
4. **資料匿名化**：傳輸前將個資匿名化或假名化

## 審計流程

### 內部稽核

1. **範圍界定**：確定哪些沙箱實例、哪些資料類別在稽核範圍內
2. **控制項測試**：抽樣測試存取控制、審計日誌、資料加密等控制項
3. **缺口分析**：找出不符合合規要求的項目
4. **補救行動**：修復缺口，重新測試
5. **稽核報告**：撰寫內部稽核報告，提交管理階層

### 外部稽核

1. **選擇稽核師**：選擇有受管行業經驗的外部稽核公司
2. **證據蒐集**：提供沙箱設定、日誌記錄、政策文件、訓練記錄
3. **現場訪談**：訪談沙箱管理員、開發人員、安全團隊
4. **稽核發現**：稽核師提出不符合項與建議改善
5. **認證/證明**：取得合規認證或審計證明

### 證據類型

| 證據類型 | 說明 |
|----------|------|
| 政策文件 | 資訊安全政策、存取控制政策、資料保留政策 |
| 設定截圖 | 沙箱設定、網路策略、存取控制設定 |
| 日誌範例 | 審計日誌範例、SIEM 輸出 |
| 訓練記錄 | 員工安全訓練、合規訓練記錄 |
| 合約文件 | 與沙箱供應商的合約、BAA、SCCs |
